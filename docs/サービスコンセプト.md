# utter - サービスコンセプト

詳細な要件は [要件定義.md](要件定義.md) を正とする。このドキュメントは「何を作るか・何を作らないか」を短くまとめたもの。

## サービス概要

utter は、話した言葉を自然な文章に整えて、いま使っているアプリの入力欄へそのまま挿入する macOS ネイティブの音声入力アプリ（OSS）。
低遅延、自然な文章整形、開発用語の認識、省電力の両立を目指す。共通基盤を使い、本人の iPhone で使う iOS 版（カスタムキーボード）も開発する。

Typeless・Aqua Voice・Nani.now を参考にするが、独自実装とし、競合製品の非公開技術を前提としない。

## コンセプト

### 1. どのアプリでも、話すだけで入力できる
- グローバルショートカットで録音開始・停止、Esc でキャンセル（Toggle / Push-to-talk）
- HUD で録音・認識・整形・挿入の状態を表示し、フォーカスを奪わない
- Accessibility API による直接挿入を優先し、失敗時は Pasteboard、最後はコピー可能なプレビューへ退避

### 2. 話し言葉を、そのまま使える文章に
- Raw / Natural / Structured の3モード
- フィラー・言い直しの除去、句読点・段落の付与。数字・URL・コード・固有名詞は保護し、意味を創作しない
- 前面アプリに応じて文体を自動選択（チャットは簡潔、メールは丁寧、IDE は技術語保持、Terminal はコマンド保護）
- ユーザー辞書と用語置換

### 3. ローカル優先とプライバシー
- 音声認識はローカル（SpeechAnalyzer / WhisperKit）を優先。クラウド STT は明示的オプトイン
- AI 整形は Claude API・Sign in with ChatGPT・Local Basic から選択。各利用者が自分の認証情報を設定する
- テレメトリなし。本文・音声をログに残さない。パスワード欄や機密アプリでは録音・送信を抑止
- クラウド整形が失敗しても、ローカル整形の結果を挿入して発話を失わない

### 4. Mac 全体を重くしない
- 待機中はマイク・STT・タイマー・ネットワークを止める
- モデルは XPC Worker で隔離し、省電力 / バランス / 高速モードで保持時間を切り替える
- 待機時メモリ 50MB、8時間待機の追加バッテリー消費 1% 未満を目標とする

### 5. iPhone でも同じ辞書・整形で
- 録音・STT・整形は iOS 本体アプリで行い、結果を App Group 経由でカスタムキーボードから挿入する
- 挿入前プレビュー＋明示的な挿入操作を初期仕様とし、二重挿入・誤挿入を防ぐ
- App Store では公開せず、本人端末への Xcode 実機インストールで運用する

## 作らないもの（MVP 外）

- ローカル LLM の常駐
- Mac App Store 配布、iOS の App Store / TestFlight 配布
- Edit Mode、クラウド STT、入力履歴、Realtime Direct（macOS は Phase 4 以降）
- 開発者の共通 API キーの配布
- 非公開 API や他製品のクライアントIDを使った連携

## 技術スタック

- 言語・UI: Swift 6 / SwiftUI / AppKit（macOS）/ UIKit（iOS キーボード）
- 録音: AVFoundation / AVAudioEngine / AVAudioSession
- STT: SpeechAnalyzer / SpeechTranscriber、WhisperKit / Core ML
- AI 整形: Anthropic Messages API、Sign in with ChatGPT（Responses API）、Local Basic
- 永続化: UserDefaults、SQLite / GRDB.swift、Keychain
- 配布: GitHub Releases（Developer ID 署名・公証）、Sparkle 2（後続フェーズ）
