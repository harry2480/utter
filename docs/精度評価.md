# utter 精度評価の手順

[要件定義.md](要件定義.md) 9章・AC-04 の精度評価を、再現できる手順で行うための規則。
計算は `Packages/UtterEvaluation`（`utter-eval`）で行う。規則を変えるときは、この文書とコードとテストを同時に更新する。

> 本書の正規化規則と意味改変の判定基準は、初版の提案である（製品判断として確定が必要）。

---

## 評価セット

- 区分は 日本語・日英混在・開発用語・数字・自己訂正・騒音 の6つ（JSON では `japanese` / `mixedJapaneseEnglish` / `developerTerms` / `numbers` / `selfCorrection` / `noisy`）
- 各区分 50 発話以上（合計 300 以上、暫定）。結果には区分ごとの件数を必ず併記する
- 評価用音声はリポジトリに含めない（`eval/audio/` は gitignore 済み）。リポジトリで管理するのは正解テキストと結果の JSON、本書の規則だけ
- 実在の個人情報や、他人の実際の発話を正解テキストに含めない

### 結果の JSON

`EvaluationSample` の配列。記入例は [eval/results.example.json](../eval/results.example.json)。

| キー | 必須 | 内容 |
|---|---|---|
| `id` | ○ | 評価セット内で一意な識別子 |
| `category` | ○ | 上記6区分のいずれか |
| `reference` | ○ | 発話どおりの正解。フィラー・言い直しも書き起こす |
| `terms` | | 用語単位で正答率を測る語。`reference` に表記どおり含める |
| `sttOutput` | | STT 単体の結果（未実施なら省略） |
| `refinedOutput` | | AI 整形後の結果（未実施なら省略） |
| `meaningChanges` | | 整形後の結果に対する重大な意味改変の判定。改変なしは `[]`、未判定は省略 |

### 実行

```sh
swift run --package-path Packages/UtterEvaluation utter-eval eval/results.json
```

区分ごとの件数・CER・用語正答率・重大な意味改変率を Markdown の表で出力する（発話本文は出力しない）。
結果はリリースごとに `docs/計測/` へ記録する（AC-19）。

## CER の正規化規則

正解と STT 結果の両方に、次の順で同じ規則を適用してから文字（書記素）単位の編集距離を数える。
CER = 編集距離の合計 ÷ 正規化後の正解の文字数の合計（発話ごとの CER の平均にはしない）。挿入が多いと 100% を超える。

1. **全角・半角**: Unicode NFKC で正規化する。全角英数字・記号は半角に、半角カナは全角になる
2. **英字の大文字・小文字**: 小文字にそろえる
3. **数字表記**: 漢数字をアラビア数字にそろえる
   - 位取りの文字（十・百・千・万・億・兆）を含む並びは値として読む（三百二十 → 320、二万五千 → 25000）
   - 位取りのない並びは1文字ずつ置き換える（二〇二六 → 2026）
   - 万・億・兆だけの並び（万全の万など）と、桁あふれする並びは変えない
   - 「一般」→「1般」のような語の内部の置き換えも起きるが、正解と結果の両方に同じ規則を適用するため CER には影響しない
   - 桁区切りのカンマは手順4で除かれるため「1,200」と「1200」と「千二百」は一致する
4. **句読点・空白**: Unicode の約物（P で始まる一般カテゴリ: 句読点、括弧、引用符、ハイフン、中黒など）と空白・改行を除く
   - 長音記号「ー」と、`+` `=` などの記号（S カテゴリ）は残す

### 用語単位の正答率（日英混在・開発用語・辞書語）

- `terms` の各語が、正解に現れる回数だけ結果にも現れたかを数える。正答は正解の回数を上限とする
- 用語は表記を正しく保てたかを見るため、CER の正規化を適用しない。大文字・小文字、全角・半角、空白の有無も区別する（「SwiftUI」と「swiftui」「Swift UI」は不一致）
- 正答率 = 正答数の合計 ÷ 正解に含まれる用語の出現回数の合計

## 重大な意味改変

STT 単体の誤りとは分けて、AI 整形後の結果（`refinedOutput`）について判定する（9章）。
比較の基準は `reference`（発話どおりの正解）であり、STT の結果ではない。
重大な意味改変率 = 重大な意味改変が1つ以上あった発話数 ÷ 判定した発話数。

### 判定基準

次のいずれかに当たる場合を「重大な意味改変」とする。JSON の `meaningChanges` に該当する種類をすべて記録する。

| 種類（JSON） | 基準 | 例 |
|---|---|---|
| 否定の反転（`negationFlipped`） | 肯定と否定、可能と不可能、許可と禁止が入れ替わった | 「送らないで」→「送って」 |
| 数値の変更（`numberChanged`） | 数値・日時・金額・数量・単位が変わった | 「3時」→「13時」、「5個」→「50個」 |
| 固有名詞の変更（`properNounChanged`） | 人名・製品名・地名・コード上の識別子が別の語に変わった | 「Swift」→「Swiftly」 |
| 内容の追加（`contentAdded`） | 発話にない内容（質問への回答、補足、命令の実行結果など）が加わった（TXT-04, AC-17） | 「天気は？」→「晴れです」 |
| 内容の欠落（`contentOmitted`） | 発話の内容が抜けた | 「AとBを確認」→「Aを確認」 |
| 関係の変更（`relationChanged`） | 主語・目的語、依頼と報告、時制などの関係が入れ替わった | 「確認してください」→「確認しました」 |

次は重大な意味改変に含めない。

- フィラー（えー、あのー）の除去
- 自己訂正で言い直す前の語の除去（「3時、いや4時」→「4時」）。ただし言い直した後の語を残さなかった場合は欠落
- 句読点・改行・段落・表記ゆれ（漢字とかな、全角と半角）の変更
- 文体の変更（です・ます調へのそろえなど）で、上の基準に当たらないもの

### 判定手順

1. 判定者は `reference` と `refinedOutput` だけを並べて読む（STT の結果や音声は見ない）
2. 上の判定基準の表を上から順に確認し、当てはまる種類をすべて記録する。当てはまらなければ `[]` を記録する
3. 迷った場合は「重大」とし、その理由を評価記録（`docs/計測/`）に1行残す
4. 同じ評価セットを2人以上で判定できる場合は、判定が分かれた発話を協議して1つに決め、件数を記録する
5. 判定基準を変えた場合は、過去の結果と比較せず、評価セット全体を判定し直す
