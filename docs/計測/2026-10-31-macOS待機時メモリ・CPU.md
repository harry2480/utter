# macOS アプリの待機時のメモリ・CPU（2026-10-31）

Phase 0 検証 [#52](https://github.com/harry2480/utter/issues/52) の「待機時メモリ・CPU」の記録。要件定義 6章の目標は、待機時アプリメモリ ≤ 50MB、待機時 CPU 平均 ≤ 0.1%（ちょうどの値は目標の内とする。要件定義 6章・`Verification/PerfProbe/README.md` と同じ）。

## 条件

- 実行日：2026-10-31
- 機種：Mac17,2・Apple M5・メモリ 24GB、macOS 27.0.1（26A434）、AC 電源
- アプリ：`Apps/macOS` の Release 構成。**署名なしでビルドし、アドホック署名した**（`CODE_SIGNING_ALLOWED=NO` → `codesign --force --deep -s -`）。この Mac が開発チームの端末として登録されておらず、開発用署名のプロファイルを作れなかったため。App Group などのエンタイトルメントは付いていない。待機中は権限を使わないため、待機時の値には影響しないと見ている（推測）
- 起動後 5 分置いてから、`sample-process.sh` で 60 秒ごとに 30 分記録した。録音・認識は一度もしていない
- ほかのアプリ（ブラウザ・エディタなど）は普段どおり開いたまま

| 計測 | 音声認識の設定 | 画面 |
|---|---|---|
| A | 未選択（ビルド時に `UTTER_MAC_STT_ENGINE=` を指定したのと同じ。計測時の `Config/Local.xcconfig`（2026-10-29 更新）はこの値を設定しておらず、`Base.xcconfig` の空の既定が効いていた。STT Worker を使わない） | このビルドでの初回起動。初回セットアップの画面が開いていたかは確かめていない |
| B | SpeechAnalyzer（ビルド時に `UTTER_MAC_STT_ENGINE=speechAnalyzer` を指定）。日本語（ja_JP）のモデルはこの Mac に最初から入っている（[2026-10-29 の記録](2026-10-29-SpeechAnalyzer-macOS-mic.md)）。utter の設定画面で「モデルを取得」を済ませていたか（ロケールの予約）は確かめていない | 計測後に確かめたところ、ウィンドウは開いていなかった（メニューバーのみ） |

再現のコマンド（リポジトリのルートで実行）：

```sh
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
xcodegen generate --spec Apps/macOS/project.yml --quiet
# Local.xcconfig の設定に左右されないよう、STT の設定をビルドのたびに明示する
# A（STT 未選択）
xcodebuild -project Apps/macOS/Utter.xcodeproj -scheme UtterMac -configuration Release \
  -derivedDataPath "$TMPDIR/mac-dd-a" CODE_SIGNING_ALLOWED=NO UTTER_MAC_STT_ENGINE= build
# B（SpeechAnalyzer）
xcodebuild -project Apps/macOS/Utter.xcodeproj -scheme UtterMac -configuration Release \
  -derivedDataPath "$TMPDIR/mac-dd-b" CODE_SIGNING_ALLOWED=NO UTTER_MAC_STT_ENGINE=speechAnalyzer build

# 計測する方を選ぶ（A は mac-dd-a、B は mac-dd-b）。A と B は1つずつ順に測る
APP="$TMPDIR/mac-dd-a/Build/Products/Release/utter.app"
codesign --force --deep -s - "$APP"
open "$APP"
# utter のウィンドウ（初回セットアップ・設定）を閉じ、メニューバーだけにしてから 5 分置く
cd Verification/PerfProbe
scripts/sample-process.sh --name utter --interval 60 --duration 1800 --output out/idle-01.csv
```

開発用署名でビルドできる環境では、`scripts/build-local.sh` の成果物を使う（[docs/Phase0検証-性能目標.md](../Phase0検証-性能目標.md) の「macOS アプリでの計測」）。

## 結果

| 計測 | 時間 | メモリ（Physical footprint） | CPU 平均 | 6章の目標 |
|---|---|---|---|---|
| A（STT 未選択） | 1,764 秒 | 38.8〜39.0MB | 0.010% | ≤ 50MB・≤ 0.1% → **どちらも内** |
| B（SpeechAnalyzer） | 1,766 秒 | 19.2〜21.2MB | 0.028% | 同上 → **どちらも内** |

- 待機中に STT Worker（`UtterSTTWorker`）は起動していなかった。Worker は認識のときに起動する。そのため B の待機時の値は、モデルを取得済みか（ロケールを予約したか）に左右されないと見ている（推測。取得済みの状態での再計測はしていない）
- 30 分の間、メモリは増え続けなかった（A は 38.8〜39.0MB、B は 19.2〜21.2MB の範囲）
- A と B でメモリに約 18MB の差があるが、**この差は STT の設定の差としては比べられない。** A は画面の状態を確かめておらず、初回セットアップなどの画面が開いていた可能性がある（推測）。この記録で言えるのは、どちらの条件でも 6章の目標に収まった、ということまで

## 測れていないこと

- 画面の状態（ウィンドウを閉じてメニューバーだけ）をそろえた A・B の比較。上のコマンドで、両方ともウィンドウを閉じてから測り直す
- 開発用署名（`build-local.sh`）のビルドでの値
- 録音開始遅延・停止→挿入（Signpost。発話とショートカットの操作が要る）、録音中・認識中のメモリ、負荷復帰
- 8時間待機の追加バッテリー消費（AC 電源を外し、対照と並べて測る）
- Bluetooth マイク
