# macOS アプリの待機時のメモリ・CPU（画面をそろえた再計測、2026-11-01）

Phase 0 検証 [#52](https://github.com/harry2480/utter/issues/52) の「待機時メモリ・CPU」の再計測。[2026-10-31 の記録](2026-10-31-macOS待機時メモリ・CPU.md)は、A（STT 未選択）の画面の状態を確かめておらず、A と B の差を比べられなかった。今回は A・B とも、起動直後に開いたウィンドウを閉じてメニューバーだけにし、ウィンドウの数を記録してから測った。

要件定義 6章の目標は、待機時アプリメモリ ≤ 50MB、待機時 CPU 平均 ≤ 0.1%。

## 条件

- 実行日：2026-11-01（A は 21:40〜22:09、B は 22:15〜22:50）
- 機種：Mac17,2・Apple M5、macOS 27.2（26B123）
- 電源：**表に使った区間は A・B ともバッテリー駆動**（`pmset -g log` で 21:03〜22:39 は `Using Batt`、残り 31% → 23%）。低電力モードはオフ。2026-10-31 の記録は AC 電源で、電源の条件が違う。B の後半（22:40:12 以降）は AC 電源（下の「B の後半」）
- アプリ：`Apps/macOS` の Release 構成。2026-10-31 と同じく、署名なしでビルドしてアドホック署名した。ビルドは 21:10〜21:13 に、main の `2cd78ec` から作った作業用の worktree で行った（worktree を作ったときの `git worktree list` の表示による。worktree は計測後に消したため、今は確かめられない）
- 起動 15 秒後に、A・B とも「初回セットアップ」のウィンドウが1つ開いていた。System Events で閉じるボタンを押してウィンドウを 0 にし、5 分置いてから `sample-process.sh` で 60 秒ごとに 30 分記録した。記録の前と後で、ウィンドウが 0 であることを確かめた
- 録音・認識は一度もしていない。STT Worker（`UtterSTTWorker`）の起動は、待機の 5 分の間に毎分と、記録の後に `pgrep` で確かめ、A・B とも検出されなかった（30 分の記録の途中は確かめておらず、短い起動は見逃しうる）
- ほかのアプリ（ブラウザ・エディタ・Xcode のビルドなど）は普段どおり動いていた

| 計測 | 音声認識の設定 |
|---|---|
| A | 未選択（`UTTER_MAC_STT_ENGINE=`） |
| B | SpeechAnalyzer（`UTTER_MAC_STT_ENGINE=speechAnalyzer`）。この日の作業では、utter の設定画面でモデルを取得していない（ロケールを予約していない）。ロケールの予約はシステム側に残るため、以前に予約していたかどうかは分からない |

再現のコマンドは [2026-10-31 の記録](2026-10-31-macOS待機時メモリ・CPU.md)と同じ。違いは次の2点。

```sh
# 1. 起動後、utter のウィンドウが開いていれば閉じる（手で閉じてもよい）。数が 0 になったことを確かめる
#    初回セットアップのウィンドウが開くかは、起動ごとに変わりうる（この日の別の起動では A で開かなかった）
osascript -e 'tell application "System Events" to tell process "utter" to repeat with w in (every window)
  click (first button of w whose subrole is "AXCloseButton")
end repeat'
osascript -e 'tell application "System Events" to count windows of process "utter"'
# 2. 計測中に Mac をスリープさせない。蓋を閉じない（caffeinate -i では蓋を閉じたときのスリープは防げない。
#    この日も caffeinate の有効中に蓋を閉じてスリープした）。アイドルによるスリープは caffeinate -i で防ぐ
```

注意：`sample-process.sh` の `--name` に起動していないプロセス（待機中の `UtterSTTWorker` など）を渡すと、記録を始めずに終わる。待機時は `--name utter` だけを渡す。

## 結果

| 計測 | 使った区間 | メモリ（Physical footprint） | 起動からの最大（`footprint_peak_mb`） | CPU 平均 | 6章の目標 |
|---|---|---|---|---|---|
| A（STT 未選択） | 30 分（1,760 秒、29 区間） | 32.7〜32.8MB | 33.7MB | 0.003% | ≤ 50MB・≤ 0.1% → **どちらも内** |
| B（SpeechAnalyzer） | 約 24 分（22:15〜22:39、1,457 秒、24 区間。スリープの前まで） | 33.1〜34.0MB | 34.4MB | 0.016% | 同上 → **どちらも内** |

- どちらも 6章の目標に収まった。30 分の間（B は 24 分の間）、メモリは増え続けなかった
- 画面をそろえると、A と B のメモリの差は 1MB 未満だった
- CPU 平均は、記録の間の CPU 時間の増分で見ると A が 0.05 秒、B が 0.24 秒だった。B は電池の残りが少ない時間帯（27% → 23%）で、ほかのアプリの負荷も同じではないため、STT の設定による差かは分からない。1 分ごとの値は `ps` の CPU 時間の単位（0.01 秒）のため 0.016% 刻みで、最大は A が 0.016%（1 刻み）、B が 0.049%（3 刻み）。1 分ごとの値どうしでは比べにくい

### 2026-10-31 の記録との比較

| 計測 | 2026-10-31（macOS 27.0.1、AC 電源） | 2026-11-01（macOS 27.2、バッテリー） |
|---|---|---|
| A | 38.8〜39.0MB（画面の状態は確かめていない） | 32.7〜32.8MB（メニューバーのみ） |
| B | 19.2〜21.2MB（計測後にウィンドウなしを確認） | 33.1〜34.0MB（メニューバーのみ） |

- 事実：A は約 6MB 減り、B は約 12MB 増えた。B はどちらの日もメニューバーだけの状態だったが、値が違う
- 事実：今回の起動からの最大（初回セットアップのウィンドウを開いていた間を含む）は A が 33.7MB、B が 34.4MB で、2026-10-31 の A の 38.8〜39.0MB に届いていない。今回の環境では、ウィンドウを開いていても A が 39MB 近くにはならなかった
- 2026-10-31 の約 18MB の差は、画面の状態の差では説明できない。OS（27.0.1 → 27.2）、ビルドしたコミット、電源、ウィンドウを一度開いて閉じたかどうかが両日で違い、原因は分からない。今回 A と B の差が 1MB 未満だったことから、STT の設定の差ではなかったと見ている（推測）

### B の後半（スリープと復帰）

22:40:03 に Mac の蓋が閉じた（`Clamshell Sleep`）。この時間帯の値は待機時の値として使わず、上の表から除いた。

- 22:40:12 に AC 電源につながり、約 2 秒だけ完全に復帰した（`DarkWake to FullWake ... Using AC`）。以後は AC 電源で、スリープと DarkWake を繰り返した
- 22:40:33 のサンプル（22:39:32 からの区間に、スリープ・DarkWake・FullWake・AC への切り替えがすべて入る）で、メモリは 33.1MB → 37.0MB、その区間の CPU は 0.424% になった。それ以降は 37.0MB のまま、CPU は 0.000% だった
- スリープのため、記録の間隔は 22:40:33 → 22:41:47 が 73.5 秒、22:43:48 → 22:50:22 が 394 秒に延びた
- スリープ・復帰のときに utter が何をしたか（メニューバーの再描画、ショートカットの登録し直しなど）は確かめていない。復帰のたびにメモリが増え続けるかは、スリープと復帰を繰り返す計測で別に確かめる

## 測れていないこと

- AC 電源での、画面をそろえた A・B（2026-10-31 との電源の条件の違いを埋める）
- 2026-10-31 と今回の値の違い（特に B の約 12MB）の原因
- 開発用署名（`build-local.sh`）のビルドでの値
- utter の設定画面でモデルを取得した（ロケールを予約した）状態の B
- スリープ・復帰を繰り返したときのメモリの推移
- 録音開始遅延・停止→挿入（Signpost）、録音中・認識中のメモリ、8時間待機の追加バッテリー消費、Bluetooth マイク
