# 合成音声での STT の比較（SpeechAnalyzer・WhisperKit、macOS・2026-10-31）

Phase 0 検証 [#48](https://github.com/harry2480/utter/issues/48)（SpeechAnalyzer）と [#49](https://github.com/harry2480/utter/issues/49)（WhisperKit）の計測記録。
人の声を録らずに進められる範囲として、macOS の読み上げ（`say`）で作った音声を同じ条件で両方に通した。

**合成音声の結果は、人の声での精度の代わりにはならない。** 傾向をつかむための参考値として扱い、11章の判定には人の声での計測を合わせて使う。

## 条件

- 実行日：2026-10-31
- 機種：Mac17,2・Apple M5・メモリ 24GB
- OS：macOS 27.0.1（Build 26A434）
- 音声：`say -v Kyoko -o <id>.wav --data-format=LEI16@16000 "<正解>"`（16kHz・モノラル・16bit。1件 約2〜4秒）
- 評価セット：[eval/synthetic-tts-set.json](../../eval/synthetic-tts-set.json)（日本語・日英混在・開発用語・数字の4区分 × 10件 = 40件）。音声は `eval/audio/synthetic/`（gitignore 済み）に置き、リポジトリに含めない
- 集計：`utter-eval`（[精度評価.md](../精度評価.md) の正規化・CER）
- SpeechAnalyzer：`SpeechAnalyzerProbe batch`（`--pace fast`、プリセット `progressive`、ロケール `ja_JP`）
- WhisperKit：`whisperkit-probe eval`（WhisperKit 1.1.1、`--compute default`、`--chunking vad`）。モデルごとに `fetch` してから `eval`

再現のコマンド（リポジトリのルートで実行）：

```sh
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
mkdir -p eval/audio/synthetic
python3 -c 'import json; [print(s["id"]+"\t"+s["reference"]) for s in json.load(open("eval/synthetic-tts-set.json"))]' |
  while IFS=$'\t' read -r id text; do say -v Kyoko -o "eval/audio/synthetic/$id.wav" --data-format=LEI16@16000 "$text"; done
python3 -c 'import json; s=json.load(open("eval/synthetic-tts-set.json")); json.dump([dict(x,audio=x["id"]+".wav") for x in s], open("eval/audio/synthetic/manifest.json","w"), ensure_ascii=False)'

# Probe のビルド
swift build -c release --package-path Verification/SpeechAnalyzerProbe
swift build -c release --package-path Verification/WhisperKitProbe

# SpeechAnalyzer（status で日本語のアセットを確かめ、未取得のときだけ install する）
sa=Verification/SpeechAnalyzerProbe/.build/release/SpeechAnalyzerProbe
$sa status --locale ja_JP
# $sa install --locale ja_JP
$sa batch eval/audio/synthetic/manifest.json --out Verification/SpeechAnalyzerProbe/output/synthetic-results.json \
  --log Verification/SpeechAnalyzerProbe/output/synthetic-batch.jsonl
swift run -c release --package-path Packages/UtterEvaluation utter-eval Verification/SpeechAnalyzerProbe/output/synthetic-results.json

# WhisperKit（3つのモデルそれぞれで fetch → eval → 集計）
wk=Verification/WhisperKitProbe/.build/release/whisperkit-probe
for m in openai_whisper-base openai_whisper-small openai_whisper-large-v3-v20240930_turbo_632MB; do
  $wk fetch --model "$m"
  $wk eval --model "$m" --set eval/synthetic-tts-set.json --audio-dir eval/audio/synthetic --out "$TMPDIR/wk-$m" >/dev/null
  swift run -c release --package-path Packages/UtterEvaluation utter-eval "$TMPDIR/wk-$m/samples.json"
done

# 速度・メモリ（40件の集計）
# SpeechAnalyzer：--log の summary（audioSeconds・realTimeFactor・lifetimeMaxPhysFootprintMB）から求める
python3 -c 'import json; s=[json.loads(l) for l in open("Verification/SpeechAnalyzerProbe/output/synthetic-batch.jsonl") if "\"summary\"" in l]; a=sum(x["audioSeconds"] for x in s); print("RTF", sum(x["realTimeFactor"]*x["audioSeconds"] for x in s)/a, "最大MB", max(x["lifetimeMaxPhysFootprintMB"] for x in s))'
# WhisperKit：eval の出力先の summary.csv（phase=eval の wall_s・audio_s、phase=load の wall_s）と memory.csv（lifetime_max_mb・thermal_state）から求める
for m in openai_whisper-base openai_whisper-small openai_whisper-large-v3-v20240930_turbo_632MB; do
  python3 -c 'import csv,sys; d=sys.argv[1]; r=list(csv.DictReader(open(d+"/summary.csv"))); e=[x for x in r if x["phase"]=="eval"]; m=list(csv.DictReader(open(d+"/memory.csv"))); print(d, "load", [x["wall_s"] for x in r if x["phase"]=="load"], "RTF", sum(float(x["wall_s"]) for x in e)/sum(float(x["audio_s"]) for x in e), "最大MB", max(float(x["lifetime_max_mb"]) for x in m), {x["thermal_state"] for x in m})' "$TMPDIR/wk-$m"
done

# SpeechAnalyzer の遅延・OS 側のメモリ（40件の正解を「。」でつないで1つの音声（約127秒）にし、実時間で流す）
say -v Kyoko -o eval/audio/synthetic/long.wav --data-format=LEI16@16000 \
  "$(python3 -c 'import json; print("。".join(s["reference"] for s in json.load(open("eval/synthetic-tts-set.json"))))')"
$sa file eval/audio/synthetic/long.wav --pace realtime --log Verification/SpeechAnalyzerProbe/output/long.jsonl &
sleep 3; while kill -0 $! 2>/dev/null; do footprint -p "$(pgrep -f localspeechrecognition.xpc | head -1)" | grep -m1 Footprint; sleep 5; done
```

## 精度（CER、用語正答率）

CER は低いほどよい。括弧内は文字数（用語正答率は用語の数）。

| 区分 | SpeechAnalyzer | WhisperKit base | WhisperKit small | WhisperKit large-v3 turbo（632MB） |
|---|---:|---:|---:|---:|
| 日本語（n=164） | 2.4% | 6.7% | 1.8% | **0.0%** |
| 日英混在（n=201） | 39.8% | **27.9%** | 28.4% | 31.8% |
| 開発用語（n=208） | 44.7% | 49.0% | 45.7% | **25.0%** |
| 数字（n=143） | 6.3% | 8.4% | 5.6% | **4.9%** |
| 合計（n=716） | 26.0% | 25.3% | 22.8% | **17.2%** |
| 用語正答率・全体（n=30） | 13.3% | 16.7% | 20.0% | **33.3%** |
| 用語正答率・開発用語だけ（n=16） | 12.5% | 6.3% | 12.5% | **31.3%** |

読み取れること：

- 日本語の一般的な文は、SpeechAnalyzer・WhisperKit small 以上とも誤りがほとんどない
- 日英混在・開発用語は、どれも CER が 25〜50% と高い。主な原因は2つで、精度そのものの不足とは分けて考える必要がある
  - 表記の違い：SpeechAnalyzer は英単語をカタカナで返すことが多い（例：meeting → 「ミーティング」、Slack → 「スラック」、merge → 「マージ」）。意味は合っていても CER・用語正答率では誤りになる。用語の置き換え（TXT 側の辞書）で直せる種類の誤り
  - 合成音声の限界：日本語の声（Kyoko）は英単語を日本語の音で読むため、「tutorial」「JSON」「async await」などは人の発音とかなり違う。SpeechAnalyzer の出力でも「YouTubeでテートリーラル王を見ました」「ドジさんをダー」のように、読み上げの音に引きずられた誤りがある
- 数字は、漢数字の正解に対してどれも算用数字で返す（「3時半」「1500円」）。`utter-eval` の正規化で大半は一致として数えられている。SpeechAnalyzer は「二十5人」（二十五人）と「逆に 2.5キロ」（約2.5キロ）の2件で誤った
- large-v3 turbo は開発用語で目立って良い（CER 25.0%、開発用語の用語正答率 31.3%）。ただし後述のとおり初回のロードが長い

## 速度・メモリ

| | SpeechAnalyzer | WhisperKit base | WhisperKit small | WhisperKit large-v3 turbo |
|---|---:|---:|---:|---:|
| モデルの取得 | この Mac では日本語のアセットが取得済みで、予約のみで使えた（未取得なら Apple のサーバーから取得する） | 36.7 秒 / 142.7MB | 83.4 秒 / 478.8MB | 124.2 秒 / 623.6MB |
| 初回ロード（取得直後。トークナイザーの取得 約2秒を含む） | — | 8.5 秒 | 19.0 秒 | **132.2 秒** |
| 2回目以降のロード | 0.01〜0.10 秒（`prepareToAnalyze`） | 0.38 秒 | 0.45 秒 | 1.39 秒 |
| 実時間比（40件の処理時間の合計 ÷ 音声長の合計 125.7 秒。小さいほど速い） | 0.015 | 0.031 | 0.079 | 0.157 |
| 認識中のメモリ（自プロセス、40件の実行中の phys_footprint の最大） | 4.1MB | 87.8MB | 109.0MB | 113.0MB |
| 認識中のメモリ（OS 側のプロセス） | `localspeechrecognition` 38〜42MB（`footprint`） | — | — | — |
| 熱状態 | — | nominal | nominal | nominal |

- SpeechAnalyzer の推論は、OS の XPC サービス `localspeechrecognition`（`/System/Library/Frameworks/Speech.framework/.../localspeechrecognition.xpc`）で動いていた。約127秒の合成音声を `file --pace realtime` で流している間、5秒ごとに `footprint -p <pid>` で測ると 38〜42MB だった（同じ実行で自プロセスは最大 5.8MB。表の 4.1MB は40件を `batch --pace fast` で流した別の実行の値で、1件 約3秒の短い音声のため小さい）。`corespeechd`（約15MB）は認識の前から動いていた。6章の目標（500MB 以下）に対して、自プロセスと OS 側を足しても十分に小さい
- 同じ約127秒の実時間での実行では、暫定結果の遅延は p50 0.030 秒・p95 0.049 秒、入力終了→最後の確定は 0.038 秒だった（マイクではなくファイルを実時間で流した値。マイクの入力遅延を含まない）
- WhisperKit のメモリは Core ML のモデル分（GPU・ANE 側）を含まない可能性がある（[WhisperKitProbe の README](../../Verification/WhisperKitProbe/README.md) の「メモリの指標について」）
- large-v3 turbo の初回ロード 132 秒は、Core ML がこの Mac 向けにモデルを最適化する時間が大半（encoder 124 秒）と見られる（推測）。2回目以降は 1.3 秒

## まだ測っていないこと

- 人の声での精度（日英混在・開発用語は特に、合成音声では判断できない）
- 騒音・自己訂正の区分、50件以上での評価（[精度評価.md](../精度評価.md) の評価セットの規模）
- オフラインでの認識（SpeechAnalyzer）
- WhisperKit の長時間の連続利用での熱・電力・安定性（#49）
- WhisperKit の medium・量子化版など、ほかのモデル
