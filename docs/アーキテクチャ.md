# utter アーキテクチャ設計規約

Swift 6 / Swift Package Manager / Xcode における、macOS・iOS 共通のモジュール設計規約。
要件の根拠は [要件定義.md](要件定義.md) の4章・13章。

---

## ディレクトリ構成

```text
Packages/
├── UtterCore/          # セッション状態機械・共通モデル・エラー型
├── UtterSpeech/        # 音声認識インターフェースと STT アダプター
├── UtterSpeechWhisperKit/ # WhisperKit で推論する STT エンジン（WhisperKit を依存に持つ。先行実装・既定で無効）
├── UtterAI/            # AI Provider・プロンプト・応答検証
├── UtterText/          # テキスト整形・保護対象・辞書・用語置換
├── UtterPersistence/   # 設定・辞書・使用量・共有結果の永続化
└── UtterEvaluation/    # 精度評価の正規化・CER・集計（開発用。アプリにリンクしない）
Apps/
├── macOS/              # メニューバーアプリ（HUD、ホットキー、挿入、認証、設定）
└── iOS/                # 本体アプリ（録音、STT、整形、結果保存）
Extensions/
└── iOSKeyboard/        # カスタムキーボード（結果表示と insertText のみ）
Workers/
└── macOSSTT/           # XPC STT Worker（モデルロード・推論・解放）
```

各 Package は `Sources/<Module>/` と `Tests/<Module>Tests/` を持つ。ターゲットごとの Entitlement、Info.plist、ビルド設定は分離する。

## モジュールの責務

| モジュール | 責務 | 置かないもの |
|---|---|---|
| UtterCore | `Session`（待機→録音→認識→整形→挿入→待機の状態機械, REC-06）、セッションID・順序番号、共通エラー型、スタイル区分とアプリ別スタイル判定（bundle ID の既定対応表と上書き, CTX-01 / CTX-02。前面アプリの取得は Apps/macOS）、同意状態のモデル、グローバルショートカットの判定と競合検出（REC-01 / REC-02。キー登録・イベント取得は Apps/macOS）、HUD の表示内容のモデル（REC-03 / REC-05。パネル表示は Apps/macOS）、録音中の割り込みへの対応方針（iOS-PERF-03）、キーボード拡張で提示する操作と案内の判定（iOS-09 / iAC-06 / iAC-07。入力欄の属性・フルアクセスの取得と画面は Extensions/iOSKeyboard） | OS 固有 API、I/O |
| UtterSpeech | `SpeechRecognizer` protocol（`partial` / `confirmed` / `completed` / `failed`）、SpeechAnalyzer / WhisperKit アダプター、音声バッファ上限（REC-05）、Realtime Preview の確定済み・暫定テキスト（2.2節, AC-03。HUD への表示は Apps/macOS）、一時保存・再認識に使う録音音声の形式 `RecordedAudio`（7章, AC-10）、STT モデルの完全性検証（PERM-03。マニフェストとの照合。取得処理と表示は Apps）、WhisperKit アダプターの設定・推論結果からイベントへの変換・モデルのフォルダの判定（WhisperKit 自体には依存しない） | UI、AI 整形、モデルのダウンロード、WhisperKit への依存 |
| UtterSpeechWhisperKit | WhisperKit で推論する `SegmentTranscriber` の本番実装 `WhisperKitTranscriber`（照合済みのフォルダからの通信しないロード・推論・解放、失敗の分類） | モデルのダウンロード、UI |
| UtterAI | `AIProvider` protocol、Claude / ChatGPT / Local Basic 実装、Refinement Router、応答検証とローカル退避（4.1節）、費用推定（AI-05）、`refine` 呼び出し時点の同意状態による送信前の確認（送信先ごとの整形の同意, AC-06。送信先は Claude API のホストに限定） | 認証 UI、Keychain の直接操作 |
| UtterText | Raw / Natural / Structured 整形、数字・URL・コード・辞書語の保護、ユーザー辞書・置換ルール、Edit Mode の差分と編集の状態（AC-14。選択範囲の取得・置き換えは Apps/macOS）、Realtime Direct の使える条件・書き込み範囲の追跡と差分・取り消し（AC-15。位置は UTF-16。入力欄の読み書きと互換性表の検証は Apps/macOS） | ネットワーク |
| UtterPersistence | UserDefaults 設定、GRDB による辞書・使用量・任意履歴、iOS App Group の共有結果（iOS-IPC-*）、形式に依存しない一時音声の保存・保持期限・復旧候補 `TemporaryAudioStore`（7章, AC-10） | 秘密情報（Keychain は各アプリの責務） |
| UtterEvaluation | 精度評価（9章, AC-04）の正規化規則・CER・用語正答率・区分別集計と `utter-eval` コマンド。規則は [精度評価.md](精度評価.md) | アプリ・拡張・Worker からのリンク、評価用音声 |
| Apps / Extensions / Workers | OS 固有 API のアダプター、画面、権限要求、DI の組み立て | 共通化できる業務ロジック |

## 依存方向（厳守）

```
Apps / Extensions / Workers
        ↓
UtterSpeech  UtterAI  UtterText  UtterPersistence
        ↓
     UtterCore
```

- **UtterCore は最内層。** Foundation 以外に依存しない
- **Packages 同士は UtterCore を介して連携する。** UtterAI → UtterText のように横依存が必要な場合は、理由を docs に残してから追加する
  - UtterAI → UtterText：整形応答の検証（4.1節）で、保護対象（数字・URL・コード・辞書語）の保持を `ProtectionChecker` で判定するため。UtterText は UtterAI に依存しない
- **Packages は Apps / Extensions / Workers に依存しない**
- **UtterSpeechWhisperKit は UtterSpeech と UtterCore と WhisperKit に依存し、Packages からは依存されない。** WhisperKit を使うターゲット（macOS STT Worker など）だけがリンクする
- **UtterEvaluation は開発用で、他の Package にも Apps / Extensions / Workers にも依存されない。** 評価対象のテキストは JSON で受け取る
- **AppKit / UIKit / ApplicationServices（AX）/ CGEvent は Apps 側だけで使う。** Packages は protocol を定義し、Apps がアダプターを実装する
- **Extensions/iOSKeyboard は UtterCore と UtterPersistence（共有結果の読み取り）のみに依存する。** UtterSpeech・UtterAI をリンクしない（iAC-08、メモリ制約）
- **DI の組み立て（Composition Root）は各アプリの起動部だけで行う。** 設定値に応じて本番実装と Stub を切り替える

## 外部 API と Stub

外部 API（Claude Messages API、ChatGPT Responses API、STT エンジン）は3点セットで実装する。

| 種類 | 配置 | 例 |
|---|---|---|
| protocol | 該当 Package の `Sources/` | `AIProvider`, `SpeechRecognizer` |
| 本番実装 | 同 Package | `ClaudeProvider`, `WhisperKitRecognizer` |
| Stub 実装 | 同 Package（テストからも使える） | `StubAIProvider`, `StubSpeechRecognizer` |

- Stub は固定応答に加え、遅延・タイムアウト・認証失効・予算超過などのエラーを注入できるようにする（AI-06 のテスト用）
- 本番実装は URLSession を DI で受け取り、テストでは通信しない
- モデル名・単価表はコードに固定せず設定値にする（AI-05 / AI-07）

## 並行処理

- Swift 6 language mode / strict concurrency を全ターゲットで有効にする
- 状態を持つサービスは `actor` か `@MainActor` に明示的に隔離する。`@unchecked Sendable` で回避しない
- 音声チャンクは `AsyncStream` で流し、バッファ上限とバックプレッシャーを実装する
- キャンセル済みセッションの遅延レスポンスは、セッションID と順序番号で破棄する

---

## エラー処理

- 失敗の種類ごとに型を分ける（タイムアウト、認証失効、利用枠不足、予算超過、ネットワーク切断を別ケースにする, AI-06）
- エラーの文言・`description` に発話本文、トークン、API キーを含めない
- 発話を失わないことを優先する。クラウド整形の失敗はローカル整形結果で挿入し、HUD で通知する（AC-16）

## iOS の録音割り込み（iOS-PERF-03）

録音中の画面ロック・電話着信・オーディオ割り込み・低電力モード・熱状態変化への対応は、UtterCore の
`RecordingInterruptionPolicy`（判定）と `SessionStateMachine.handleInterruption(_:capturedAudioDuration:policy:)`（遷移）が持つ。
OS の通知は Apps/iOS のアダプターが `RecordingInterruption` に変換して渡し、UtterCore は OS の型に依存しない。

| OS の通知（Apps/iOS で受ける） | `RecordingInterruption` | 既定の対応 |
|---|---|---|
| `AVAudioSession.interruptionNotification`（`.began`） | `.audioInterruptionBegan` | 録音を止めて処理する |
| `AVAudioSession.interruptionNotification`（`.ended`） | `.audioInterruptionEnded` | 何もしない（自動で再開しない） |
| `AVAudioSession.routeChangeNotification`（`.oldDeviceUnavailable`） | `.audioRouteChanged(.inputDeviceLost)` | 録音を止めて処理する（設定で継続も可） |
| 同（`.newDeviceAvailable` / それ以外） | `.audioRouteChanged(.inputDeviceAdded / .other)` | 継続する |
| `AVAudioSession.mediaServicesWereResetNotification` | `.mediaServicesReset` | 録音を止めて処理する |
| `UIApplication.willResignActiveNotification` | `.appWillResignActive` | 継続する（マイクを奪われたら割り込み開始が別に届く） |
| `UIApplication.didEnterBackgroundNotification`（画面ロックを含む） | `.appDidEnterBackground` | 録音を止めて処理する |
| `ProcessInfo.thermalStateDidChangeNotification` | `.thermalStateChanged(_:)` | `critical` 以上で録音を止めて処理する（閾値は設定可） |
| `NSProcessInfoPowerStateDidChange` | `.lowPowerModeChanged(isEnabled:)` | 継続する（設定で停止も可） |

- **音声を破棄しない（REC-05）。** 録音を止めるときは、取得済みの音声を通常どおり認識へ渡す（`stopReason` は `.interrupted(原因)`）。
  取得済みの音声が下限（既定 0）以下で処理できないときだけ `error(.recording)` にして失敗を表示し、無言で終わらせない
- **割り込み後に録音を自動で再開しない。** 着信の後などに利用者の意図しない録音を始めないため、再開は利用者の操作で新しいセッションとして行う
- **常時録音のための Background Modes（`audio`）は使わない（iOS-PERF-02, iOS-PERF-03）。** バックグラウンドへ移ったら録音を止め、
  バックグラウンド実行の制限を迂回しない。止めた後の認識をいつ実行するか（前面に戻ってから実行する、音声を一時保存して後で処理するなど）と、
  熱状態が高いときに STT を遅らせるかは Phase i1 の iOS 録音・STT 実装で決める
- 既定値（熱状態の閾値 `critical`、低電力モードで止めない、入力機器の喪失で止める、音声の下限 0）は **Phase i0 の実機検証前の仮定**で、
  検証結果に応じて見直す

## 一時音声と再処理（7章, AC-10）

STT Worker の異常終了やアプリの異常終了で発話を失わないよう、録音した音声を一時保存して認識をやり直せるようにする。
STT Worker の異常終了ではメモリ上の録音全体を、アプリの異常終了では最後に保存した時点までの音声を戻せる。
保存形式は UtterSpeech の `RecordedAudio`（PCM16 モノラル、先頭に識別子・版・サンプリング周波数）、
保存先と保持期限は UtterPersistence の `TemporaryAudioStore` が持つ。UtterPersistence は形式に依存せず、バイト列だけを扱う。

1. 録音中のチャンクを `RecordedAudio.append(_:)` で溜める
2. 必要なとき（認識へ渡す前など）に `encoded()` を `TemporaryAudioStore.save(_:for:)` で保存する
3. 認識・整形・挿入が正常に終わったら `TemporaryAudioStore.remove(_:)` で削除する
4. STT Worker が異常終了しても、メインアプリのメモリには `RecordedAudio` が残っている。その `stream()` を
   `SpeechRecognizer.recognize(_:session:)` に渡して認識をやり直す（ディスクから読み直さない）。
   一時音声と状態機械が同じセッションを指すよう `SessionID` は使い回し、順序番号は 0 から始まり直すため、
   渡す前に `RecognitionEventFilter.begin(_:)` を同じ `SessionID` で呼んで受け手の順序番号を初期化する
5. アプリ自体が異常終了した後の起動時は、`sweep()` で保持期限（暫定24時間）を過ぎたものを削除し、残り（`recoverable`）の
   復旧を利用者に確認する。`save` は古い音声を消せなくても成功扱いのため、同じセッションの音声が複数残ることがある。
   `recoverable` はセッションごとにまとめ、作成時刻が新しい順に `load(_:)` → `RecordedAudio(decoding:)` を試し、
   最初に戻せたものを使う。戻せない（`unsupportedFormat` / `corrupted`）ものは飛ばして次に古いものを試し、
   復旧を終えた場合と、すべて戻せなかった場合に `remove(_:)` でそのセッションをまとめて削除する

- 保存する頻度（録音の停止時だけか、録音中も定期的に保存するか）と、復旧の確認画面は Apps/macOS・Apps/iOS で決める。
  録音中に一度も保存しないうちにアプリが異常終了した場合、その録音は戻せない。停止時だけ保存するなら、戻せるのは
  停止後（認識・整形・挿入の途中）の異常終了に限られる。
  保存は毎回録音全体を書き直すため、録音中に定期的に保存すると書き込み量は録音時間と保存回数の積で増える

## iOS キーボードの利用可否と案内（iOS-09, iAC-06, iAC-07）

キーボード拡張が提示する操作と案内は、UtterCore の `KeyboardAvailability` が `KeyboardEnvironment`（拡張が観測した状態）から決める。
拡張は OS の値を OS 非依存の値に変換して渡すだけにし、判定を持たない。

| 観測する状態（Extensions/iOSKeyboard で取る） | `KeyboardEnvironment` |
|---|---|
| `textDocumentProxy.isSecureTextEntry` | `inputField.secureTextEntry`（取れなければ `unknown`） |
| `textDocumentProxy.keyboardType` が `phonePad` / `namePhonePad` | `inputField.phoneNumber`（取れなければ `unknown`） |
| `hasFullAccess` | `hasFullAccess` |
| App Group の共有コンテナを読めるか | `sharedContainer`（`.unavailable` / `.available(hostApp:)`） |
| 本体アプリが共有コンテナに残した権限・STT モデル・整形設定と観測時刻 | `.available(hostApp:)` の `HostAppStatus`（なければ `nil`） |
| 拡張で観測したネットワーク（`NWPathMonitor` など） | `network`（観測できなければ `unknown`） |

- **制約を回避しない（iOS-09, iAC-06）。** セキュア入力欄・電話番号欄・属性を判定できない欄では、通常の文字入力と地球儀キーだけを残し、
  共有結果の読み込み・挿入と本体アプリへの移動を提示しない。標準キーボードへの切り替えを案内する。
  キーボード禁止アプリでは OS が拡張を起動しないため、検出・回避する仕組みは作らない
- **共有結果を読めない原因を分けて案内する（iAC-07）。** フルアクセスが無効ならフルアクセスの許可、フルアクセスがあっても読めなければ
  App Group の Entitlement・署名の不備として入れ直しを案内する。フルアクセスが必須かは決め打ちせず、共有コンテナを読めたかで判定する
  （Phase i0 の検証結果に依存しないため）
- 権限拒否・STT モデル未取得は本体アプリの状態として、オフラインは拡張で観測した値として案内し、対処（設定での許可、
  ネットワーク接続、本体アプリでの取得）を添える。ネットワークは変わりやすく、本体アプリが残した値では古い案内が出るため、拡張側で観測する
- **古い本体アプリの状態で案内しない。** `HostAppStatus` は観測時刻を持ち、鮮度の上限（既定 1 時間、暫定）を超えたもの、
  観測時刻が現在より後のものは、状態がない場合と同じく案内に使わない。本体アプリは前面に来たときなどに状態を残し直す。
  `HostAppStatus` を App Group に残す保存処理は、本体アプリの実装（Phase i1/i2）で扱う

## STT モデルの完全性検証（PERM-03）

取得した STT モデルは、UtterSpeech の `ModelIntegrityVerifier` でマニフェスト（`ModelManifest`：相対パス・サイズ・SHA-256）と照合し、
`ModelIntegrityStatus.verified` のときだけロードする（`isLoadable`）。ディレクトリの読み取りは `ModelFileSource` protocol 越しに行い、
本番は `LocalModelFileSource`（FileManager / CryptoKit）、テストは `StubModelFileSource` を使う。

- **検証失敗にするもの：** ファイルの欠落、サイズの不一致、SHA-256 の不一致、読み込みの失敗、マニフェストにないファイル、
  シンボリックリンクなど通常ファイルでない項目。マニフェスト自体も、絶対パス・`..`・重複パス（大文字・小文字、Unicode 正規化の違いを含む）を拒否する
- **`.DS_Store` などの隠しファイルも、マニフェストになければ検証失敗にする。** 無視するファイル名は設けない（取得し直せば直る）。Finder で開いただけで失敗する可能性があり、緩めるかは今後判断する
- **マニフェストはモデルと別の信頼できる経路で持つ。** モデルと同じ取得元から同時に受け取ったマニフェストでは、破損は検出できても改ざんは検出できない。
  マニフェストの配布方法（アプリへの同梱など）は Phase 0 の STT 方針とモデル配布方法（14章）の確定後に決める
- 検証は同期的にファイルを読むため、メインスレッドの外で呼ぶ。キャンセルされたら `CancellationError` を投げる
- ダウンロード処理、取得元・サイズの表示（`ModelManifest.totalByteCount` を使う）、特定エンジン（SpeechAnalyzer / WhisperKit）のモデル形式は対象外で、
  Phase 0 の結果を受けて Apps / アダプター側で実装する

## WhisperKit アダプター（先行実装）

Phase 0 #49（モデル選定）と #47（ライセンス確定）の判定待ちの先行実装。**既定で無効**で、`WhisperKitRecognizerConfiguration.isEnabled` を
明示的に `true` にしない限り、`recognize` は音声を読まずに `failed(.modelUnavailable)` で終える。アプリ・Worker にはまだリンクしない。

WhisperKit は UtterSpeech とは別の Package（UtterSpeechWhisperKit）に閉じ込め、UtterSpeech をビルド・リンクしても WhisperKit を取得しない。
推論以外の処理は WhisperKit に依存しない形で UtterSpeech に置き、モデルなしでテストする。

| 型 | Package | 役割 |
|---|---|---|
| `WhisperKitRecognizer<Transcriber>` | UtterSpeech | `SpeechRecognizer` の実装。音声を読み、`SegmentTranscriber` で推論してイベントを流す |
| `WhisperKitRecognizerConfiguration` | UtterSpeech | 有効化フラグ、言語、推論し直す間隔、未確定として残す区間の数（すべて仮置き） |
| `WhisperTranscriptAssembler` | UtterSpeech | 推論結果の区間から `partial` / `confirmed` / `completed` を作る |
| `WhisperKitModelCheck` | UtterSpeech | モデルのフォルダをロードしてよいかの判定（マニフェストの必須ファイルと `ModelIntegrityVerifier`） |
| `SegmentTranscriber` / `TranscribedSegment` / `StubSegmentTranscriber` | UtterSpeech | 推論エンジンの口・結果・テスト用の実装 |
| `WhisperKitTranscriber` / `WhisperKitModel` | UtterSpeechWhisperKit | WhisperKit でのロード・推論・解放 |

- **逐次の結果：** WhisperKit はまとまった音声を推論するため、新しい音声が `transcriptionInterval`（仮置き 1 秒）たまるたびに未確定の音声全体を推論し直す。
  結果の区間のうち末尾の `requiredSegmentsForConfirmation`（仮置き 2）個より前を `confirmed` にし、その終わりまでの音声を捨てる。残りは `partial`。
  音声が終わったら未確定の音声を推論し、全体を `completed` にする（WhisperKit の `AudioStreamTranscriber` と同じ考え方。マイク入力を持つ同クラスは使わない）
- **推論の遅れ：** 推論の間も別のタスクで音声を読み続け、次の推論でそれまでに届いた分をまとめて扱う。推論が録音より遅くても遅れが積み重ならず、
  推論中に録音が終わったら途中の推論をせずに最後の推論に進む（録音済みの音声は1回だけ推論する）
- **未確定の音声の上限：** 未確定の音声が 30 秒（仮置き）を超えたら、末尾の1区間を残して確定する。区間がない（無音）なら末尾 5 秒（仮置き）を残して捨てる。
  確定しない状態が続いて、推論し直す量が増え続けるのを防ぐ
- **長い音声：** WhisperKit の VAD による分割（`chunkingStrategy: .vad`）は使わない。v1.1.1 は分割した一部の推論の失敗を例外にせず結果から外すため、
  発話の一部を黙って失う。30 秒を超える音声は WhisperKit の通常の処理（30 秒ずつ順に進める）に任せる
- **音声の形式：** 16kHz モノラルだけを受け付け、違えば `failed(.unsupportedAudioFormat)`。変換は録音側で行う
- **モデル：** 同梱もダウンロードもしない。Apps が取得し、`WhisperKitModel`（ディレクトリ・マニフェスト）で渡す。モデルの種類は WhisperKit が次元から判定する。
  トークナイザーはモデルのディレクトリの直下に置き、同じマニフェストで照合する（[ライセンス・依存関係.md](ライセンス・依存関係.md) 3.4 の案 a）。
  モデル名の仮置きは `openai_whisper-tiny`（WhisperKitProbe の候補のうち最小の多言語モデル）
- **通信しないロード：** WhisperKit はフォルダ直下より先に `models/openai/whisper-*/` の下のトークナイザーを探し、読めなければ Hugging Face から取得するため、
  マニフェストに `models/` で始まるパスを置かせない（マニフェストにないファイルは照合で失敗するため、フォルダには直下のトークナイザーしか置けない）。
  照合（`.ready`）→ トークナイザーを WhisperKit と同じ経路で読めることの確認 → `modelFolder` / `tokenizerFolder` に照合済みのフォルダを指定し
  `download: false` で初期化、の順に行い、どれかに失敗したらロードしない。実際に通信しないことは #49 の実機確認で通信を監視して確かめる
- **失敗の分類：** モデル・トークナイザー・初期化の失敗とロード中の失敗は `.modelUnavailable`、推論中の失敗は `.engineFailed`。WhisperKit のエラー文言は使わない（パスを含みうる）
- **保持と解放：** ロードしたモデルは `WhisperKitTranscriber.unload()` まで保持する。保持・解放の判断は呼び出し側が `ModelRetentionPolicy` で行う。
  macOS では STT Worker（要件定義 3章のプロセス隔離）に置く想定
- **ログ：** WhisperKit のログは無効にする。認識テキストを持つ型の `description` は文字数だけを出す
- メモリ・熱の目標値と、モデル・設定値の決定は #49 の実測で行う。不成立なら UtterSpeechWhisperKit と上の表の UtterSpeech の型を消す

## 命名規約

- 型は UpperCamelCase、ファイル名は主たる型名と一致させる（`SpeechRecognizer.swift`）
- protocol は役割名（`AIProvider`）、実装は `<方式><役割>`（`ClaudeProvider`, `LocalBasicRefiner`）、Stub は `Stub<役割>`
- テストファイルは `<対象型>Tests.swift`
- 機能IDに対応するテストは `@Test("REC-05: 最大録音時間で自動停止する")` のように表示名へ機能IDを含める
