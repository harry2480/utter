# utter アーキテクチャ設計規約

Swift 6 / Swift Package Manager / Xcode における、macOS・iOS 共通のモジュール設計規約。
要件の根拠は [要件定義.md](要件定義.md) の4章・13章。

---

## ディレクトリ構成

```text
Packages/
├── UtterCore/          # セッション状態機械・共通モデル・エラー型
├── UtterSpeech/        # 音声認識インターフェースと STT アダプター
├── UtterSpeechWhisperKit/ # WhisperKit で推論する STT エンジン（WhisperKit を依存に持つ。先行実装・既定で無効）
├── UtterAI/            # AI Provider・プロンプト・応答検証
├── UtterText/          # テキスト整形・保護対象・辞書・用語置換
├── UtterPersistence/   # 設定・辞書・使用量・共有結果の永続化
└── UtterEvaluation/    # 精度評価の正規化・CER・集計（開発用。アプリにリンクしない）
Config/                 # アプリターゲット共通の xcconfig（署名・識別子の既定値、Local.xcconfig の雛形）
Apps/
├── macOS/              # メニューバーアプリ（HUD、ホットキー、挿入、認証、設定）。project.yml（xcodegen）が正
└── iOS/                # 本体アプリ（録音、STT、整形、結果保存）。project.yml（xcodegen）が正
    ├── Sources/        # AVAudioSession / AVAudioEngine・UIKit のアダプター、画面、DI の組み立て
    └── UtteriOSKit/    # 録音セッションの進行・割り込みの変換・結果の保存先の選択（OS の API を使わずにテストする部分）
Extensions/
└── iOSKeyboard/        # カスタムキーボード（文字入力、結果のプレビューと insertText のみ）。Apps/iOS/project.yml のターゲット UtterKeyboard
Workers/
└── macOSSTT/           # XPC STT Worker（モデルロード・推論・解放）
```

各 Package は `Sources/<Module>/` と `Tests/<Module>Tests/` を持つ。ターゲットごとの Entitlement、Info.plist、ビルド設定は分離する。

## モジュールの責務

モジュールごとに「責務」と「置かないもの」を1項目1行で書く。
新しい項目は、末尾にまとめて足さず、関係する項目の直後に1行で足す（複数の PR が同じ行を書き換えて衝突しないようにするため）。

### UtterCore

責務:

- `Session`（待機→録音→認識→整形→挿入→待機の状態機械, REC-06）
- セッションID・順序番号
- 共通エラー型
- スタイル区分とアプリ別・サイト別スタイル判定（bundle ID の既定対応表と上書き、明示的許可制のサイト別上書きとホスト名の正規化, CTX-01 / CTX-02。前面アプリとブラウザの URL の取得は Apps/macOS）
- 同意状態のモデルと、同意の画面の状態・文言（送信先・送信内容ごとの行、送るもの・送らないもの, AC-06 / AI-04 / CTX-03。画面の表示は Apps/macOS）。常に出す行は共通の `presentedScopes` に、画面ごとの機能の行（macOS の Edit Mode の選択テキストの送信 `editModeScopes`、クラウド STT の音声の送信 `cloudSpeechRecognitionScopes`）を `additionalScopes` で足す
- グローバルショートカットの判定と競合検出（REC-01 / REC-02。キー登録・イベント取得は Apps/macOS）
- HUD の表示内容のモデル・表示文言（失敗の理由を含む）・表示と表示時間の更新制御・Realtime Preview の認識テキストの表示範囲（REC-03 / REC-05 / AC-03、ローカル整形への退避の通知 4.1節 / AC-16。録音停止（または失敗の理由）と退避の通知は同時に複数表示する。パネルと画面は Apps/macOS）
- 録音中の割り込みへの対応方針（REC-04 / iOS-PERF-03。OS の通知の取得は Apps/iOS・Apps/macOS）
- キーボード拡張で提示する操作と案内の判定（iOS-09 / iAC-06 / iAC-07。入力欄の属性・フルアクセスの取得と画面は Extensions/iOSKeyboard）
- 権限の段階的な要求と取り消し時の機能の無効化の判定・オンボーディングの段階（PERM-01 / PERM-02。権限の状態の取得・要求ダイアログ・案内の画面は Apps/macOS）
- macOS の自動更新を起動してよいかの判定 `SoftwareUpdateConfiguration`（3章「自動更新」。appcast URL と公開鍵の検証。Info.plist の読み取りと Sparkle の起動は Apps/macOS）

- OS 固有 API
- I/O

## 依存方向（厳守）

```
Apps / Extensions / Workers
        ↓
UtterSpeech  UtterAI  UtterText  UtterPersistence
        ↓
     UtterCore
```

- **UtterCore は最内層。** Foundation 以外に依存しない
- **Packages 同士は UtterCore を介して連携する。** UtterAI → UtterText のように横依存が必要な場合は、理由を docs に残してから追加する
  - UtterAI → UtterText：整形応答の検証（4.1節）で、保護対象（数字・URL・コード・辞書語）の保持を `ProtectionChecker` で判定するため。また、整形の入力を組み立てる前に `UserDictionary` の置換ルールを適用し辞書語を取り出すため（TXT-03）。UtterText は UtterAI に依存しない
  - UtterAI → UtterSpeech：クラウド STT（`OpenAISpeechRecognizer`, #60）が `SpeechRecognizer` に準拠し、`RecordedAudio` で音声を溜めるため。
    送信部（`HTTPStreamingTransport`）・送信先のホスト制限・`BudgetGuard` は UtterAI にあり、UtterSpeech に複製しない。UtterSpeech は UtterAI に依存しない
- **Packages は Apps / Extensions / Workers に依存しない**
- **UtterSpeechWhisperKit は UtterSpeech と UtterCore と WhisperKit に依存し、Packages からは依存されない。** WhisperKit を使うターゲット（macOS STT Worker など）だけがリンクする
- **UtterEvaluation は開発用で、他の Package にも Apps / Extensions / Workers にも依存されない。** 評価対象のテキストは JSON で受け取る
- **AppKit / UIKit / ApplicationServices（AX）/ CGEvent は Apps 側だけで使う。** Packages は protocol を定義し、Apps がアダプターを実装する
- **Apps/iOS/UtteriOSKit は Apps/iOS だけが使う。** Packages 同士の横依存を増やさずに録音〜保存の流れを組み立て、テストできるようにするための置き場で、Packages からも Extensions からも依存しない
- **Extensions/iOSKeyboard は UtterCore と UtterPersistence（共有結果の読み取り）のみに依存する。** UtterSpeech・UtterAI をリンクしない（iAC-08、メモリ制約）
- **DI の組み立て（Composition Root）は各アプリの起動部だけで行う。** 設定値に応じて本番実装と Stub を切り替える

## ユーザー辞書の編集と保存（TXT-03, AC-07）

辞書語と置換ルールの編集・検証は UtterText の `DictionaryEditor`、保存は UtterPersistence の `DictionaryStore` が持つ。
UtterText と UtterPersistence は互いに依存しないため、両者の値の変換と画面の状態は Apps/macOS の `DictionaryEditorModel` が持つ。

- **保存できた編集だけを画面に反映する。** 編集を `DictionaryEditor` で検証し、`DictionaryStore.replaceAll` で辞書全体を1つのトランザクションで置き換えてから画面の内容を進める。読み込み（`contents()` で辞書語とルールを同じ時点で読む）・保存の途中は次の読み込み・編集を受け付けず、保存した内容が画面から巻き戻らないようにする
- **検証:** 辞書語とパターンは前後の空白・改行を取り除き、空と重複（同じテキストに一致しうるパターンを含む）を拒否する。置換は長い一致を優先し、同じ長さで競合するルールは持てないため、定義順は置換結果に影響せず、並べ替えは扱わない
- **保存場所:** macOS は `~/Library/Application Support/utter/utter.sqlite`（`AppDatabaseLocation`）。DB の読み書きはメインスレッドの外で行う
- **辞書語はクラウド整形の文脈として送られる（CTX-03）。** 編集画面にその旨と、秘密情報を登録しないよう表示する。辞書語・ルールの値はログ・エラー文言に出さない
- 保存された内容から辞書を組み立てられない（ほかの経路で競合するルールが保存されたなど）ときは、読み込めない場合と分けて案内し、編集できない状態にして上書きしない（復旧手段は今後決める）

外部 API（Claude Messages API、ChatGPT Responses API、STT エンジン）は3点セットで実装する。

| 種類 | 配置 | 例 |
|---|---|---|
| protocol | 該当 Package の `Sources/` | `AIProvider`, `SpeechRecognizer` |

- Stub は固定応答に加え、遅延・タイムアウト・認証失効・予算超過などのエラーを注入できるようにする（AI-06 のテスト用）
- 本番実装は URLSession を DI で受け取り、テストでは通信しない（送信部は `HTTPTransport`。応答を受信しながら読むものは `HTTPStreamingTransport`）

### 推定費用の記録と表示（AI-04 / AI-05）

UtterAI と UtterPersistence は互いに依存しない（Packages 同士は UtterCore を介して連携する）。
推定費用の保存と復元の橋渡しは、アプリ（Composition Root）の責務とする。

- **記録：** `BudgetGuard` の初期化で渡す `onRecord` が、台帳に推定費用を記録するたびに `RecordedEstimatedCost`（推定費用と計上した月）を受け取る。
  アプリはこれを `MonthlyUsageStore.record(_:currencyCode:in:)` に加算する（`YearMonth` → `UsageMonth`、`CostCurrency.code` → 通貨コード）。
  送信後に呼び出し元がキャンセルして `refine` が結果を返さない場合も呼ばれるため、永続化はこの経路で行う。
  同じ値は `BudgetGuard.settle` の戻り値と `RefinementOutcome.recordedCost` にも入る（表示・通知用）。予約を取り消した場合・送信しなかった場合は記録しない
- **保存に失敗したら：** `onRecord` はエラーを投げる（`UsageMonth` に変換できない月を含む）。再起動後に累計を少なく数えうるため、
  `BudgetGuard` は `hasPersistenceFailure` になり、以降の予約をすべて拒否する（クラウド整形はローカルに退避する。安全側）。
  アプリは保存の失敗を利用者に知らせ、保存できる状態に戻してから台帳を復元し直した `BudgetGuard` を作る
- **復元：** 起動時は `MonthlyUsageStore.entries()` のうち予算と同じ通貨の行だけから `MonthlyUsageLedger(currency:spentByMonth:)` を作り、
  `BudgetGuard` に渡す。異なる通貨の累計は足さず、為替換算もしない
- **表示：** `BudgetGuard.estimatedCostSummary(in:)` が今月の推定累計・予約中・上限・推定の残り（負にしない）・単価表の更新日を返す。
  いずれも単価表から計算した推定値で、プロバイダーの請求額・API クレジット残高と混同しない表示にする。画面は Apps が作る

## iOS の録音割り込み（iOS-PERF-03）

録音中の画面ロック・電話着信・オーディオ割り込み・低電力モード・熱状態変化への対応は、UtterCore の
`RecordingInterruptionPolicy`（判定）と `SessionStateMachine.handleInterruption(_:capturedAudioDuration:policy:)`（遷移）が持つ。
OS の通知は Apps/iOS のアダプター（`RecordingSignalObserver`）が `RecordingSystemSignal`（Apps/iOS/UtteriOSKit）に写し、
`RecordingSystemSignal.recordingInterruption` で `RecordingInterruption` に変換して `RecordingSessionModel` に渡す。UtterCore は OS の型に依存しない。

| OS の通知（Apps/iOS で受ける） | `RecordingInterruption` | 既定の対応 |
|---|---|---|
| `AVAudioSession.interruptionNotification`（`.began`） | `.audioInterruptionBegan` | 録音を止めて処理する |
| `AVAudioSession.interruptionNotification`（`.ended`） | `.audioInterruptionEnded` | 何もしない（自動で再開しない） |
| `AVAudioSession.routeChangeNotification`（`.oldDeviceUnavailable`） | `.audioRouteChanged(.inputDeviceLost)` | 録音を止めて処理する（設定で継続も可） |
| 同（`.newDeviceAvailable` / それ以外） | `.audioRouteChanged(.inputDeviceAdded / .other)` | 継続する |
| `AVAudioSession.mediaServicesWereResetNotification` | `.mediaServicesReset` | 録音を止めて処理する |
| `UIApplication.willResignActiveNotification` | `.appWillResignActive` | 継続する（マイクを奪われたら割り込み開始が別に届く） |
| `UIApplication.didEnterBackgroundNotification`（画面ロックを含む） | `.appDidEnterBackground` | 録音を止めて処理する |
| `ProcessInfo.thermalStateDidChangeNotification` | `.thermalStateChanged(_:)` | `critical` 以上で録音を止めて処理する（閾値は設定可） |
| `NSProcessInfoPowerStateDidChange` | `.lowPowerModeChanged(isEnabled:)` | 継続する（設定で停止も可） |

- **音声を破棄しない（REC-05）。** 録音を止めるときは、取得済みの音声を通常どおり認識へ渡す（`stopReason` は `.interrupted(原因)`）。
  取得済みの音声が下限（既定 0）以下で処理できないときだけ `error(.recording)` にして失敗を表示し、無言で終わらせない
- **割り込み後に録音を自動で再開しない。** 着信の後などに利用者の意図しない録音を始めないため、再開は利用者の操作で新しいセッションとして行う
- **常時録音のための Background Modes（`audio`）は使わない（iOS-PERF-02, iOS-PERF-03）。** バックグラウンドへ移ったら録音を止め、
  バックグラウンド実行の制限を迂回しない。止めた後の認識をいつ実行するか（前面に戻ってから実行する、音声を一時保存して後で処理するなど）と、
  熱状態が高いときに STT を遅らせるかは Phase i1 の iOS 録音・STT 実装で決める
- **macOS 専用の値は iOS では使わない。** `.systemWillSleep / .systemDidWake`、`.audioRouteChanged(.inputDeviceChanged)`、
  `.microphoneAccessRevoked` は Apps/iOS からは渡さない（iOS では設定でマイク権限を取り消すとアプリが終了するため、取り消しは次回起動時の権限確認で扱う）
- 既定値（熱状態の閾値 `critical`、低電力モードで止めない、入力機器の喪失で止める、音声の下限 0）は **Phase i0 の実機検証前の仮定**で、
  検証結果に応じて見直す
- **経路の変更で止まった録音エンジンは作り直して続ける。** `AVAudioEngineConfigurationChange`（ヘッドセットの抜き差しなど）でエンジンが止まったら、
  `AudioEngineRecorder` が新しい入力の形式でエンジンを作り直す。録音を始めたときの入力ポートが消えていたら作り直さない
  （経路の変更の通知より先に届くと、内蔵マイクに切り替わって周囲の音を録るため）。作り直さない・作り直せないときは、録音エンジンを
  作り直す必要がある点で同じ `.mediaServicesReset` として扱い、取得済みの音声を処理する。録音を止めるかどうかは、別に届く経路の変更の通知とポリシーが決める
- `AVAudioSession.RouteChangeReason.noSuitableRouteForCategory`（使える入力がない）も `.audioRouteChanged(.inputDeviceLost)` に写す
- 録音中は画面の自動ロックを止める（`isIdleTimerDisabled`）。話している間に自動ロックで録音が止まらないようにするためで、録音していないときは元に戻す
- オーディオセッションは録音カテゴリ（`.record`）で、録音中だけ有効にする。止めたら `notifyOthersOnDeactivation` で無効にする（iOS-PERF-02）

## iOS 本体アプリの録音と共有結果（iOS-04, iOS-07）

`RecordingSessionModel`（Apps/iOS/UtteriOSKit）が、`SessionStateMachine` に沿って録音 → 認識 → 整形 → 共有結果の保存を進める。
iOS では状態機械の `inserting` を「共有結果の保存」に使う（挿入はキーボード拡張が行う）。

| 段階 | 実装 | 既定 |
|---|---|---|
| 録音 | `UtteriOSKit.AudioRecorder`（UtterSpeech の macOS 用 `AudioRecorder` とは別。`AudioEngineRecorder`: AVAudioSession + AVAudioEngine。16kHz モノラルの `AudioChunk` にして `BoundedAudioStream` へ流す） | 音声はファイル・ログに出さない |
| 認識 | `SpeechRecognizer` を注入（`SpeechEngineSelection` で選ぶ） | iOS の STT エンジンは #54 の判定待ちのため `UnconfiguredSpeechRecognizer`（録音は続け、止めた後に「未設定」として失敗を返す）。`Config/Local.xcconfig` の `UTTER_IOS_STT_ENGINE = speechAnalyzer`（Debug は起動引数 `-UtterSpeechEngine speechAnalyzer` でも可）のときだけ `SpeechAnalyzerRecognizer`。Debug ビルドだけ、起動引数 `-UtterStubSpeechRecognizer YES` で `StubSpeechRecognizer` に切り替えられる（最優先） |
| 整形 | `LocalRefiner` と `CloudRefinement` を注入 | Local Basic（Natural、スタイルは `standard`）。同意・API キー・予算がそろったときだけ Claude で整形する（下記「iOS のクラウド整形」） |
| 保存 | `SharedResultStore`（`SharedResultStorage.resolve` で保存先を選ぶ） | 下記 |

- **App Group は設定したときだけ使う（#56 の判定待ち）。** `Config/Local.xcconfig` で `UTTER_APP_GROUP_ENABLED = YES` と `UTTER_APP_GROUP_ID` を設定したときだけ、
  ID を Info.plist の `UtterAppGroupIdentifier` に埋め込み、`UtteriOS-AppGroup.entitlements` の Entitlement を付ける（キーボード拡張と同じ設定キー）。
  ID が未設定、またはコンテナを開けなければ、アプリ内（Application Support/SharedResults、バックアップ対象外）にだけ保存し、キーボードとは共有しない。
  どちらの保存先かは救済画面に表示する
- **発話を失わない。** 保存に失敗したら本文を画面に残し、その場でコピーできるようにする（次の録音を始めるまで）。認識結果が空なら保存しない
- **救済導線（iOS-07）。** 本体アプリの画面に保存済みの結果を一覧し、`SharedResultRescueCoordinator` でコピーする。起動時と前面に戻ったときに
  `SharedResultStore.cleanUp(at:)` で期限切れ・挿入済みの結果を削除し、中断された挿入を復旧してから読み直す（iOS-IPC-05 / iOS-IPC-06）。
  クリップボードへは他の端末へ同期せず（`localOnly`）、10分の期限つきで置く
- **SpeechAnalyzer は選んだときだけ使う（#54 の判定待ち）。** 選ぶと、設定画面（`SpeechSettingsView`）にモデルの取得状態を出し、
  「モデルを取得」ボタンを押したときだけ `SpeechAnalyzerAssets.install()` を呼ぶ（PERM-03。画面を開いても状態を確かめるだけ）。
  モデルが未取得なら認識は `failed(.modelUnavailable)` で終わり、録音の結果として「未設定かモデル未取得」を表示する。
  音声認識の権限（`SFSpeechRecognizer`）は、SpeechAnalyzer を選んだときだけマイクの許可の後に求める（要るかは未確認。拒否されても録音は続ける, PERM-01）
- **本体アプリの状態をキーボードに伝える（iAC-07）。** `HostAppStatusPublisher` が、拒否された権限（マイク。音声認識は SpeechAnalyzer を選んだときだけ）・
  STT モデルの取得状況（`SpeechAnalyzerAssets` が取得済みなら `ready`、未取得・取得中は `notDownloaded`、端末で使えない・STT 未設定は取得しても解決しないため `notApplicable` でモデルの案内を出さない）・
  整形の処理系にクラウド AI を選んでいるか・観測時刻を `HostAppStatusStore` に書く。書くのは起動時と前面に来たとき、録音の開始（権限の要求）の後、
  モデルの取得状態が変わったとき。前の書き込みが終わってから観測し、古い状態で上書きしない。権限は読むだけで求めない（`SystemHostAppPermissionReader`）。
  App Group を設定し、コンテナを開けたときだけ書く（未設定なら作らない, #56）。秘密情報・本文・音声は書かない（iOS-IPC-04, iAC-08）
- **バックグラウンドへ移った後の認識。** 録音は止めるが、認識・保存はバックグラウンド実行を延ばさずにそのまま続け、OS に中断されたら前面に戻ってから続きを処理する

### iOS のクラウド整形（iOS-10）

`CloudRefinement`（Apps/iOS/UtteriOSKit）が整形のたびに次の順で確かめ、欠けていれば送信せずに Local Basic だけを使う。
macOS と同じ `RefinementRouter` / `ClaudeProvider(apiKeyStore:)` / 同意の画面の状態（`ConsentScreenState`）を使う。

| 順 | 確かめること | 欠けたとき |
|---|---|---|
| 1 | `AppSettingsStore`（`UserDefaults.standard`。App Group ではない）の最新の設定で、整形の処理系（`refinementEngine`）にクラウド AI を選んでいる（AI-03。既定は Local Basic） | Local Basic。通知しない |
| 2 | Claude への整形の送信に同意している（AC-06） | Local Basic。通知しない |
| 3 | API キーが本体アプリの Keychain にあり、読み出せる（AC-12） | Local Basic。未設定・読み出せないことを画面に通知する |
| 4 | 予算上限を確かめられる（`UsageStoreBudgetSource`: 月次予算・単価表〈通貨・更新日・モデルの単価〉・保存済みの今月の累計, AI-04） | Local Basic。理由（未設定・通貨の不一致・単価表にないモデル・累計を読み書きできない・前の整形の記録中）を通知する |

- 機密入力の判定（7章, AC-12）は、本体アプリが自分の画面で録音・整形するため `CloudRefinement.ownAppSensitivity()` で
  `SensitiveInputPolicy().decide(SensitiveInputContext(secureField: .off, secureEventInput: .off, app: 自アプリの bundle ID))` として作り、
  `RefinementRouter.refine` に渡す（bundle ID を取れなければ判定不能として送信しない。テストは `CloudRefinement` の `sensitivity` で差し替える）
- そろえば `RefinementRouter` で1回だけ送信する。送信の直前に処理系の選択と同意をもう一度読み、変更をすぐに反映する。失敗・検証失敗・上限時間の超過・予算超過は
  Local Basic の結果に退避し、理由を画面に通知する（4.1節, AI-06）。待つ間にキャンセルしたセッションの結果は保存しない
- **推定費用の記録（AI-05）。** 整形ごとに `BudgetGuard` を作り、月次予算から `MonthlyUsageStore` に保存した今月の累計を引いた残りを上限にする。
  送信後（キャンセルされた場合も）に記録された推定費用を `MonthlyUsageStore` に加算する。送信中にアプリが終了しても少なく数えないよう、
  送信前に見込み費用を未確定の予約としてファイル（Application Support/PendingCloudRefinementCost.json）に残し、記録を終えたら消す。
  次の整形の前に予約が残っていれば見込み費用で累計に加算する。保存に失敗したら、累計が実際より少ない可能性があるため、
  以降はアプリを起動し直すまでクラウド整形を使わない。予約のファイルが読めない場合は額がわからないため、ファイルを残し、起動し直しても使わない。前の整形の記録が終わる前の次の整形も送信しない。データベースは Application Support（App Group ではない）に置き、最初のクラウド整形のときに開く
- **整形と予算の画面（AI-03, AI-04, AI-05）。** 処理系（Local Basic / Claude）・整形用モデル名・月次予算・通貨・単価表（更新日・モデルごとの単価）を
  `RefinementSettingsModel` が `CloudRefinement` と同じ `AppSettingsStore` の版 2 の項目（`refinementEngine` / `refinementModel` / `monthlyBudget` / `priceTable`）に書く。
  入力の検証は macOS の `SettingsForm` と同じ規則（金額は半角の 0 以上の数だけ。負・桁区切り・全角は保存しない。予算と単価表は同じ通貨。単価があれば更新日は必須）で、
  問題があれば何も保存しない。保存の基準には保存先の最新の値を使い、同意状態などほかの画面の項目を残す。画面は設定値を書くだけで送信しない（送信は上の順で同意を確かめてから, AC-06）。
  今月の推定費用は、保存済みの予算・単価表と、予算の通貨の今月の累計（`MonthlyUsageStore.spent(in:currencyCode:)`。予算の判定と同じ値）から `EstimatedCostSummary` で作り、
  予算・単価表の通貨・更新日がそろわなければ表示しない（0 で補わない）。送信中の未確定の予約は含めない
- 設定の入口は録音画面の「設定」（`SettingsView`）。音声認識の設定（`SpeechSettingsView`）・整形と予算の画面（`RefinementSettingsView`）・同意の画面（`ConsentSettingsView`）・API キーの画面（`ClaudeAPIKeySettingsView`）へ移る。いずれも Apps/iOS/Sources が持つ。設定を閉じたら本体アプリの状態（処理系の選択を含む, iAC-07）を書き直す

## macOS の録音割り込み（REC-04）

macOS の録音中のスリープ・入力機器の切断・既定の入力機器の変更・マイク権限の取り消しも、iOS と同じ
`RecordingInterruptionPolicy` と `SessionStateMachine.handleInterruption(_:capturedAudioDuration:policy:)` で扱う。
OS の通知の取得と `RecordingInterruption` への変換は Apps/macOS のアダプターの責務で、UtterCore は OS の型に依存しない。

| OS の通知（Apps/macOS で受ける） | `RecordingInterruption` | 既定の対応 |
|---|---|---|
| `NSWorkspace.willSleepNotification` | `.systemWillSleep` | 録音を止めて処理する |
| `NSWorkspace.didWakeNotification` | `.systemDidWake` | 何もしない（自動で再開しない） |
| 録音中の入力機器の消失（Core Audio の `kAudioDevicePropertyDeviceIsAlive` が偽になる等） | `.audioRouteChanged(.inputDeviceLost)` | 録音を止めて処理する |
| 既定の入力機器で録音している間の、既定の入力機器の変更（`kAudioHardwarePropertyDefaultInputDevice` / `AVAudioEngineConfigurationChange` で機器が変わった） | `.audioRouteChanged(.inputDeviceChanged)` | 録音を止めて処理する（設定によらない） |
| 録音中のマイク権限の取り消しの検出（`AVCaptureDevice.authorizationStatus(for: .audio)` が `.authorized` でなくなった等） | `.microphoneAccessRevoked` | 録音を止めて処理する |

- **iOS と同じ原則に従う。** 音声があれば止めて通常どおり処理し（REC-05、`stopReason` は `.interrupted(原因)`）、
  なければ `error(.recording)` で失敗を表示する。HUD は既存の `HUDNotice.recordingInterrupted(原因)` で理由を示し、
  通知の追加や HUD の構造の変更はしない。復帰・権限の再付与・機器の再接続で録音を自動で再開せず、再開は利用者の操作で新しいセッションとして行う
- **入力機器の消失・既定の入力機器の変更は止める。** 利用者が選んでいない機器（会議用マイク・別の部屋の機器など）で録り続けないため。
  macOS では機器が変わると録音エンジンを新しい機器で作り直す必要があり、続けると利用者の操作なしの再開になるため、
  `inputDeviceChanged` に続ける設定は設けない。`stopsOnInputDeviceLoss` は iOS 向けの設定で、Apps/macOS は既定値（止める）を使う。
  消失に続いて既定の機器の変更が届いた場合は、先に届いた方で止まり、後の通知は録音中でないため無視される。
  将来、特定の機器を指定して録音できるようにした場合は、既定の機器の変更を `inputDeviceChanged` に変換しない
- **iOS の機器の追加（継続）との違い。** iOS の `.newDeviceAvailable` は利用者がヘッドセットなどを手元で接続した結果で、
  経路の切り替えを OS が録音を止めずに行う。macOS の既定の入力機器は他アプリやシステム設定からも変わり、録音エンジンが止まる。
  iOS 側の扱いも Phase i0 前の仮定で、実機検証で見直す
- **マイク権限の取り消しは、取り消し前に取得した音声だけを処理する。** 取り消し後に無音のバッファが届く場合でも、
  `capturedAudioDuration` には取り消しを検出するまでの音声の長さを渡す。止めた後は権限がないため次の録音を開始せず、
  再設定を案内する（PERM-02。開始前の権限確認は Apps/macOS の権限オンボーディング）
- **止めた後の処理と挿入先（Phase 1 で決める）。** スリープで止めた場合、認識・整形・挿入がスリープ前に終わらず復帰後に進むことがある。
  復帰後は挿入先が変わっている（ロック画面・別のアプリ・フォーカスの移動）おそれがあるが、挿入直前の挿入先の再検証と
  プレビューへの退避（INS-01 / AC-09）で扱う。スリープをまたいだ場合もこれで足りるかは Phase 1 の挿入実装で確認する
- **iOS 専用の値は macOS では使わない。** `.audioInterruptionBegan / Ended`、`.mediaServicesReset`、`.appWillResignActive`、
  `.appDidEnterBackground` は AVAudioSession と UIApplication の通知に対応する値で、Apps/macOS からは渡さない
- **スリープ・入力機器の変更の後は `ShortcutInterpreter.reset()` を呼ぶ。** Push-to-talk の押下中にスリープすると解放が届かないため、押下状態を破棄する
- **連打（REC-04, REC-06）は割り込みではなく状態機械とショートカットの判定で扱う。** キーリピートは操作にせず、
  処理中の開始操作は無視し、同時に1セッションのみとする（`SessionStateMachine.start(at:)` / `ShortcutInterpreter`）。
  開始直後の停止でごく短い録音になった場合も手動停止として認識へ進め、空の認識結果の扱いは Phase 1 の STT・挿入の実装で決める
- 同じ機器の形式（サンプルレート等）だけが変わった場合の扱い、スリープ・権限の取り消しで録音エンジンから実際にどの通知・エラーが届くか、
  録音中にマイク権限を取り消したときにプロセスが終了させられないか（終了する場合は `.microphoneAccessRevoked` は届かず、取り消し前の音声も残らない）は、
  **Phase 0 / Phase 1 の録音実装で実機確認する**。確認結果で対応表を更新する

## macOS の録音（AVAudioEngine, REC-04 / REC-05）

マイクからの録音は、UtterSpeech の `AudioRecorder` protocol を Apps/macOS の `AVAudioEngineRecorder`（actor）が実装する。
AVFoundation・AppKit（スリープの通知）を使うためアダプターは Apps/macOS に置き、OS に依存しない部分
（モノラル化 `AudioDownmix`、100ms ごとのチャンク分割 `AudioChunker`、上限と終わりの通知 `AudioRecordingPipeline`、
使用許可の判定 `MicrophoneAccess.ensureAccess()`）は UtterSpeech に置いてテストする。テストは `StubAudioRecorder` を使う。

1. 録音を始めるたびにマイクの使用許可を確かめる。未確認なら要求し（初めて録音するとき, PERM-01）、拒否・制限なら録音しない
2. 入力ノードにタップを付け、コールバック（オーディオのスレッド）でチャンネルを平均してモノラルにし、
   `AVAudioConverter` で 16kHz に変換して `AudioRecordingPipeline` に渡す。コールバックはアクターに隔離しない
3. `AudioRecordingPipeline` が 100ms ごとのチャンクにして `BoundedAudioStream` で流す。上限（既定5分）に達したら
   収まる分まで流して `.limitReached` で終え、エンジンを止める（REC-05）
4. 録音の終わりは理由によらず `AudioRecording.ends` に1回だけ流す。割り込みで止まったときは
   `.interrupted(RecordingInterruption)` と、それまでの音声の長さを `SessionStateMachine.handleInterruption(_:capturedAudioDuration:policy:)` に渡す

| OS の通知（Apps/macOS で受ける） | `RecordingInterruption`（`MacRecordingInterruptions`） | HUD の理由 |
|---|---|---|
| `AVAudioEngineConfigurationChange`（入力機器の切断・既定の入力機器の変更・形式の変更。エンジンは止まっている） | `.audioRouteChanged(.inputDeviceChanged)`（機器の切断と区別できないため、既定の入力機器の変更に寄せる） | 入力機器が切り替わった |
| `NSWorkspace.willSleepNotification` | `.systemWillSleep` | Mac がスリープした |

- どちらも録音を止めて、それまでの音声を処理する（既定の `RecordingInterruptionPolicy`）。自動で再開しない
- `AVAudioEngineConfigurationChange` は出力側の変更（ヘッドホンの接続など）や、Bluetooth ヘッドセットで入力を開いたときの
  形式の切り替えでも届くことがある。いまは一律に止める（安全側）。実機で頻度を確かめ、入力の形式・機器が開始時と同じなら
  開始し直すかを決める
- 停止時と通知で止めるときは、タップを外してエンジンを止めてから、変換器に残ったサンプルも流して終える
- 受け手が音声のストリームを読むのをやめたら、次のチャンクを待たずに `.cancelled` で終えてエンジンを止める
- **連打（REC-04）:** 録音中や使用許可を待っている間の `start` は `.alreadyRecording` を投げ、2つ目の録音を始めない。
  許可を待つ間に `stop()` が呼ばれたら、許可されても録音を始めない（`.cancelled`）。`stop()` は何度呼んでもよい
- **音声を外に出さない:** 音声はメモリ上で流すだけで、ファイル・ログには出さない。一時音声の保存は `TemporaryAudioStore` の責務
- 録音中のマイク権限の取り消し（PERM-02）の検出、特定の入力機器を選んで録音すること、App Sandbox・Hardened Runtime の
  Entitlement（`com.apple.security.device.audio-input`。公証する Phase 3 で必要になる）は、この実装の範囲外

## STT Worker（4章, 7章, AC-10, AC-11）

macOS では STT を XPC Service（`Workers/macOSSTT`、ターゲット `UtterSTTWorker`）に分離し、Worker の異常終了でメインアプリを止めない。
メッセージと処理は UtterSpeech に置き、XPC には依存させない。XPC の接続（`XPCSession` / `XPCListener`）だけを各ターゲットに置く。

| 役割 | 型 | 置き場所 |
|---|---|---|
| メッセージ（Codable） | `STTWorkerRequest`（`start` / `audio` / `finishAudio` / `cancel` / `updateResources`）、`STTWorkerResponse`（`event`） | UtterSpeech |
| Worker 内の処理 | `STTWorkerService`（エンジンごとの `SpeechModelLoader` を受け取り、ロード・推論・解放） | UtterSpeech |
| アプリ側のアダプター | `STTWorkerSpeechRecognizer`（`SpeechRecognizer` に準拠。`STTWorkerConnection` 越しに送受信） | UtterSpeech |
| 接続 | 本番 `XPCSTTWorkerConnection`、テスト `StubSTTWorkerConnection`（プロセス内で `STTWorkerService` を動かす） | Apps/macOS / UtterSpeech |
| Worker の起動部・エンジンの登録 | `main.swift`（`XPCListener`）、`STTWorkerPeer`、`STTWorkerEngines` | Workers/macOSSTT |
| 端末の状態の変換・送信 | `DeviceResourceObservation`（`DeviceResourceSignal` を適用して `DeviceResourceState` にする）、`STTWorkerResourceForwarder`（変わったときだけ `STTWorkerResourceReceiving` へ送る） | UtterSpeech |
| 端末の状態の監視 | `SystemDeviceResourceMonitor`（OS の通知）、`DeviceResourceMonitoring`（監視と送信の結線。`AppComposition` が STT Worker の認識器を作ったときに、起動から終了まで動かす） | Apps/macOS |

- **エンジンの既定値を持たない。** どれを使うかは Phase 0 の判定（11章）で決める。未選択（`engine == nil`）なら Worker を起動せず `failed(.modelUnavailable)` にする。
  使うエンジンは `AppComposition.selectedEngine()` がビルド設定 `UTTER_MAC_STT_ENGINE`（Info.plist の `UtterSTTEngine`。`Config/Base.xcconfig` では空）から選ぶ。
  判定は `STTEngineSetting`（Apps/macOS `Sources/Settings`、`UtterMacTests` でテスト）で、受け付けるのは Worker に登録したエンジンのうち `speechAnalyzer` だけ。
  知らない値・空の値・WhisperKit（未登録）は未選択に倒す。Debug ビルドだけ起動引数 `-UtterDebugSTTEngine` がビルド設定より優先し、`stub` も選べる。
  Worker に登録のないエンジンも `failed(.modelUnavailable)` にする。実エンジン（SpeechAnalyzer / WhisperKit）は `SpeechModelLoader` に準拠させて `STTWorkerEngines` に登録する。
  開発用の `stub` エンジンは Debug ビルドだけに登録する
- **Worker は最初の認識で起動する。** 待機中には起動しない（6章）。同時に認識するのは1セッションまで（4章）
- **異常終了の検知と再処理（AC-10）。** 認識中に接続が interruption / invalidation で終わったら、そのセッションを `failed(.engineFailed)` で終え、
  `onTermination`（`STTWorkerTermination`）で知らせる。再処理は「一時音声と再処理」の手順4で、同じ `SessionID` のまま認識し直す。
  `onTermination` は失敗を流した後に届くため、受け手が失敗を受け取った時点では届いていないことがある。受け手が異常終了による失敗かを
  見分けるには `termination(of:)` を使う（失敗を流す前に記録するため、失敗を受け取った後に呼べば順序に依らず答えられる）
  待機中の終了（OS がアイドルの Worker を終了させた場合など）は数えない
- **再起動の回数制限。** 再起動は次の認識で接続を作り直して行う。認識中の異常終了・起動の失敗が `restartLimit`（既定 2 回、仮置き）を超えて続いたら Worker を起動せず、
  `resetRestartLimit()` まで `failed(.engineFailed)` にする。Worker が終端イベントを返したら回数を 0 に戻す
- **モデルの保持（6章, AC-11）。** 保持モードと端末の状態はアプリが `updateResources` で送り、接続し直したときも送り直す。
  保持モードは設定画面で保存した値（`ModelRetentionPolicy.fromSettings`）を起動時に読み、設定が変わったら `AppComposition` が送り直す。Worker は推論の後と状態の変化のたびに
  `ModelRetentionPolicy.retention(in:)` で解放・保持を決める。設定を受け取る前は推論後すぐに解放する。メモリ圧迫時は高負荷モデルをロードせず `failed(.resourceLimited)` にする。
  接続が切れたらモデルを解放する
- **端末の状態の監視（6章, AC-11）。** アプリは起動から終了まで、録音・認識の有無に関わらず次の OS の通知を受け、変化を `STTWorkerResourceForwarder` に渡す。
  タイマー・ポーリングは使わない（6章「待機中は不要なタイマー・ポーリングを停止」）
  - メモリ圧迫：`DispatchSource.makeMemoryPressureSource`（`normal` / `warning` / `critical`）。現在値を問い合わせる公開 API がないため、起動時は `normal` とする
  - 低電力モード：`ProcessInfo.isLowPowerModeEnabled` と `NSProcessInfoPowerStateDidChange`
  - 電源：notify(3) の `kIOPSNotifyPowerSource`・`kIOPSNotifyLowBattery` を受けて、`IOPSGetProvidingPowerSourceType` と `IOPSGetBatteryWarningLevel` を読み直す
  - 低バッテリーは「低電力モード」か「外部電源でなく、OS がバッテリー残量の警告を出している」とする。残量の閾値（%）はアプリで持たない
  - 送るのは判定に使う値（保持の設定と `DeviceResourceState`）が変わったときだけ。Worker が未起動なら `STTWorkerSpeechRecognizer` が最後の値を持ち、接続時に送る
- **メッセージに秘密情報を載せない。** 送るのは音声・認識イベント・保持の設定と端末の状態だけ。音声と認識テキストはログに出さず、文字列表現にも出さない
- 音声のサンプルは Float32 のビット列で送る。チャンクのまとめ方（4章「バッチ化」）と共有メモリの要否は、Phase 0 の実測で決める

## API キーの保存（AC-12）

Claude API キーは利用者が設定画面で入力し、各アプリの Keychain に保存する。開発者の共通キーは配布しない（1章）。

| 部分 | 配置 | 内容 |
|---|---|---|
| 入力の検証 | UtterAI `APIKey` | 前後の空白・改行を取り除く。空の入力と、制御文字（前後を含む）・途中の空白・ASCII 以外を含む入力を拒否する。接頭辞などの形式は確かめない。文字列表現では伏せる |
| 保存先の protocol | UtterAI `APIKeyStore`（Stub: `StubAPIKeyStore`） | `load` / `save` / `delete`。1インスタンスが1つのキーを扱う |
| 設定画面の状態 | UtterAI `APIKeySettingsModel` | 保存済みかは `load()` で確かめ、読めない値は「確認できない」と示す。値は画面に出さない。保存に成功したら入力を消す |
| Keychain 実装 | Apps/macOS `KeychainAPIKeyStore` | data protection keychain、`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`、`kSecAttrSynchronizable = false`。Entitlement は `keychain-access-groups`（自アプリのグループのみ） |
| Keychain 実装（iOS） | Apps/iOS `KeychainAPIKeyStore` | `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`、`kSecAttrSynchronizable = false`。アクセスグループを指定せず、`keychain-access-groups` も持たないため本体アプリ自身のグループに入る（App Group に入らず、キーボード拡張から読めない, iAC-08） |
| 画面 | Apps/macOS `APIKeySettingsView`（設定画面の「API キー」タブ。Claude と OpenAI〈クラウド STT〉のキーを別の項目で持つ）、Apps/iOS `ClaudeAPIKeySettingsView`（録音画面の「設定」） | `SecureField` で入力し、保存済みのキーは再表示しない |

- `ClaudeProvider(apiKeyStore:)` は整形のたびにキーを読み出す。未設定・読み出せないときは送信せず `authenticationExpired` を投げる
- data protection keychain と `keychain-access-groups` は署名とプロビジョニングプロファイルに紐づく。署名なしのビルドでは保存できない（`errSecMissingEntitlement`）。旧来の keychain へは切り替えない。署名の条件は [ビルド・配布規約.md](ビルド・配布規約.md)
- App Group・UserDefaults・UtterPersistence にキーを置かない（iOS-IPC-04）。iOS は本体アプリの Keychain で別に管理し、macOS と共有しない（13章）

## 一時音声と再処理（7章, AC-10）

STT Worker の異常終了やアプリの異常終了で発話を失わないよう、録音した音声を一時保存して認識をやり直せるようにする。
STT Worker の異常終了ではメモリ上の録音全体を、アプリの異常終了では最後に保存した時点までの音声を戻せる。
保存形式は UtterSpeech の `RecordedAudio`（PCM16 モノラル、先頭に識別子・版・サンプリング周波数）、
保存先と保持期限は UtterPersistence の `TemporaryAudioStore` が持つ。UtterPersistence は形式に依存せず、バイト列だけを扱う。

1. 録音中のチャンクを `RecordedAudio.append(_:)` で溜める
2. 必要なとき（認識へ渡す前など）に `encoded()` を `TemporaryAudioStore.save(_:for:)` で保存する
3. 認識・整形・挿入が正常に終わったら `TemporaryAudioStore.remove(_:)` で削除する
4. STT Worker が異常終了しても、メインアプリのメモリには `RecordedAudio` が残っている。それを
   `SpeechRecognizer.recognizeAgain(_:session:)` に渡して認識をやり直す（ディスクから読み直さない）。
   一時音声と状態機械が同じセッションを指すよう `SessionID` は使い回し、順序番号は 0 から始まり直すため、
   `recognizeAgain` は同じ `SessionID` で `RecognitionEventFilter.begin(_:)` を呼んだフィルターでイベントを受け付ける。
   HUD などへ途中経過を流す受け手が別にフィルターを持つ場合は、そちらも同じ `SessionID` で `begin(_:)` を呼ぶ
5. アプリ自体が異常終了した後の起動時は、`sweep()` で保持期限（暫定24時間）を過ぎたものを削除し、残り（`recoverable`）の
   復旧を利用者に確認する。`save` は古い音声を消せなくても成功扱いのため、同じセッションの音声が複数残ることがある。
   `recoverable` はセッションごとにまとめ、作成時刻が新しい順に `load(_:)` → `RecordedAudio(decoding:)` を試し、
   最初に戻せたものを使う。戻せない（`unsupportedFormat` / `corrupted`）ものは飛ばして次に古いものを試し、
   復旧を終えた場合と、すべて戻せなかった場合に `remove(_:)` でそのセッションをまとめて削除する。
   この手順は `TemporaryAudioRecovery` にある。`candidates()` が整理とセッションごとのまとめを、
   `recover(_:decode:process:)` が新しい順の復元・認識のやり直し・削除を行う。`decode` に `RecordedAudio(decoding:)`、
   `process` に `recognizeAgain(_:session:)`（`completed` 以外は投げる）を渡すのは Apps の Composition Root。
   `process` が失敗・キャンセルした場合はやり直せるよう音声を残し、保持期限で削除する。端末のロック中（ファイル保護）
   などで読み込めない音声があれば、古い音声で復旧すると新しい音声ごと削除してしまうため、それより古いものは試さず、
   戻せないと決めずに音声を残す（`unreadable`）。
   確認を待つ間に保持期限を過ぎた音声は試さず、復旧を終えたときにセッションごと削除する。認識後に削除できなかった場合は結果（`removed: false`）で知らせ、
   次回の起動時に同じ発話を再び復旧しないよう、呼び出し側が削除をやり直す

- 保存する頻度（録音の停止時だけか、録音中も定期的に保存するか）と、復旧の確認画面は Apps/macOS・Apps/iOS で決める。
  録音中に一度も保存しないうちにアプリが異常終了した場合、その録音は戻せない。停止時だけ保存するなら、戻せるのは
  停止後（認識・整形・挿入の途中）の異常終了に限られる。
  保存は毎回録音全体を書き直すため、録音中に定期的に保存すると書き込み量は録音時間と保存回数の積で増える

### macOS の結線（Apps/macOS `Sources/Recovery/`）

- **保存先：** `~/Library/Application Support/<Bundle ID>/TemporaryAudio`（App Group には置かない）。ディレクトリ 0700・ファイル 0600
  （`TemporaryAudioStore`）で、バックアップから除外する。ディスク上の暗号化は FileVault に任せる。
  保存・削除・起動時の整理は `TemporaryAudioStoreQueue` で頼んだ順に1つずつ、メインスレッドの外で行う
- **保存と削除（`TemporaryAudioRetention`）：** 録音中のチャンクをメモリ上の `RecordedAudio` に溜め、録音が止まったら1回だけ保存する
  （録音中は保存しない。上の制約のとおり、録音中のアプリの異常終了は戻せない）。セッションが終わったら成功・キャンセル・失敗のいずれでも
  メモリ上の音声を手放して削除する。途中でサンプリング周波数が変わった録音は、再処理にも保存にも使わない
- **STT Worker の異常終了（`SessionCoordinator`）：** 認識が失敗したら `SessionRecognitionRecovering`（本番 `STTWorkerRecognitionRecovery`。
  `termination(of:)` で異常終了かつ再起動の回数制限の範囲内のときだけ）に尋ね、やり直すなら HUD は認識中のまま、録音が止まるのを待って
  （録音中の異常終了でも録音は止めない）メモリ上の録音全体を `recognizeAgain` に渡す。やり直しはセッションごとに1回まで。
  起動の失敗・回数制限・Worker が報告したエンジンの失敗はやり直さない（同じ音声で同じ失敗を繰り返すため）。
  やり直せる構成では、認識がストリームを手放しても録音のチャンクを読み続ける（録音は調停役が停止・キャンセル・失敗で止める）
- **起動時の復旧（`LaunchAudioRecovery`）：** `AppComposition` の初期化で、キューの先頭に `TemporaryAudioRecovery.candidates()` を積む
  （起動後に録音したセッションを候補に含めない）。候補があれば、セッションが待機中になるのを待って新しいセッションの開始を止め
  （`SessionCoordinator.suspendIfIdle()`。STT Worker は同時に1セッションしか認識しないため、復旧中に録音すると `resourceLimited` で発話を失う。
  録音中に前面を奪わないためでもある）、件数だけを出すダイアログ（`AudioRecoveryAlert`）で尋ね、
  断ったら候補の音声をすべて削除する。復旧を選んだら候補ごとに認識し直し、ローカルで整形（スタイル区分は既定）してコピーできるプレビュー
  （`InsertionPreviewCause.recoveredAfterRestart`）に出す。元の入力欄は変わっている可能性が高いため、自動では挿入しない。
  認識し直せなかった音声は残して件数を知らせ、次回の起動時にもう一度尋ねる。音声認識が使えない（エンジン未選択）なら尋ねず、保持期限に任せる。
  読み込み・認識し直し・削除はキューの中で行い（その間、ほかのストアの操作は待つ）、終えたら開始の停止を解く

## iOS キーボードの利用可否と案内（iOS-09, iAC-06, iAC-07）

キーボード拡張が提示する操作と案内は、UtterCore の `KeyboardAvailability` が `KeyboardEnvironment`（拡張が観測した状態）から決める。
拡張は OS の値を OS 非依存の値に変換して渡すだけにし、判定を持たない。

| 観測する状態（Extensions/iOSKeyboard で取る） | `KeyboardEnvironment` |
|---|---|
| `textDocumentProxy.isSecureTextEntry` | `inputField.secureTextEntry`（取れなければ `unknown`） |
| `textDocumentProxy.keyboardType` が `phonePad` / `namePhonePad` | `inputField.phoneNumber`（取れなければ `unknown`） |
| `hasFullAccess` | `hasFullAccess` |
| App Group を設定したビルドか、共有コンテナを読めるか | `sharedContainer`（`.notConfigured` / `.unavailable` / `.available(hostApp:)`） |
| 本体アプリが共有コンテナに残した権限・STT モデル・整形設定と観測時刻（`HostAppStatusStore`） | `.available(hostApp:)` の `HostAppStatus`（なければ `nil`） |
| 拡張で観測したネットワーク（`NWPathMonitor`） | `network`（観測できなければ `unknown`。フルアクセスがなければ拡張はネットワークを使えずオフラインと区別できないため `unknown`） |

- **制約を回避しない（iOS-09, iAC-06）。** セキュア入力欄・電話番号欄・属性を判定できない欄では、通常の文字入力と地球儀キーだけを残し、
  共有結果の読み込み・挿入と本体アプリへの移動を提示しない。標準キーボードへの切り替えを案内する。
  キーボード禁止アプリでは OS が拡張を起動しないため、検出・回避する仕組みは作らない
- **共有結果を読めない原因を分けて案内する（iAC-07）。** フルアクセスが無効ならフルアクセスの許可、フルアクセスがあっても読めなければ
  App Group の Entitlement・署名の不備として入れ直しを案内する。フルアクセスが必須かは決め打ちせず、共有コンテナを読めたかで判定する
  （Phase i0 の検証結果に依存しないため）
- 権限拒否・STT モデル未取得は本体アプリの状態として、オフラインは拡張で観測した値として案内し、対処（設定での許可、
  ネットワーク接続、本体アプリでの取得）を添える。ネットワークは変わりやすく、本体アプリが残した値では古い案内が出るため、拡張側で観測する
- **App Group を設定していないビルドでは共有結果を読まない。** App Group（#56 の判定待ち）は既定で無効で、拡張は `.notConfigured` を渡し、
  フルアクセス・署名の案内ではなく「本体アプリでの共有が未設定」と案内する（設定方法は [ビルド・配布規約.md](ビルド・配布規約.md)）
- **古い本体アプリの状態で案内しない。** `HostAppStatus` は観測時刻を持ち、鮮度の上限（既定 1 時間、暫定）を超えたもの、
  観測時刻が現在より後のものは、状態がない場合と同じく案内に使わない。
  `HostAppStatus` は UtterPersistence の `HostAppStatusStore` で App Group に残し、本体アプリの `HostAppStatusPublisher`（Apps/iOS/UtteriOSKit）が書く（下記「iOS 本体アプリの録音と共有結果」）。
  本体アプリを開かないまま鮮度の上限を超えると、権限・モデルの案内は出ない

### キーボード拡張の構成（Extensions/iOSKeyboard）

`UIInputViewController`（`KeyboardViewController`）は OS の値の受け渡しと画面だけを持ち、判定は Packages に任せる。

| 処理 | 担当 |
|---|---|
| 提示する操作と案内 | UtterCore の `KeyboardAvailability`。入力欄の制限は共有コンテナを読む前に `KeyboardInputField.restrictions` で確かめ、制限があれば読まない。フルアクセスがなく結果も見つからなければ、空と読めないを区別できないため読めないものとして扱う |
| 待つ結果の選択 | UtterPersistence の `SharedResultInsertionCoordinator.latestSessionID()`。表示時に整理（`cleanUp`）してから、挿入済みと作成時刻が現在より後の結果を除く最も新しい結果を選ぶ。キーボードは本体アプリで録音したセッションを知らない（移動・復帰が手動になりうる）ため。挿入先は利用者がプレビューで確かめる（iOS-06） |
| プレビュー・明示的な挿入・二重挿入の防止 | `SharedResultInsertionCoordinator` の `preview(sessionID:)` / `insert(sessionID:confirmedReinsertion:)`。挿入の直前に入力欄を判定し直す |
| 結果ごとの操作と残り時間 | UtterPersistence の `SharedResultKeyboardPanel`（プレビューと表示する時刻から決める。表示中は 15 秒ごとに表示し直す）。挿入できる結果は「挿入」「消す」と「あと N 分」（分に切り上げ）。挿入を確認できない結果は「入っていた」「もう一度入れる」「消す」で、自動ではやり直さない（iOS-IPC-03）。表示中に期限を過ぎたら挿入・再挿入を出さない |
| 消す・入っていた | `SharedResultInsertionCoordinator` の `discard(sessionID:)` / `confirmInserted(sessionID:)`。結果を `consumed` にして比較交換で保存してから削除するため、本体アプリの救済画面でも挿入済みと同じく使えない（iOS-IPC-01〜03, iOS-IPC-05）。挿入中（猶予時間内）の結果は消さない。「入っていた」は挿入結果が不明な結果だけに使い、挿入はしない |
| フルアクセスの手順 | `KeyboardAvailability` がフルアクセスが無効で共有結果を読めないときだけ `fullAccessSteps` を提示し、「オンにする手順を見る」を押すと手順を表示する。設定アプリは開かない（キーボード拡張から開く公開 API がないため, iOS-03） |
| 挿入と確認 | 拡張の `TextDocumentProxyInserter`（`UITextDocumentProxy.insertText` だけ）。確保を待った後の挿入の直前にも入力欄の制限を確かめ、制限があれば挿入せず挿入結果不明にする。入ったかは挿入前後の `documentContextBeforeInput` を `SharedResultInsertionConfirmation(insertedText:contextBefore:contextAfter:)` で判定し、確認できなければ挿入結果不明にする（自動では再挿入しない）。文脈は判定にだけ使い、保存・記録しない |
| 通常の文字入力 | 拡張の `KeyboardKeysView`（英字と数字・記号の2面、削除・改行・地球儀キー, iOS-08）。日本語の変換は持たず、標準キーボードへの切り替えを案内する |
| 本体アプリへの移動 | 手動で切り替える案内を常に出す（iOS-03, iAC-05）。#53 の判定待ちで、`UTTER_HOST_APP_URL_SCHEME` を設定したときだけ公開 API の `NSExtensionContext.open(_:)` で自アプリのスキームを開き、開けなければ手動の案内に戻る |

- 拡張は UtterCore と UtterPersistence だけをリンクし、マイク録音・STT モデル・クラウド認証トークン・ネットワーク送信を持たない（iAC-08）。
  `scripts/verify.sh` がバイナリに UtterSpeech / UtterAI のシンボルがないことを確かめる
- `RequestsOpenAccess` は App Group を有効にしたビルドだけ true（共有結果の読み取りと挿入状態の書き込みに使う）。無効なら false

## 権限の段階的な要求と取り消し（PERM-01, PERM-02）

macOS 本体アプリの権限は、UtterCore の `PermissionRequirements`（機能ごとに要る権限と要求の順）と `FeatureAvailability`
（権限の状態から使える機能・案内・挿入経路を決める）が判定する。Apps/macOS は OS の権限の状態を `PermissionSnapshot` に変換して渡し、
要求ダイアログ・システム設定への案内・画面を受け持つ。UtterCore は OS の型に依存しない。

| 機能（`AppFeature`） | 要る権限 |
|---|---|
| `recording`（録音と音声認識） | マイク（固定）と、呼び出し側が渡す STT の権限（SpeechAnalyzer が音声認識の許可を要するか, #48） |
| `insertion(経路)` | 呼び出し側が経路ごとに渡す（#41）。渡していない経路は使わない |
| `modifierOnlyShortcut` / `escapeCancel` | 呼び出し側が渡す（入力監視・Accessibility の要否, #51） |

- **Phase 0 の結果を決め打ちしない。** マイク以外の要件は既定値を持たせず、Phase 0 の結果をデータとして渡す（`ShortcutCapabilities` と同じ方針）
- **使わない経路の権限は要求しない（PERM-01）。** 要求は利用者が有効にしている機能に要る権限だけを、マイク → 音声認識 → Accessibility → 入力監視の順に、
  用途（それを要する機能）つきで返す。許可済みの権限は含めない。拒否済みなら OS のダイアログを出し直せないため、システム設定での許可を案内し、
  MDM などで制限されている（`restricted`）なら利用者には変えられないことを示す
- **取り消されたら該当機能だけを無効にする（PERM-02）。** 足りない権限が要る機能だけを外し、ほかの機能は使えるままにする。
  前回観測した状態を渡すと、許可から外れた権限（`notDetermined` に戻った場合を含む）の案内を取り消しとして示す。
  権限の状態はアプリが前面に来たとき・録音を始める前などに取り直す（観測の契機は Apps/macOS で決める）
- 挿入は `FeatureAvailability.permittedRoutes` を `InsertionPolicy.plan` に渡す。経路がすべて外れてもコピー可能なプレビューへの退避は残る（INS-02）
- 録音はマイクと STT の権限がそろうときだけ始める（`canStartRecording`）。認識できない録音で発話を失わないため、音声認識を録音と別の機能に分けない
- 修飾キー単独のショートカットを割り当てられるかは環境の対応（`ShortcutCapabilities`）だけで判定する。割り当てた後に要る権限を要求し、
  権限がない間はその機能だけを無効にして案内する（権限がないことを割当の拒否にすると、権限を要求する段階に進めないため）
- iOS 本体アプリの権限は既存の `HostAppStatus` / `HostAppPermission`（iAC-07）で表し、この判定は macOS 本体アプリで使う

### オンボーディングの画面（Apps/macOS）

- 段階は UtterCore の `PermissionOnboarding` が決める。有効な機能に要る権限を要求の順に並べ（許可済みも進み具合として残す）、
  次に操作する段階（`currentStep`）は、許可されておらず利用者が変えられる最初の段階とする。制限されている権限は飛ばす。
  要る権限が分からない機能（判定待ちの挿入経路）は段階に出さず `undecidedFeatures` として「確認中」に示し、要求しない
- 取り消しは `PermissionHistory`（一度でも許可を観測した権限）と比べて示す。直前の観測と比べると、取り消し後に一度観測しただけで
  取り消しの表示が消えるため。履歴は権限の種類だけを UserDefaults に保存し、アプリの再起動をまたいで取り消しを示す
- Apps/macOS の `PermissionAccess`（本番は `SystemPermissionAccess`）が OS の状態を `PermissionSnapshot` に変換する。
  マイクは `AVCaptureDevice`、音声認識は `SFSpeechRecognizer`、Accessibility は `AXIsProcessTrusted`（要求したかを覚えて未確認と拒否を分ける）、
  入力監視は `IOHIDCheckAccess`。状態の取得ではダイアログを出さず、要求とシステム設定を開く操作は画面のボタンからだけ行う
- 状態は画面を開いたとき・アプリが前面に来たとき・要求の後に取り直す
- Phase 0 の判定待ちの値（#48 / #41 / #51）は `MacPermissionConfiguration` で渡す。判定前は、音声認識を要求せず、
  挿入経路の権限は入力欄への直接挿入（AX）のアクセシビリティだけを渡し（AX の API は許可なしでは使えないため。貼り付け・キー入力の経路は確認中として示す）、
  修飾キー単独・Esc の機能を有効にしない

### 初回セットアップ（Apps/macOS, PERM-01〜03, #198）

権限オンボーディングの画面は、初回セットアップの手順として「マイク → アクセシビリティ → 認識モデル → ショートカット → 整形の実行先」の順に並べる
（`FirstRunSetupStep`）。最後の手順まで終えていなければ、起動時に画面を開き（`defaultLaunchBehavior`）、保存した手順から続ける。

- **手順の状態は保存せず、毎回求める。** 権限・モデル・設定から `FirstRunSetupEvaluation` が求める（済み・不要・取得中・操作が要る・ここでは設定できない・あとで）。
  保存するのは今の手順・終えたか・整形の実行先の選択だけ（`FirstRunSetupDefaults`。UserDefaults に置き、秘密情報・発話は置かない）。
  操作が要る手順からは「次へ」に進めない。管理者による制限・エンジンの未設定・この Mac で使えないモデルは、ここでは設定できないとして進める
- **権限は手順ごとに `PermissionOnboarding` の段階を振り分ける。** 音声認識の許可（使う STT が要するとき）はマイクの手順、入力監視
  （修飾キー単独のショートカットのとき）はショートカットの手順に出す。どちらも `MacPermissionConfiguration` で要る権限に入れたときだけ出る。
  ショートカットの登録が権限の不足で使えないときは、メニューと同じく `ShortcutCoordinator.requestPermission` で求める
- **認識モデルは「取得を開始」を押したときだけ通信する。** 状態の確認と取得は設定画面と同じ `SpeechModelSettingsModel`。手順に出すモデル名・取得元・
  サイズ・取得後の確認は `SpeechModelDescription` がエンジンごとに作る（エンジンを替えるときはここと `STTEngineSetting.makeModelAssets` を書き換える）。
  SpeechAnalyzer のモデルは OS が管理するため、サイズは取得の前には示せないこと、取得後の確認は macOS が行い utter は照合しないことをそのまま示す。
  エンジンが未設定（`UTTER_MAC_STT_ENGINE`）なら、取得のボタンを出さず未設定であることを示す。WhisperKit の取得は実装しない（#49）
- **ショートカットは重なりを確かめてから保存する。** 記録は設定画面と同じ `ShortcutRecordingMonitor`。有効なシステムのショートカット・Edit Mode のショートカットとの重なりと、
  登録の結果（`ShortcutCoordinator.status`。他アプリとの競合など）を `FirstRunShortcutCheck` で示す。保存は保存先の最新の設定の録音ショートカットだけを書き換える
- **整形の実行先は「あとで」で飛ばせる。** 選択肢は設定画面と同じ `RefinementProviderChoice`（OpenAI API キー方式は準備中で選べない）。
  「あとで」は設定を変えない（既定は Local Basic で、送信しない）。クラウドを選んでも、送るかは整形の経路が同意・API キー（またはサインイン）で決め（AC-06）、
  この画面からは送らない。同意は変えない
- 手順・状態・進み具合の判定と `FirstRunSetupModel` は `UtterMacTests` で確かめる（権限・モデルは Stub）。権限ダイアログを含む動作は人が実機で確かめる

## STT モデルの完全性検証（PERM-03）

取得した STT モデルは、UtterSpeech の `ModelIntegrityVerifier` でマニフェスト（`ModelManifest`：相対パス・サイズ・SHA-256）と照合し、
`ModelIntegrityStatus.verified` のときだけロードする（`isLoadable`）。ディレクトリの読み取りは `ModelFileSource` protocol 越しに行い、
本番は `LocalModelFileSource`（FileManager / CryptoKit）、テストは `StubModelFileSource` を使う。

- **検証失敗にするもの：** ファイルの欠落、サイズの不一致、SHA-256 の不一致、読み込みの失敗、マニフェストにないファイル、
  シンボリックリンクなど通常ファイルでない項目。マニフェスト自体も、絶対パス・`..`・重複パス（大文字・小文字、Unicode 正規化の違いを含む）を拒否する
- **`.DS_Store` などの隠しファイルも、マニフェストになければ検証失敗にする。** 無視するファイル名は設けない（取得し直せば直る）。Finder で開いただけで失敗する可能性があり、緩めるかは今後判断する
- **マニフェストはモデルと別の信頼できる経路で持つ。** モデルと同じ取得元から同時に受け取ったマニフェストでは、破損は検出できても改ざんは検出できない。
  マニフェストの配布方法（アプリへの同梱など）は Phase 0 の STT 方針とモデル配布方法（14章）の確定後に決める
- 検証は同期的にファイルを読むため、メインスレッドの外で呼ぶ。キャンセルされたら `CancellationError` を投げる
- ダウンロード処理、取得元・サイズの表示（`ModelManifest.totalByteCount` を使う）、特定エンジン（SpeechAnalyzer / WhisperKit）のモデル形式は対象外で、
  Phase 0 の結果を受けて Apps / アダプター側で実装する

## Web サイト単位のスタイル判定（CTX-02, CTX-03）

スタイルは UtterCore の `ContextStyleResolver` で、サイト別の上書き → アプリ別の上書き → 既定の対応表 → `standard` の順に選ぶ。
サイト別の上書き（`SiteStyleResolver`）は明示的な許可制で、許可（`isSiteIdentificationAllowed`）の既定は無効。許可がなければホスト名を受け取っても使わない。
サイトには既定の対応表を持たず、利用者が設定した上書きだけで判定する。

- **ホスト名だけを扱う。** `SiteHost` は URL からホスト名だけを取り出し、スキーム（`http` / `https` 以外は作らない）・利用者情報・ポート・パス・クエリ・フラグメントを捨てる。
  小文字にそろえ、末尾のドットと先頭の `www.` を外す。国際化ドメイン名は Punycode の形で扱い、ASCII の英数字・ハイフン・ドット以外を含む値は作らない。
  サブドメインは別のサイトとして扱う（親ドメインの上書きは当てない）。`_` を含む名前・IPv6 は作らず、IP アドレスの表記はそろえない。
  設定画面の入力は `SiteHost(userInput:)` で、ホスト名・URL・Unicode の国際化ドメイン名をブラウザから得た値と同じ形にする
- **URL の取得は Apps/macOS の責務。** 前面のブラウザから URL を読むのは Apps/macOS で、`SiteStyleResolver.needsSiteHost` が `true`（許可があり、上書きが1件以上）のときだけ読む。
  読んだ URL はその場で `SiteHost(url:)` に渡し、URL 自体は保持しない
- **macOS の読み取り（`FrontmostSiteHostReading`）。** 本番は `AccessibilitySiteHostReader`（`Apps/macOS/Sources/Session/FrontmostSiteHost.swift`）、テストは Stub。
  `SessionRefinementPipeline` が整形のたびに、Raw でなく、`needsSiteHost` が `true` で、録音開始時の前面アプリ（bundle ID）が分かるときだけ呼ぶ。
  前面のアプリがその bundle ID のときだけ、フォーカス中の要素から親をたどって `AXWebArea` を探し（なければ `AXFocusedWindow` の中を数と深さを限って探す）、
  その `AXURL` からホスト名だけを取り出す。挿入と同じ Accessibility の権限だけを使い、未許可なら何もしない。AppleScript・Apple Events・非公開 API は使わず、
  権限・Entitlement を増やさない。メインスレッドで問い合わせるため、待ち時間を短く（1回 0.25 秒、探索全体で 0.3 秒）し、応答しないアプリでは打ち切る。
  読み終えたときに前面のアプリが替わっていたら、そのホスト名は使わない。
  Chromium 系のブラウザは支援技術から要求されるまで Web 領域を公開しないことがあるが、公開を求める属性（`AXManualAccessibility` など）は他アプリの状態を変えるため設定しない。
  読めなければ `nil` で、アプリ別のスタイルに戻る
- **ホスト名・URL を外に出さない（CTX-03）。** 判定結果は `RefinementStyle` だけで、`RefinementRequest` にホスト名・URL を入れない。
  `SiteHost`・`SiteStyleResolver`・`ContextStyleResolver` の文字列表現とリフレクションにはホスト名を出さず、ログにも出さない
- **設定の保存。** 許可フラグ（`siteIdentificationAllowed`、既定は無効）とサイト別上書き（`siteStyleOverrides`、キーは正規化したホスト名）は `AppSettings` の版 2 に含める。
  `AppSettings.contextStyleResolver` で判定器を作る。項目のない版 2 の保存値は許可なし・上書きなしで読む

## macOS の設定画面（AC-05, AC-12, AI-05, CTX-01, CTX-02, PERM-03, REC-01）

Apps/macOS の `Settings` シーン（メニューの「設定…」, ⌘,）に、録音・整形・費用・スタイル・除外アプリ・音声認識・API キーのタブで並べる。API キーのタブは Keychain に即時に保存し、音声認識のタブは保存する項目を持たないため、どちらも下の「保存」「元に戻す」を出さない。同意・辞書・入力履歴・権限は別のウインドウ（メニューから開く）。

- **View は薄くする。** 入力の検証と保存する値は `SettingsForm`（文字列の入力をまとめて検証し、問題があれば何も保存しない）、保存と再読み込みは `SettingsModel`、
  UtterAI と UtterPersistence の橋渡し（単価表・予算・台帳の変換、推定費用の表示値、`BudgetGuard` の作成と `MonthlyUsageStore` への記録）は `CloudCostBridge` が持つ。
  これらは `UtterMacTests`（アプリを起動しないユニットテスト。テスト対象のソースを直接コンパイルする）で確かめる
- **保存の基準は保存先の最新の値。** 画面で扱わない項目（同意状態・履歴）はほかの画面の変更ごと残す
- **録音ショートカット（REC-01, REC-02）。** 「録音」タブの「記録」を押した後の次のキー入力を、`NSEvent` のローカルモニター
  （`ShortcutRecordingMonitor`）で受け取る。モニターは記録中だけ付け、組み合わせを受け付けた・Esc で取り消した・画面が消えた
  （ウインドウを閉じた・タブを移った）・設定ウインドウがキーウインドウでなくなった・アプリが前面でなくなったときに外す。
  記録中の設定ウインドウでの通常のキーの押下はほかの操作（⌘W・Return での保存など）に渡さない。ほかのウインドウ（辞書の編集など）への入力は奪わず、記録をやめる。
  キー入力の解釈は `ShortcutRecorder`（純粋な値型）で、登録時と同じく `CarbonHotKeySpec` で扱える組み合わせだけを受け付け、
  有効なシステムのショートカット（`SystemShortcuts`）と重なるものも受け付けない。修飾キー単独（修飾キーだけを押して離す）・
  Fn を含む組み合わせ・修飾キーのない文字キーは理由を表示して記録を続ける。F キー・矢印キーに `NSEvent` が付ける Fn のビットは外す。
  記録した値は `SettingsForm.recordingShortcut` に入れ、ほかの項目と同じ「保存」で保存する（「解除」で未設定にする）。
  保存済みの値が登録できない組み合わせなら、保存時に問題にする。入力されたキーは結果の組み合わせ以外に保持せず、ログに出さない
- **除外アプリ（7章, AC-12）。** `AppSettings.excludedApps` を bundle ID の行で編集し、ほかのタブと同じ「保存」でまとめて検証・保存する。
  bundle ID の形（ASCII の英数字・`.`・`-`・`_`）でない行と、大文字・小文字だけが違う重複の行は問題にして保存しない。
  「起動中のアプリから追加」は `NSWorkspace.runningApplications` のうち通常のアプリ（自分自身・一覧にあるものを除く）を候補にする（`ExcludedAppCandidate`）。
  設定画面を開いている間の前面アプリは utter 自身のため、前面アプリそのものは候補にしない。
  除外アプリは、セッションの録音の開始・クラウド送信・入力履歴の保存の判定（`SensitiveInputPolicy`）に使う。挿入の判定にはまだ使っていない
- **推定費用は推定値として表示する（AI-05）。** 予算・単価表の通貨と更新日がそろわなければ表示せず、0 で補わない。請求額・クレジット残高ではないことを画面に明記する
- **ChatGPT は2つの方式を別の選択肢にする（#50, S7）。** 「整形」タブの処理系に「ChatGPT（Sign in with ChatGPT）」と「ChatGPT（OpenAI API キー方式。準備中）」を並べ、
  後者はまだ選べない（`RefinementProviderChoice`）。保存は `AppSettings.refinementEngine`（クラウド AI）と `cloudRefinementProvider`（Claude / Sign in with ChatGPT。版 2 に足し、ない保存値は Claude）で行う。
  Sign in with ChatGPT を選ぶと、「Continue with ChatGPT」・アカウント・「Using ChatGPT plan」と「Manage usage」・サインアウト・利用上限からの再開・モデル一覧（`chatGPTRefinementModel`。既定は未選択）を出す
  （状態は `ChatGPTAccountSettingsModel`、画面は `ChatGPTAccountSection`）。サインインは Keychain に即時に保存し、モデル名はほかの項目と同じ「保存」で保存する。
  サインインは利用者の操作でだけ始め、整形の送信時に自動では始めない。整形と設定画面は同じ `ChatGPTAccountSession` を使う（トークンの更新を1か所で直列にする）
- **音声認識（4章, PERM-03）。** 使っている STT エンジン（`AppComposition.selectedEngine()`）を出す。エンジンはビルド設定で選び、この画面では変えない。
  未選択なら `Config/Local.xcconfig` の `UTTER_MAC_STT_ENGINE` で選ぶことを示す。SpeechAnalyzer を選んでいるときだけ、モデルの取得状態と「モデルを取得」ボタンを出す。
  状態は `SpeechModelSettingsModel`（OS の口は `SpeechModelAssets`。本番は UtterSpeech の `SpeechAnalyzerAssets`、テストは Stub）が持ち、
  iOS の同名の型と同じ振る舞いにする（状態の確認はネットワークを使わず、取得はボタンからだけ。取得元が Apple のサーバーで、取得にネットワークを使うことを画面に書く）。
  モデルは OS 全体で共有するため、アプリのプロセスで取得したモデルを STT Worker の認識がそのまま使う

## macOS のグローバルショートカット（REC-01, REC-02）

録音のショートカットは Apps/macOS の `GlobalShortcutController` が登録し、押下・解放を UtterCore の `ShortcutInterpreter` に渡して
セッション操作（`ShortcutCommand`）にする。割当の検証は UtterCore の `ShortcutValidator`。修飾キー単独と Esc 捕捉を使うかは
`ShortcutCapabilities`（`supportsModifierOnly` / `supportsEscapeCapture`）で決め、#51 の判定までは `.keyCombinationsOnly`（どちらも使わない）。
OS への登録は `HotKeyRegistering` protocol 越しに行い、本番は `CarbonHotKeyRegistrar`（RegisterEventHotKey）、テストは `StubHotKeyRegistrar` を使う。
イベントタップは `KeyEventTapFactory` / `EventTapPermissionChecking` protocol 越しに作り・権限を確かめ、本番は `CGKeyEventTapFactory` /
`SystemEventTapPermissions`、テストは `StubKeyEventTapFactory` / `StubEventTapPermissions` を使う。

- **既定で対応するのは通常のキー組み合わせ（修飾キー＋キー）だけ。** 修飾キー単独と、セッション中だけの Esc 捕捉は #51（要件定義 11章）の
  判定待ちの先行実装で、既定で無効（Release は常に `.keyCombinationsOnly`。Debug ビルドに限り起動引数
  `-UtterDebugModifierOnlyShortcut YES` / `-UtterDebugEscapeCapture YES` で有効にできる）。不成立なら、下記の「修飾キー単独」「Esc 捕捉」の
  ファイルと capability を外せば、通常のキー組み合わせの実装がそのまま残る
- **通常のキー組み合わせは権限を要求しない（PERM-01）。** RegisterEventHotKey は入力監視・アクセシビリティなしで登録・受信できる。押下（kEventHotKeyPressed）と
  解放（kEventHotKeyReleased）の両方を受け取り、解放を Push-to-talk の停止に使う
- **競合の検出（REC-02）:** 登録前に、有効なシステムのショートカット（`SystemShortcuts`、CopySymbolicHotKeys）と `ShortcutValidator` で照合する。
  登録が成功してもシステムが先に処理する組み合わせは届かないため。登録は排他（kEventHotKeyExclusive）にし、他のプロセスの排他登録との競合は
  eventHotKeyExistsErr として検出する。F キー・矢印キーのシステムの項目に付く Fn のビットは外して照合する。他アプリが独自に処理するショートカット（メニュー・イベントタップ）は検出できない
- **登録しない組み合わせ:** Fn を含むもの（RegisterEventHotKey の修飾キーとして公式に挙げられていない）、対応表（`MacKeyCodes`）にないキー、
  F1〜F20 以外のキーで Command・Option・Control のいずれも含まないもの（space・return・矢印キー等を含め、他アプリでの文字入力・編集操作を奪うため）
- **キーリピートと取りこぼし:** RegisterEventHotKey はキーリピートを届けないため、押下はすべて新しい押下として渡す（`HotKeyEventTranslator`）。
  解放を取りこぼしても、Push-to-talk は次の押下で停止できる（`ShortcutInterpreter`）。押下を受けていない解放は捨てる。
  スリープ前・ユーザー切替の前に押下中の状態を破棄する
- **割当は版2設定の保存値。** 録音ショートカット（`AppSettings.recordingShortcut`）と録音の操作方式（`recordingTrigger`）を
  `GlobalShortcutSetting.fromSettings` で割当にし、`AppComposition` が起動時に読んで `ShortcutCoordinator` に渡す。ショートカットが未設定（`nil`）なら
  何も登録しない（既定のショートカットは要件で決まっていない）。割当は設定画面の「録音」タブで記録する（上の「macOS の設定画面」）。
  Debug ビルドに限り、起動引数 `-UtterDebugRecordShortcut ctrl+option+k`（`-UtterDebugRecordShortcutMode ptt`）で実機確認用に割り当てられ、
  そのときは保存値より優先し、設定の変更にも従わない
- **設定の変更は待機中に反映する。** 設定画面の保存は UserDefaults の変更の通知で読み直し、割当が変わったときだけ
  `GlobalShortcutController.update` に渡す。待機中ならすぐに、セッション中なら待機に戻ってから（`sessionPhaseDidChange`）登録し直す
  （録音中に登録し直すと Push-to-talk の押下中の状態を失うため）。同じ割当なら登録し直さず、競合・登録失敗の表示もそのまま残す
- **修飾キー単独（#51 の判定待ち）:** Fn と、左右を指定した修飾キー（`ModifierOnlyKey`。`right-option` 等）の1つだけを割り当てられる。
  入力監視の listenOnly タップで検出し、イベントは止めない（Toggle は flagsChanged・keyDown・クリック・スクロール、
  Push-to-talk は flagsChanged だけを受け取る）。判定は `ModifierOnlyDetector`（純粋な値型）で、
  押下時に他の修飾キー（同じ種類の反対側を含む）が押されていれば扱わない。Push-to-talk は押下で開始・解放で停止、Toggle は他のキーを
  挟まずに離したときだけ反応する（右 Option での記号入力・⌥⌘D・⌘クリック等では反応しない）。このため Toggle に限り、その修飾キーを含む
  システムのショートカットとの重なり（`modifierOverlap`）を競合から除く。Push-to-talk は重なりを競合として残す。
  通常のキー・マウス操作は「押下中にあったか」だけを使い、どのキーか・位置は保持・記録しない
- **Esc 捕捉（#51 の判定待ち）:** ショートカットを登録できたときだけ、アクセシビリティの defaultTap（keyDown・keyUp）を作る。
  待機中はタップを無効にし、`ShortcutInterpreter.capturesEscape(in:)` が true の間（録音〜整形中）だけ有効にする（REC-01）。
  判定は `EscapeCaptureFilter`（純粋な値型）: 修飾キーなしの Esc の押下を止めてキャンセルし、そのキーリピートと解放も止める。
  修飾キー付きの Esc は通す。Push-to-talk ではトリガーを押したまま Esc を押すため、トリガーの修飾キーは判定から除く。Fn は判定に含めない。
  ショートカット以外の要因で状態が変わったら、アプリが `sessionPhaseDidChange()` を呼ぶ（`AppComposition` が `SessionCoordinator.onPhaseChange` に結線する）。
  Esc のキャンセルはタップのコールバックの中で同期的に `SessionCoordinator.cancel()` まで進むため、その経路では状態機械の更新だけを行い、
  HUD のウィンドウ操作（`HUDPanelPresenter`）はメインスレッドの次の処理に回す
- **イベントタップの権限（PERM-01, PERM-02）:** capability が無効ならタップを作らず、権限も確かめない。有効でも自分からは権限を求めず、
  メニューの項目（用途を添えた文言）を利用者が選んだときだけ求める（Info.plist に用途説明のキーはない。
  拒否済みでダイアログが出なければシステム設定の該当画面を開く）。権限がない・取り消された場合は
  その機能だけを無効にし、理由をメニューに出して、許可するか通常のキー組み合わせを割り当てるよう案内する（Esc 捕捉がなくても
  通常のキー組み合わせは使える）。OS に権限の変化の通知がないため、イベントタップを使う機能が有効なときだけ 5 秒ごと（仮置き）と、
  OS がタップを無効化したときに確かめる（`refreshPermissions`）。OS がタップを無効化したら押下・捕捉の状態を破棄して再有効化する
- `Apps/macOS/Sources/Shortcut` はテスト・バンドル `UtterMacTests` にソースごと含めてテストする（アプリを起動しない）。
  本番の登録処理（`CarbonHotKeyRegistrar`、`SystemShortcuts.loadEnabledBindings`、`CGKeyEventTapFactory`、`SystemEventTapPermissions`）も含まれるが、テストからは呼ばず Stub を使う

## HUD（REC-03, REC-05, AC-16）

HUD は UtterCore の3つの型と、Apps/macOS の画面部品に分ける。

| 型 | 置き場所 | 役割 |
|---|---|---|
| `HUDState` / `HUDContent` | UtterCore | 状態機械の変化から、表示する状態（録音・認識・整形・挿入・失敗）と通知（上限到達・割り込み・失敗の理由・ローカル整形への退避）を導く。通知は `notices` に複数持つ。時刻は引数で受け取る |
| `HUDPresentation` | UtterCore | `HUDContent` から表示文言・表示の種類・VoiceOver の読み上げ文言を組み立てる。文言はここだけで作る。通知は `messages` に複数持ち、1件ずつ表示する。Realtime Preview の認識テキスト（`HUDTranscript`）は録音中・認識中だけ持つ |
| `HUDSessionInfo` | UtterCore | 状態と通知のほかに表示に添える情報（録音の経過時間と最大録音時間、入力音量、録音開始時のセッションの設定、クラウド整形の送信先、停止・キャンセルのキー）。本文・音声・API キーは持たない |
| `HUDController` | UtterCore（`@MainActor`） | `HUDState` と表示中のセッションの認識テキストを保持し、内容が変わったときだけ `HUDPresenting` に表示・非表示を依頼する。通知を消す時刻・失敗の表示を終える時刻に `HUDRefreshScheduling` で更新を予約し、失敗の表示時間が過ぎたら `onErrorDisplayExpired` で知らせる |
| `HUDPanel` / `HUDView` / `HUDPanelPresenter` / `TaskHUDRefreshScheduler` | Apps/macOS | 非アクティブ化パネル（NSPanel）と SwiftUI の画面、`ContinuousClock` によるタイマー |

- **フォーカスを奪わない。** パネルは `nonactivatingPanel` で、キーウィンドウ・メインウィンドウにならず、`orderFrontRegardless()` でアプリをアクティブにせずに出す。
  クリックも受けない（`ignoresMouseEvents`）。HUD に操作部品は置かない
- **全 Space とフルスクリーンのアプリの上に出す**（`canJoinAllSpaces` / `fullScreenAuxiliary`、レベルは `statusBar`）。
  表示を始めた時点でマウスポインターのある画面の下部中央（`visibleFrame` の下端から間隔を空けた位置。Dock に重ならない）に置き、
  表示中は下端の中央を保ったまま上へ伸び縮みし、画面を移らない
- **本文は Realtime Preview のときだけ表示する。** `HUDContent` は状態と通知の区分だけを持ち、文言は区分から作るため、API キー・トークン・エラー詳細は HUD に出ない。
  発話本文を出すのは入力モードが Realtime Preview（2.2節, AC-03）のときの認識テキスト（`HUDTranscript`）だけで、Instant（既定）では出さない。
  セッションを進める側が UtterSpeech の `TranscriptPreview` に `partial` / `confirmed` を溜め、`HUDController.updateTranscript(_:for:)` に渡す。
  表示は渡したセッションの録音中・認識中だけで、別のセッション・キャンセル・整形以降の段階では捨てる。画面は確定済みを通常の色、
  暫定を淡い色と点線の下線で区別し、長ければ新しい側を残して先頭を省く。`HUDTranscript` / `HUDPresentation` の `description` には文字数だけを出す
- **VoiceOver：** 画面は `HUDPresentation.accessibilityLabel` を1つの要素のラベルにする。パネルにフォーカスが移らないため、
  失敗と通知は `HUDPresentation.announcement(after:)` で読み上げを依頼する。録音中（読み上げがマイクに入る）と処理中の各段階（短い間隔で変わる）は読み上げない。
  段階だけが変わったとき（整形中 → 挿入中 → 通知だけを残す）は同じ通知を読み直さず、新しい通知が加わったときと失敗のときだけ読み上げる。
  Realtime Preview の認識テキストはラベルにも読み上げにも含めず、認識テキストだけが変わったときは通知を読み上げ直さない。
  `HUDPanelPresenter` は表示・非表示の依頼をメインスレッドの次の処理でまとめて反映し、短い間隔の更新では最後の内容だけを描画する
  LSUIElement のアプリからの読み上げが届くか、録音に入らないかは実機の VoiceOver で確かめる
- **新しい `HUDNotice` や停止の原因を追加したら、`HUDPresentation` に文言を追加する。** switch を `default` で受けず、追加漏れをコンパイルエラーで検出する
- セッションを進める側（Apps/macOS の `SessionCoordinator`）は、状態機械を変えるたびに `HUDController.update(from:failureNotice:)` を呼び、
  `onErrorDisplayExpired` で `SessionStateMachine.dismissError()` を呼んでから再び `update(from:)` で反映する
- **録音を始めなかった通知（7章, AC-12）：** 機密入力の判定で録音を始めなかったら、待機中のまま
  `HUDController.recordRecordingSuppressed(_:)` を呼ぶ。`HUDNotice.recordingSuppressed` を1行目に出し、上限到達の通知と同じ時間だけ残す
- **失敗の理由：** 失敗の表示に入るときに `failureNotice`（`HUDNotice.speechRecognitionNotConfigured` / `.microphoneAccessDenied`）を渡すと、
  2行目に理由を出す。停止理由の通知より優先し、失敗の表示を終えるまで保つ。理由は区分だけで、エラー詳細は出さない
- **ローカル整形への退避（4.1節, AC-16）：** `SessionCoordinator` は、整形の経路が `SessionRefinementRoute.cloudFallback(理由)`（送ろうとして退避した）のとき、
  整形完了を状態機械へ渡す前に `HUDController.recordRefinementFallback(RefinementFallbackNotice(reason:), for:)` を呼ぶ。
  通知は整形中から挿入中まで出し、正常に終えたら上限到達の通知と同じ時間だけ残す。キャンセル・失敗の表示の終了では残さない。
  送らなかった場合（`localOnly`: Local Basic を選んでいる・同意なし・API キーなし・機密入力など）は知らせない
- **録音中・処理中の情報（REC-03, REC-05）：** `HUDPresentation` が段階ごとに次を組み立て、画面はそのまま描画する。
  - 録音中: 経過時間と最大録音時間（例: `0:07 / 5:00`。`HUDController` が1秒の区切りごとに更新を予約する）、
    レベルメーター（`SessionCoordinator` が録音のチャンクから実効値を求めて `HUDController.updateInputLevel(_:for:)` に渡す。
    音声は保持・送信しない。点灯する本数が変わったときだけ表示を更新する）、チップ（整形モード・アプリ別スタイル・音声認識の種別。
    録音開始時に `recordSessionDetails(_:for:)` で渡す。アプリ別スタイルは前面アプリの対応表と上書きから選び、録音開始を遅らせないよう
    サイト別の上書きは反映しない）
  - 処理中: 4段階（録音 → 認識 → 整形 → 挿入）のどこにいるか
  - クラウドへ送る間だけ送信先: クラウド STT の認識中は「OpenAI へ送信」、クラウド整形は `SessionRefining.refine` の `willSend` で
    送ると決めた整形中に `recordRefinementDestination(_:for:)` で渡す（「Claude へ送信」など）。ローカルで処理する間は出さない
  - キャンセルが効く間（録音中・認識中・整形中）だけ、停止とキャンセルのキー。`ShortcutCoordinator` が登録済みのショートカットと
    Esc の捕捉の状態から `HUDKeyHints` を作り、`updateKeyHints(_:)` で渡す。使えないキーは出さない
- **挿入完了（REC-03）：** 入力先へ挿入したら、`SessionCoordinator` が挿入完了を状態機械へ渡す前に
  `HUDController.recordInsertion(_:for:)` で録音開始時の前面アプリの表示名を渡す。待機に戻った後も「〇〇 に挿入しました」を
  `completionDisplayDuration`（通知も重なれば `limitNoticeDisplayDuration`）だけ残す。読み戻しで確かめられなかったときは入ったと言い切らない。
  表示名が分からない・プレビューへ退避した・キャンセル・失敗では出さない。取り消し方法（⌘Z など）は経路ごとの Undo の検証（#41）まで出さない
- **複数の通知：** 録音停止（または失敗の理由）と退避の通知が重なると、`HUDPresentation.messages` に1件ずつ並べ、画面は状態の下に1行ずつ出す。
  通知だけを残している間は先頭の通知を1行目、残りを2行目以降に出す。VoiceOver は表示順に続けて読む

## macOS の挿入（INS-01〜07, AC-08, AC-09）

経路の順・次に何をするか・結果の分類・クリップボード復元の可否は UtterCore（`InsertionPolicy` / `InsertionPlan` / `InsertionResult.classify` /
`ClipboardRestorePolicy`）が決め、Apps/macOS の `InsertionExecutor`（`Sources/Insertion/`）がその計画を AX / Pasteboard / CGEvent で実行する。
OS の機能は protocol 越しに使い、本番は次のアダプター、テスト（`Apps/macOS/Tests/`）は Stub を渡す。

| protocol | 本番 | 役割 |
|---|---|---|
| `InsertionTargetInspector` | `AccessibilityInsertionTarget` | 録音開始時の入力対象の記録、挿入直前のフォーカス中の入力対象（`InsertionTargetID`、bundle ID、セキュア入力欄か）、システムのセキュア入力 |
| `InsertionFieldAccess` | `AccessibilityInsertionTarget` | 挿入前の値・選択範囲の読み取り、`kAXSelectedTextAttribute` への書き込み、読み戻し |
| `InsertionPasteboard` | `SystemInsertionPasteboard` | クリップボードの退避・書き込み（印つき）・書き戻し |
| `InsertionKeyEvents` | `CGEventInsertionKeyEvents` | Cmd+V、Unicode 文字列付きのキー入力 |
| `InsertionPermissions` | `SystemInsertionPermissions` | `AXIsProcessTrusted` / `CGPreflightPostEventAccess`（要求はしない） |
| `InsertionPreviewPresenting` | `InsertionPreviewPanel` | コピー可能なプレビュー（フォーカスを奪わない浮動パネル） |
| `InsertionClock` | `ContinuousInsertionClock` | 読み戻しの締め切りと待ち（取り消されても待ちを短くしない） |

- **経路を試す直前ごと、および AX の書き込み・Cmd+V・キー入力を送る直前に入力対象を確かめる。** 録音開始時と違う・消えた・記録できなかった場合は、
  何も送らずにプレビューへ退避する（INS-01, AC-09）。CGEvent 経路は1文字ごとに確かめ、途中で変わったら残りを送らずに成功不明で終える。
  `AXUIElement` は `TargetIdentityRegistry` で不透明な識別子に対応づけ、同一性は pid と `CFEqual` で比べる。持つのは直近に記録した1件だけで、
  挿入の途中で次の録音を始めると前の挿入は読み戻せなくなる（成功不明側に倒れる）。セッションは挿入を終えてから次の録音を始める前提にする
- **同じ時点で `SensitiveInputPolicy` を判定し、抑止ならプレビューへ退避する。** パスワード欄（`AXSecureTextField`）、システムのセキュア入力、
  機密アプリ・除外アプリ、判定できない場合（7章）
- **権限（PERM-01, PERM-02）。** 入力対象の確認は AX で行うため、Accessibility が未許可ならどの経路も使わずに退避する（`accessibilityNotTrusted`）。
  イベント送信が未許可なら Pasteboard / CGEvent 経路を計画から外す。権限の状態をまとめる型（`FeatureAvailability.permittedRoutes`, PR #129）ができたら、そちらから渡す
- **成功不明なら再試行しない（INS-05）。** 書き込み後、一致するまで読み直し、`InsertionResult.classify` で分類する。締め切りは AX の問い合わせの時間を含む実時間で、
  時刻と待ちは `InsertionClock` で差し替える。次の経路を試すのは、送信前の失敗か、読み戻しで変化がないと確かめた場合だけ。
  タスクが取り消されたら、読み戻しの途中なら成功不明で終え、経路を試す前や AX の書き込み・Cmd+V・キー入力を送る直前ならそれを送らずにプレビューへ退避する。同じ実行器への挿入が重なった場合は後の方を退避する
- **Return キーを送らない（INS-03, AC-08）。** 末尾の空白・改行は除く。ターミナル系のアプリへの改行を含む文字列は退避する（`InsertionPlan.preparedText`）。
  CGEvent 経路は、改行のキー入力がチャット欄で送信に、Tab がフォーカスの移動になりうるため、改行・制御文字を含む文字列を送らない（送信前の失敗として次へ進む）
- **Pasteboard 経路（INS-04, INS-06）。** 退避 → 退避中に書き換えられていたら中止 → `org.nspasteboard.TransientType` / `ConcealedType` を付けて書き込み →
  送り先を確かめて Cmd+V → 読み戻し → 待ち（読み戻せない入力欄は読み戻しの時間切れ分も待つ。取り消されても短くしない）→
  changeCount が書き込み直後と同じときだけ書き戻す。遅延提供・ファイルプロミスなど読み出せない種別は戻せない（`restoredPartially`）。
  書き戻し自体はクリップボード管理アプリに新しいコピーとして見えうる（元の内容を変えないよう印は付けない）
- **プレビュー** は退避1件ごとに別の浮動パネルを開き、前の文字列を上書きしない。「コピー」も Transient / Concealed の印を付け、書き込めなければ閉じない
- **アプリ別の既定経路（`AppInsertionProfile`）は、Phase 0（#41）の判定後に [挿入互換性表.md](挿入互換性表.md) から入れる。** それまでは空で、
  すべてのアプリで既定の順（AX → Pasteboard → CGEvent）を試す。ただしターミナル系のアプリ（`KnownTerminalApps`）の `isTerminal` は、
  互換性表 6章のとおり判定によらず有効にする。待ち時間（`InsertionTiming` の既定値）も AXInsertionProbe の既定値で、実機の結果で見直す
- 入力欄の値・クリップボードの中身はメモリ上の比較にだけ使い、ログ・`description` に出さない

### Realtime Direct（2.2節, AC-15。実験機能・MVP 外）

範囲の追跡・差分・照合・取り消しは UtterText の `RealtimeDirectSession` が決め、Apps/macOS の `RealtimeDirectWriter`（`Sources/RealtimeDirect/`）が
認識イベント（`RecognitionEvent`）の列を受けて AX で書き込む。入力欄の読み書きは `RealtimeDirectFieldAccess`（`InsertionFieldAccess` に
範囲の置き換えを足したもの。本番は `AccessibilityInsertionTarget` で、`kAXSelectedTextRange` で範囲を選んでから `kAXSelectedText` を置き換える）。

- **使えるアプリは `RealtimeDirectAllowlist` だけ。** 互換性表で範囲追跡と Undo を確認したアプリを入れる。Phase 0（#41）の判定前のため空で、
  既定ではすべてのアプリで使えない（入力モードで選んでも、Instant と同じく停止後に一括挿入する）。Debug ビルドでだけ、
  起動引数 `-UtterRealtimeDirectDebugApps <bundle ID,...>` で足せる。
  ターミナル系のアプリ（`KnownTerminalApps`）・パスワード欄など（7章。除外アプリはセッションの開始ごとに保存値を読む）・
  録音開始時と違う入力対象・選択中のテキストがある場合も始めない
- **許可リストへの追加の手順。** 実機で範囲追跡（書き込み中の範囲外の編集・フォーカスの移動を検知してやめる）と取り消し（キャンセル・
  メニューの「Realtime Direct の入力を取り消す」）を確かめ、[挿入互換性表.md](挿入互換性表.md) に Realtime Direct の列を足して記録する。
  確認できたアプリの bundle ID を `RealtimeDirectAllowlist.verified`（`Sources/RealtimeDirect/RealtimeDirectAllowlist.swift`）に
  `RealtimeDirectAllowlist().adding([...])` で入れ、同じ PR で [既知の制限.md](既知の制限.md) を直す。確かめる間は Debug ビルドの起動引数で足す
- **`partial` は書き込まない。** `confirmed` ごとに確定済みテキスト全体を、`completed` で全体の確定テキストを渡し、差分だけを置き換える
- **書き込む直前ごとに照合する。** フォーカス中の入力対象・値全体・カーソル位置が記録と合わない（範囲外の編集・フォーカスの移動など）、
  機密入力に変わった、書き込みに失敗した場合は、入力欄に触れずに直接の書き込みをやめる。それまでの書き込みは残し、
  入力欄へ書き込みを送っていたら、認識の完了時に確定テキスト全体をコピー可能なプレビューに出す（`InsertionPreviewCause.realtimeDirectStopped`, AC-09）。
  何も送らないうちにやめたらプレビューに出さず、結果（`RealtimeDirectWriter.completion`）を見たセッションが一括挿入する
- **認識の失敗では書き込みを残す。セッションのキャンセルでは照合のうえ取り除く。** 完了後の取り消し（`undo()`）も同じ照合を行い、合わなければ触れない
- **録音のセッションへの結線（#187）。** `SessionCoordinator` が入力モード（`SessionInputMode.realtimeDirect`）のときだけ使う。
  下の「macOS のセッションの調停」の Realtime Direct の項を参照。Debug メニューの Stub の認識列での確認（`RealtimeDirectDebugRunner`）は、
  本番の結線と起動引数の許可リストで同じことを確かめられるため外した
- Edit Mode（AC-14）の選択範囲の置き換えも同じ `AccessibilityInsertionTarget` を使う（`EditFieldAccess`。下の「macOS の Edit Mode」）

## macOS のセッションの調停（REC-01〜06, INS-01, AC-02, AC-09）

Apps/macOS の `SessionCoordinator`（`Sources/Session/`）が、録音（`AudioRecorder`）→ 音声認識（`SpeechRecognizer`。本番は STT Worker）→
整形（`SessionRefining`。本番は `SessionRefinementPipeline`）→ 挿入（`SessionTextInserting`。本番は `InsertionExecutor`）→ HUD（`HUDController`）を1つのセッションとしてつなぐ。
状態は `SessionStateMachine` が持ち、調停役は操作と非同期処理の結果を状態機械に渡すだけにする。部品はすべて protocol 越しに受け取り、
`UtterMacTests` で Stub を使ってテストする。ショートカット（`ShortcutCoordinator`）とメニューの操作は `SessionCoordinator` へ渡す。

1. 開始（待機中だけ）: 入力対象とスタイル区分の判定に使う前面アプリを記録し（INS-01, CTX-01）、その入力先を機密入力の判定
   （`SensitiveInputPolicy` と保存済みの除外アプリ）にかける。録音してよければ状態機械を録音へ進め、前の録音の停止を待ってから
   `AudioRecorder.start` を呼ぶ（連打, REC-04）
2. 録音のチャンクを一時音声の差し込み口（`SessionAudioRetaining`）に渡しながら、そのまま音声認識へ流す（認識は録音と並行して進む）
3. 停止（操作・最大録音時間のタイマー・音声バッファの上限・割り込み）: 状態機械を認識へ進め、録音を止める。上限・割り込みの通知は HUD に出す（REC-05）。
   最大録音時間のタイマーは `recordingDeadline` に合わせて状態が変わるたびに予約し直す。音声バッファは最大録音時間 + 1秒にし、通常はタイマーで止める。
   音声バッファの上限・割り込みでは録音側が自ら止め（`AudioRecordingPipeline` の `onEnd`）、調停役は状態機械だけを進める
4. 認識の `completed` で整形へ、整形の後に挿入へ進む。整形は `SessionRefining`（本番は `SessionRefinementPipeline`）に任せる。
   クラウドへ送る条件と退避は「macOS のセッションの整形と入力履歴」を参照
5. 挿入はプレビューへの退避も含めて完了とし、待機へ戻る（文字列はプレビューに残る, AC-09）。入力先へ挿入したとき（`InsertionOutcome.finished`）だけ、
   `SessionHistoryRecording`（本番は `InputHistoryRecorder`）で入力履歴に保存する

- **機密入力での開始（7章, AC-12）：** 開始時の入力先がパスワード欄・セキュア入力・機密アプリ・除外アプリ、または判定できない
  （入力欄やアプリを取れない）なら、セッションを始めない。マイク・音声認識・一時音声・送信・履歴のどれも使わず、待機中のまま
  `HUDController.recordRecordingSuppressed(_:)` で「〜のため、録音しません」を上限到達の通知と同じ時間だけ出す（理由は
  `SensitiveInputDecision.primaryReason` で1つ選ぶ）。前の録音の停止・クラウド STT の準備を待った後（マイクを開く前）と、
  マイクの使用許可を待った後（音声を読む前）にも判定し直し、その間に変わっていれば同じく待機へ戻して知らせる。
  録音を始めた後に入力先が機密入力に変わった場合は録音を続け、
  送信・履歴保存・挿入の直前の判定で止める（挿入はプレビューへ退避）
- **STT 未設定：** 既定のエンジンは Phase 0 の判定待ちで持たない。エンジンが選ばれていなければ（`recognizer == nil`）マイクを開かず、
  認識の失敗と「音声認識が設定されていません」を表示する。選ぶのは `AppComposition`（ビルド設定 `UTTER_MAC_STT_ENGINE`。
  Debug ビルドだけ起動引数 `-UtterDebugSTTEngine` が優先する。「STT Worker」の節）
- **キャンセル：** 録音〜整形中と失敗の表示中だけ受け付ける（挿入中は取り消さない, REC-01）。メニューの「キャンセル」と、Esc の捕捉
  （#51 の判定待ちで既定は無効。`ShortcutCapabilities.supportsEscapeCapture`）で行う。状態が変わるたびに `onPhaseChange` で
  ショートカットへ知らせ、Esc のタップをセッション中だけ有効にする
- **Realtime Preview（2.2節, AC-03）：** 入力モードが Realtime Preview なら、認識の `partial` / `confirmed` をセッションごとの `TranscriptPreview` に溜め、
  HUD に渡す（Instant では渡さない）。入力モードは設定画面の保存値（`AppSettings.inputMode`、既定は Instant）で、
  Debug ビルドだけ起動引数 `-UtterDebugInputMode realtimePreview`（または `instant` / `realtimeDirect`）が優先する。入力欄への挿入はどちらも停止後に一括で行う
- **Realtime Direct（2.2節, AC-15。実験機能・MVP 外）：** 入力モードが Realtime Direct（`AppSettings.inputMode = .realtimeDirect`。既定は Instant で、
  明示的に選んだときだけ）のセッションは、入力対象を記録した直後に `SessionRealtimeDirectWriting`（本番は `RealtimeDirectWriter`。
  挿入と同じ `AccessibilityInsertionTarget` を共有する）の `begin` で使えるか確かめる。始めたら録音中の認識イベントをそのまま渡し、
  確定済みチャンクを逐次書き込む（HUD に認識テキストは出さない）。全体を書き込んで終えたら整形・一括挿入をせずに待機へ戻り
  （整形しないため、クラウドへも送らない）、入力履歴が有効なら認識テキストを保存し、メニューの「Realtime Direct の入力を取り消す」
  （`undoRealtimeDirect()`）で一度だけ取り除ける。次のセッションを始めたら取り消せない
  - **自動で無効にする：** 許可リストにないアプリ・ターミナル系・入力欄を読めない（`unsupportedTarget`）、機密入力（`sensitiveInput`）、
    クラウド STT を選んでいる（`cloudSpeechRecognition`）ときは始めず、HUD で知らせて Instant と同じく停止後に整形・一括挿入する
    （`HUDNotice.realtimeDirectDisabled`。通知は挿入後もしばらく残す）。クラウド STT（`OpenAISpeechRecognizer`）は録音の終わりに一括で
    認識し `completed` だけを流すため、逐次書き込む確定済みチャンクがない
  - **書き込みの途中でやめた：** 何も送らないうちに照合・書き込みに失敗したら（`stoppedBeforeWriting`）一括挿入へ進む。書き込んだ後なら
    （`stoppedAfterWriting`）書き込みを残し、書き込み側が全体をプレビューに出すため、一括挿入しない（同じ文字列を二重に入れない）
  - **キャンセル：** `cancel()` で書き込んだ範囲を照合のうえ取り除く。照合に失敗したら入力欄に触れない
  - **認識し直さない：** STT Worker の異常終了でも、録音全体での認識のやり直し（AC-10）をしない。書き込んだ範囲と、認識し直した全体を
    突き合わせられないため。それまでに書き込んだ確定済みチャンクは入力欄に残り、セッションは認識の失敗になる
- **録音の設定の反映：** 最大録音時間（`AppSettings.maxRecordingDuration`）と入力モードは `SessionSettings.fromSettings` で変換し、
  `AppComposition` が起動時の値を渡す。設定画面で保存したら UserDefaults の変更の通知で読み直し、変わったときだけ `useSettings` で渡す。
  渡した値は次のセッションの開始時（待機中）から使い、録音中・処理中のセッションの最大録音時間のタイマー・音声バッファ・HUD の表示は変えない
- **古いセッションのイベント：** 非同期処理は依頼したセッションを覚えておき、状態機械のセッション ID と段階（フェーズ）を確かめてから結果を渡す。
  違えば捨てる。認識のイベントは `RecognitionEventFilter` で SessionID と順序番号も確かめる。キャンセルしたセッションの認識のストリームは手放す（STT Worker の認識も止まる）
- **失敗：** マイクの拒否・制限は録音の失敗と理由、それ以外の録音の失敗・認識の失敗は段階だけを表示する。認識が録音中に失敗したら録音を止める。
  処理できる音声がないまま割り込まれたら、録音の失敗と割り込みの通知を表示する
- **連打：** 次の録音は前の録音の停止を待ってから始める。キャンセル直後の開始で、前のセッションの開始が録音側に遅れて届いて
  `.alreadyRecording` になったら、それを止めて1回だけやり直す
- **録音を始める前の停止：** マイクの使用許可を待つ間に停止されたら、音声がないため何も処理せずに待機へ戻る
- **一時音声と再処理（7章, AC-10）：** 録音を始めたセッションにだけ、`SessionAudioRetaining` へ `begin` / `finishRecording`（録音が止まった）/ `end` を1回ずつ伝える。
  本番は `TemporaryAudioRetention`。STT Worker の異常終了で認識が失敗したら、録音全体で1回だけ認識し直す（「一時音声と再処理」の macOS の結線）
  起動時の復旧（`LaunchAudioRecovery`）は、設定画面に保存した整形モードでローカル整形だけを行い、クラウドへは送らない
- **本文を出さない：** 発話本文・認識結果・入力欄の値はログ・エラーに出さない。HUD には Realtime Preview の認識テキストだけを出す
- **性能計測の区間（6章, #52）：** `PerfIntervalMeasuring`（本番は `SignpostPerfIntervals`。サブシステム `utter.perf`・Points of Interest の Signpost、
  テストは記録するだけの Stub）を `SessionCoordinator` と `SessionRefinementPipeline` に渡し、`RecordingStart`・`RealtimeFirstText`・`STTFinalize`・
  `Insert`・`StopToInsertLocal` / `StopToInsertAI`・`LLMComplete`（送信先を `PerfMeasuredAIProvider` で包む）を出す。区間名は
  `Verification/PerfProbe` の `PerfInterval` と同じ文字列を `Sources/Performance/PerfInterval.swift` に持つ（アプリは PerfProbe に依存しない）。
  区間には名前だけを付け、本文・アプリ名・bundle ID は載せない。終点に達しないまま待機・失敗の表示へ進んだら開いている区間をすべて閉じる。
  記録していなければほぼ無コストのため、ビルド構成によらず常に出す。開始・終了の位置と出さない区間は [Phase0検証-性能目標.md](Phase0検証-性能目標.md)

## macOS のセッションの整形と入力履歴（TXT-03, AI-01, AI-03, AI-04, AC-06, AC-12, CTX-01〜03, 7章）

Apps/macOS の `SessionRefinementPipeline`（`Sources/Session/`）が、保存済みの設定（`AppSettings` 版 2）・同意・API キー・辞書・予算をつないで整形する。
UtterAI・UtterText・UtterPersistence は互いに依存しないため、値の変換はここで行う（辞書は `DictionaryEditorModel.dictionary(from:)`、予算は `CloudCostBridge`）。

1. 整形のたびに最新の設定を読み、`RefinementRequestPreparer` で置換ルールの適用・辞書語を添え、スタイル区分を `AppSettings.contextStyleResolver`
   （サイト別 → アプリ別 → 既定）で選んだ入力を作る。Raw は置換も送信もせず、ホスト名も読まない。辞書を読めなければ置換・辞書語なしで続ける。
   サイト別のスタイル（CTX-02）は、許可と上書きがあるときだけ前面のブラウザのホスト名を `FrontmostSiteHostReading` で読んで使う
   （「Web サイト単位のスタイル判定」の節）。ホスト名はスタイルの判定にだけ使い、保持・送信・記録しない（CTX-03）
2. 次がすべてそろったときだけ `RefinementRouter` 経由で `ClaudeProvider(apiKeyStore:)` に1回だけ送る。どれかが欠ければ送らず Local Basic にする（`SessionRefinementRoute.localOnly`）
   - 処理系がクラウド AI（`refinementEngine == .cloudAI`。既定は Local Basic）で、モデル名から `ClaudeProvider.Configuration` を作れる
   - Claude への整形の送信に同意している（`ConsentSettingsController.currentConsent()`。予算の確認の後、送る直前にも読み直す, AC-06）
   - API キーが Keychain に保存されていて読み出せる（AC-12。値はプロバイダーが送信時に読む）
   - 入力先が機密入力でない（`SensitiveInputPolicy` と設定の除外アプリ。判定できなければ送らない, 7章）
   - 月次予算・単価表・今月の累計から `CloudCostBridge.makeBudgetGuard` で `BudgetGuard` を作れる（AI-04, AI-05）
3. 送った後の失敗・上限時間の超過・検証失敗・予算超過は `RefinementRouter` がローカル整形の結果に退避する（`SessionRefinementRoute.cloudFallback`, 4.1節）。
   推定費用の累計を保存できなかった後は、アプリを起動し直すまで送らない
4. `cloudFallback` のときは `SessionCoordinator` が HUD に退避の理由を出す（「HUD」の節）。経路の差し込み口 `SessionRefinementReporting` はテストで経路を確かめるのに使い、本番では渡さない

- **機密入力の判定に使う入力先：** `SessionTextInserting.sensitiveInputContext(for:)`。フォーカス中の入力対象が録音開始時と違う・取れない場合は、
  入力欄の属性とアプリを `unknown` / `nil` にして判定できない側に倒す。`RefinementRouter` と `InputHistoryStore` は同期的に判定を求めるため、
  送る直前・保存の直前にメインスレッドで判定した値を渡す（Router が予約を待った後に求める再判定にも同じ値を返す。予約の間の入力先の変化は反映しない）
- **入力履歴：** `InputHistoryRecorder` は、設定で履歴が有効で、保存の直前の入力先が機密入力でないときだけ `InputHistoryStore.record` で保存する。
  履歴の有効・無効は書き込みの中でも読み直す（無効化と全削除の後に書き込まない）
- **CTX-03：** 送るのは本文・整形モード・スタイル区分・辞書語だけ。bundle ID・URL・ウィンドウタイトルは送らない
- **データベース：** 辞書・推定費用の累計・入力履歴は同じファイル（`AppDatabaseLocation`）に置く。セッションの整形・入力履歴とその画面・設定画面の推定費用・辞書の画面は、どれも `AppDatabaseProvider` の接続を1つ共有する（同じファイルを別の接続で開かない）

## macOS の Edit Mode（AC-14, 2.2節。MVP 外の先行実装）

選択したテキストを音声の指示で書き換える。Apps/macOS の `Sources/EditMode/` に置き、`UtterMacTests` にソースごと含めてテストする
（メニューの項目は `AppComposition` を使うため `Sources/EditModeMenu/` に分ける）。

| 型 | 役割 |
|---|---|
| `EditModeShortcut` | Edit Mode のショートカットの登録。押下だけを受け取る（Toggle） |
| `EditModeController` | 1回の流れ（録音 → STT → 送信 → 差分プレビュー → 確定・キャンセル・元に戻す）と、録音のセッションとの調停 |
| `EditModeCoordinator` | 選択範囲の読み取り・送信前の同意と機密入力の確認・差分プレビュー・置き換え・元に戻す（AX） |
| `EditRequestSending` / `EditModeRequestPipeline` | 選択テキストと音声指示の送信。本番は設定・同意・API キー・予算を送るたびに読み直して `EditRouter` で Claude へ。テストは `RouterEditSender` と Stub のプロバイダー |
| `EditModePresenting` / `EditModePanel` | 差分プレビュー（確定・キャンセル）、通知、録音中などの進行中の表示、コピーできるパネルへの退避 |

1. **ショートカットは録音とは別のキー。既定は未割り当て。** `AppSettings.editModeShortcut`（版 2 に追加。ない保存値は未割り当てで読む）を
   設定画面の「録音」タブの行（録音ショートカットと同じ `RecordingShortcutRow` / `ShortcutRecorder`）で記録する。録音ショートカットと同じキーは
   保存時に問題にし（`SettingsIssue.editModeShortcutSameAsRecording`）、登録時にも登録しない。未割り当ての間は何も登録せず、Edit Mode を使わない。
   登録は録音ショートカットと同じ `CarbonHotKeyRegistrar` で行い、システムのショートカット・録音ショートカットと `ShortcutValidator` で照合する。
   設定画面の保存は UserDefaults の変更の通知で読み直し、割当が変わったときだけ登録し直す
2. **録音のセッションと1つずつ。** 押したら `SessionCoordinator.suspendIfIdle()`（`EditModeSessionGate`）で録音のセッションを止める。
   録音のセッション中・起動時の復旧中は始めず、Edit の間（確定・キャンセル・元に戻すまで）は録音を始めない。録音（`AVAudioEngineRecorder`）と
   STT Worker は録音のセッションと同じものを使う。STT エンジンが未選択なら録音のセッションと同じく「音声認識が設定されていません」を出し、
   選択範囲を読まずにマイクも開かない
3. **流れ。** 押す → 選択範囲を読む（パスワード欄など 7章の入力先では読まない）→ 指示を録音 → もう一度押すと止めて認識 →
   空でなければ送信 → 差分プレビュー → 確定で置き換え（読み戻しで確かめる）／キャンセル → メニューの「直前の Edit を元に戻す」。
   確認中にもう一度押すと、同じ選択テキストへの指示をやり直す。指示の長さは 60 秒（仮置き）までで、超えたらそこまでの音声で認識する。
   録音・認識・送信に失敗したら通知し、確認中の編集案がなければ Edit を終える（選択範囲は変えない）
4. **送信（`EditModeRequestPipeline`）。** 次がすべてそろったときだけ `EditRouter` で Claude へ1回だけ送る。欠ければ送らず、理由を通知する
   - Claude への選択テキストの送信（`editSelection`）に同意している。整形の送信の同意とは別で、同意の画面に別の行として出す
     （`ConsentScreenState.editModeScopes`）。送信の前（`EditSession.cloudTransmission`）と、予算の確認の後の送る直前に読み直す（AC-06）
   - Claude API キーが保存されていて読み出せる（整形と同じ Keychain の項目, AC-12）
   - 入力先が機密入力でない。選択範囲を読んだ入力欄と開始時の前面アプリ、保存済みの除外アプリで送る直前に判定し直す（7章, AC-12）
   - 整形と同じ月次予算・単価表・今月の累計から `BudgetGuard` を作れる（AI-04, AI-05）。推定費用は整形と同じ累計に記録する

   整形の処理系（Local Basic / クラウド AI）の選択は見ない。モデル名は整形用モデル名を使う
- **CTX-03：** 送るのは選択テキスト・音声指示・辞書語だけ。bundle ID・URL・ウィンドウタイトル・選択範囲の外の本文は送らない
- **本文を出さない：** 選択テキスト・音声指示・編集案・音声はログ・エラーに出さず、保存もしない（一時音声の保存と認識のやり直しは録音のセッションだけ）

## SpeechAnalyzer アダプター（4章, PERM-03）

`SpeechAnalyzerRecognizer` は Apple SpeechAnalyzer / SpeechTranscriber による `SpeechRecognizer` の本番実装。
Phase 0（#48）で決まるのは標準 STT をどちらにするかで、このアダプターは標準でも代替でも使う。既定エンジンの選択・切替はこの層に置かない。
STT Worker には `SpeechAnalyzerModelLoader`（モデルは OS が管理するためロードはせず、認識器を返すだけ。負荷の区分は仮置きで `light`）で登録する。
使い方は Verification/SpeechAnalyzerProbe で確かめたものに合わせる。

- **ロケール：** 既定は `ja_JP`。`SpeechTranscriber.supportedLocale(equivalentTo:)` で解決してから使う
- **モデル：** 認識はモデルを取得しない。未対応・未取得なら `failed(.modelUnavailable)` で終える。
  取得状態の表示は `SpeechAnalyzerAssets.availability()`、取得は `SpeechAnalyzerAssets.install()`（ネットワークを使う）で、
  `install()` は利用者の明示的な操作を起点にだけ Apps から呼ぶ（PERM-03）。取得・保存・完全性の確認は OS が行うため、
  `ModelIntegrityVerifier` の対象外
- **音声形式：** `AudioChunk`（モノラル Float）を `AudioChunkConverter`（AVAudioConverter）で `bestAvailableAudioFormat` の形式に変換する。
  途中でサンプリング周波数が変わったら `failed(.unsupportedAudioFormat)`
- **イベント：** `TranscriptionEventMapper` が暫定（volatile）結果を `partial`、確定（final）結果を `confirmed` にする。
  確定した範囲より後の暫定部分が残っていれば、音声の時刻の属性（`audioTimeRange`）で切り出して `partial` で送り直す。
  音声の終わりで `finalizeAndFinishThroughEndOfInput()` を呼び、確定テキスト全体を `completed` で流す。
  確定結果がカバーしていない最後の暫定部分が残っていれば `completed` の末尾に含める（暫定結果が確定として出し直される保証がないため, #48）。
  `confirmed` は確定済みのチャンクのままで、`completed` は `confirmed` の連結より長くなることがある
- **キャンセル・失敗：** 受け手がストリームを破棄したら、モデルのロードや確定の待ちの最中でも `cancelAndFinishNow()` で止め、終端イベントは流さない。失敗は `failed` を流してから音声の読み取りを止める。失敗は Speech のエラーコードで
  `SpeechRecognitionError` に分類する（モデル・ロケール → `modelUnavailable`、形式 → `unsupportedAudioFormat`、資源不足 → `resourceLimited`、それ以外 → `engineFailed`）
- **空の録音：** 音声が1つもなければ確定を呼ばず、`completed("")` で終える
- **テスト：** SpeechAnalyzer の呼び出しは `TranscriptionSession` protocol（本番 `SpeechAnalyzerSession`）に切り出し、認識の進め方（`TranscriptionRun`。
  終端イベントの一意性・順序番号・失敗・キャンセル）はテストの Stub で確かめる。OS のモデルと実機の音声に依存する部分は単体テストせず、
  音声形式の変換・イベント変換・エラー分類を切り出してテストする

## クラウド STT（#60, 7章, AC-06, CTX-03）

MVP 外（1.1節）の先行実装。UtterAI の `OpenAISpeechRecognizer` が `SpeechRecognizer` に準拠し、録音音声を OpenAI の音声認識 API
（`POST /v1/audio/transcriptions`、API キー方式）へ送る。要件定義では送信先が決まっていないため、送信先は仮置き。
macOS の録音のセッションだけが、設定画面でクラウド STT を選んだときに組み立てる（既定で無効。下の「macOS の録音のセッションへの結線」）。
iOS と Edit Mode の指示・起動時の復旧では使わない。採用しない場合は `OpenAISpeechRecognizer.swift`・`CloudSpeechRecognitionPipeline.swift` と
UtterAI → UtterSpeech の依存を外す。

- **同意：** 音声送信の同意（`ConsentScope.transmission(.speechRecognition)`）を認識の開始時と送信の直前に確認し、
  なければ送信せずに `failed(.consentNotGranted)` で終える。整形の同意（`.textRefinement`）とは別で、そちらでは送らない（7章, AC-06）
- **送る内容：** 録音音声の WAV（PCM16 モノラル）と、モデル名・言語・応答形式の設定値だけ。ウィンドウタイトル・入力欄の本文・URL・辞書語は送らない（CTX-03）。
  送信先は `OpenAIProvider` と同じく https の OpenAI API のホストに限る（AI-02）
- **一括認識：** 録音の終わりまで音声を溜め、1回だけ送る。アップロードが終わるまで結果が出ないため `partial` / `confirmed` は流さず、
  `completed` か `failed` を1回だけ流す。Realtime Preview（2.2節）はローカル STT の機能として扱う
- **上限：** 音声の長さ（既定は最大録音時間 REC-05 の暫定 5 分）・WAV のバイト数（既定 25 MB、仮置き）を超えたら、それ以降の音声を読まずに
  `failed(.audioLimitExceeded)` で終える。音声は録音側に残っているため、ローカル STT での再認識などは呼び出し側が決める。
  アップロードと応答待ちを合わせた上限時間（既定 120 秒、暫定）を超えたら `failed(.timeout)`
- **費用：** トークン課金のため、整形と同じく `BudgetGuard` で送信前に見込み費用を予約し、応答の使用量で確定する（AI-04, AI-05）。
  見込みの使用量は音声1秒あたりの量（呼び出し側の設定）から計算する。認証・利用枠で拒否されたら取り消し、時間切れ・キャンセル・通信の失敗は見込みの費用で記録する
- **失敗の種類：** `SpeechRecognitionError` に、同意なし・上限超過・予算超過・時間切れ・認証失効・利用枠不足・通信の失敗・応答の解釈失敗を分けて持つ（AI-06 と同じ分け方）
- 受け手がストリームを破棄したら通信を止め、イベントを流さない

### macOS の録音のセッションへの結線（#188, 4章, AC-06, AI-04, AI-05）

| 部分 | 配置 | 内容 |
|---|---|---|
| 選択 | UtterPersistence `AppSettings.cloudSpeechRecognitionEnabled`、Apps/macOS `SpeechRecognitionSettingsTab`（設定画面の「音声認識」タブ） | 「ローカルのエンジン」か「クラウド音声認識（OpenAI）」を選んで「保存」する。既定は無効。版 2 に足し、ない保存値・読めない値は無効で読む |
| 同意 | UtterCore `ConsentScreenState.cloudSpeechRecognitionScopes`、Apps/macOS `ConsentSettingsScene` | 同意の画面に「クラウド音声認識」の行を、整形・選択テキストの行とは別に出し、個別に同意・撤回する。送信先は OpenAI（音声認識 API）と示す |
| API キー | Apps/macOS `KeychainAPIKeyStore.openAI()`、`APIKeySettingsView` | Claude API キーと同じ作り（data protection keychain、本デバイス限定、iCloud 同期なし）で account だけを分ける。整形とは共有しない（整形の ChatGPT は Sign in with ChatGPT で、API キーを使わない, #50） |
| 準備 | Apps/macOS `CloudSpeechRecognitionPipeline`（`SessionCloudSpeechRecognizing`） | 録音を始める前に、同意 → API キー → 予算の順に確かめ、そろえば `OpenAISpeechRecognizer` を作る |
| 調停 | Apps/macOS `SessionCoordinator` | クラウド STT の認識器を STT Worker を通さない `SpeechRecognizer` として使う |

- **使うかはセッションの開始時に決める。** 開始の操作のときに保存済みの選択を読み、そのセッションの間は変えない（設定の変更は次のセッションから。録音の設定の #183 と同じ形）。
  クラウド STT を選んでいればローカルのエンジンが未選択でも録音でき、選んでいなければ従来どおり STT Worker を使う
- **そろわなければ送らない。** 録音を始める前（マイクを開く前）に次を確かめ、欠けていれば録音せずに「認識に失敗しました」と理由
  （`HUDNotice.cloudSpeechRecognitionFailed`。同意なし・API キー未設定・読み出せない・予算を確かめられない）を HUD に出す。ローカルのエンジンへは切り替えない
  （利用者が選んだ認識の場所を黙って変えない）
  1. 音声の送信（`.transmission(.speechRecognition)`）に同意している。整形・選択テキストの同意では送らない
  2. OpenAI API キーが保存されていて読み出せる
  3. 整形と同じ月次予算・単価表・今月の累計から `BudgetGuard` を作れ、単価表にクラウド STT のモデル（`CloudSpeechRecognitionPipeline.model`、仮置き `gpt-4o-mini-transcribe`）の単価がある
- **同意は送る直前にも確かめる。** 予算を確かめた後と、`OpenAISpeechRecognizer` の認識の開始時・予算の予約の前後（送信の直前）に、同意の画面が保存した最新の値を読み直す。撤回されていれば送らない（予約済みなら取り消す）
- **機密入力も送る直前に確かめる（7章, AC-12）。** 録音の開始時の判定（「macOS のセッションの調停」）に加えて、`OpenAISpeechRecognizer` は送信の直前に
  `SessionCoordinator` が渡す判定（録音開始時の入力対象の今の入力先と、保存済みの除外アプリ）を呼ぶ。録音中にパスワード欄・除外アプリなどへ移っていれば、
  送らずに `SpeechRecognitionError.sensitiveInput` で終え、HUD に「入力先が機密入力のため、クラウドで音声認識できませんでした」を出す
- **推定費用は整形と同じ累計に記録する（AI-05）。** 見込みの使用量は音声1秒あたり入力 20・出力 10 トークン（仮置き。少なめに見積もらない）。
  累計を保存できなかった後は、整形と同じくアプリを起動し直すまでクラウド STT で送らない
- **送った後の失敗も理由を出す。** 予算超過・音声の上限超過・時間切れ・認証失効・利用枠不足・通信の失敗・応答の解釈失敗を、認識の失敗の理由として HUD に出す
- **異常終了の再処理（`STTWorkerRecognitionRecovery`）は使わない。** STT Worker を通さないため Worker の異常終了が起きない。
  クラウド STT の失敗（通信・同意・予算・認証など）は、同じ音声を送り直しても直らないことが多く、送り直すと費用がかかるため、認識し直さない。
  ローカルのエンジンでの再認識も行わない（利用者が選んだ認識の場所を黙って変えない）。失敗したセッションの一時音声は、ローカルのエンジンの失敗と同じく削除する
- **起動時の復旧と Edit Mode の指示はクラウドへ送らない。** どちらもクラウド STT を選んでいても STT Worker で認識する
  （起動時は利用者の操作なしに音声を送らない。Edit Mode の指示の音声送信は同意の対象に含めていない）
- Realtime Preview（2.2節）を選んでいても、クラウド STT は一括認識のため途中経過を出さない

## WhisperKit アダプター（先行実装）

Phase 0 #49（モデル選定）と #47（ライセンス確定）の判定待ちの先行実装。**既定で無効**で、`WhisperKitRecognizerConfiguration.isEnabled` を
明示的に `true` にしない限り、`recognize` は音声を読まずに `failed(.modelUnavailable)` で終える。アプリ・Worker にはまだリンクしない。

WhisperKit は UtterSpeech とは別の Package（UtterSpeechWhisperKit）に閉じ込め、UtterSpeech をビルド・リンクしても WhisperKit を取得しない。
推論以外の処理は WhisperKit に依存しない形で UtterSpeech に置き、モデルなしでテストする。

| 型 | Package | 役割 |
|---|---|---|
| `WhisperKitRecognizer<Transcriber>` | UtterSpeech | `SpeechRecognizer` の実装。音声を読み、`SegmentTranscriber` で推論してイベントを流す |
| `WhisperKitRecognizerConfiguration` | UtterSpeech | 有効化フラグ、言語、推論し直す間隔、未確定として残す区間の数（すべて仮置き） |
| `WhisperTranscriptAssembler` | UtterSpeech | 推論結果の区間から `partial` / `confirmed` / `completed` を作る |
| `WhisperKitModelCheck` | UtterSpeech | モデルのフォルダをロードしてよいかの判定（マニフェストの必須ファイルと `ModelIntegrityVerifier`） |
| `SegmentTranscriber` / `TranscribedSegment` / `StubSegmentTranscriber` | UtterSpeech | 推論エンジンの口・結果・テスト用の実装 |
| `WhisperKitTranscriber` / `WhisperKitModel` | UtterSpeechWhisperKit | WhisperKit でのロード・推論・解放 |

- **逐次の結果：** WhisperKit はまとまった音声を推論するため、新しい音声が `transcriptionInterval`（仮置き 1 秒）たまるたびに未確定の音声全体を推論し直す。
  結果の区間のうち末尾の `requiredSegmentsForConfirmation`（仮置き 2）個より前を `confirmed` にし、その終わりまでの音声を捨てる。残りは `partial`。
  音声が終わったら未確定の音声を推論し、全体を `completed` にする（WhisperKit の `AudioStreamTranscriber` と同じ考え方。マイク入力を持つ同クラスは使わない）
- **推論の遅れ：** 推論の間も別のタスクで音声を読み続け、次の推論でそれまでに届いた分をまとめて扱う。推論が録音より遅くても遅れが積み重ならず、
  推論中に録音が終わったら途中の推論をせずに最後の推論に進む（録音済みの音声は1回だけ推論する）
- **未確定の音声の上限：** 未確定の音声が 30 秒（仮置き）を超えたら、末尾の1区間を残して確定する。区間がない（無音）なら末尾 5 秒（仮置き）を残して捨てる。
  確定しない状態が続いて、推論し直す量が増え続けるのを防ぐ
- **長い音声：** WhisperKit の VAD による分割（`chunkingStrategy: .vad`）は使わない。v1.1.1 は分割した一部の推論の失敗を例外にせず結果から外すため、
  発話の一部を黙って失う。30 秒を超える音声は WhisperKit の通常の処理（30 秒ずつ順に進める）に任せる
- **音声の形式：** 16kHz モノラルだけを受け付け、違えば `failed(.unsupportedAudioFormat)`。変換は録音側で行う
- **モデル：** 同梱もダウンロードもしない。Apps が取得し、`WhisperKitModel`（ディレクトリ・マニフェスト）で渡す。モデルの種類は WhisperKit が次元から判定する。
  トークナイザーはモデルのディレクトリの直下に置き、同じマニフェストで照合する（[ライセンス・依存関係.md](ライセンス・依存関係.md) 3.4 の案 a）。
  モデル名の仮置きは `openai_whisper-tiny`（WhisperKitProbe の候補のうち最小の多言語モデル）
- **通信しないロード：** WhisperKit はフォルダ直下より先に `models/openai/whisper-*/` の下のトークナイザーを探し、読めなければ Hugging Face から取得するため、
  マニフェストに `models/` で始まるパスを置かせない（マニフェストにないファイルは照合で失敗するため、フォルダには直下のトークナイザーしか置けない）。
  照合（`.ready`）→ トークナイザーを WhisperKit と同じ経路で読めることの確認 → `modelFolder` / `tokenizerFolder` に照合済みのフォルダを指定し
  `download: false` で初期化、の順に行い、どれかに失敗したらロードしない。実際に通信しないことは #49 の実機確認で通信を監視して確かめる
- **失敗の分類：** モデル・トークナイザー・初期化の失敗とロード中の失敗は `.modelUnavailable`、推論中の失敗は `.engineFailed`。WhisperKit のエラー文言は使わない（パスを含みうる）
- **保持と解放：** ロードしたモデルは `WhisperKitTranscriber.unload()` まで保持する。保持・解放の判断は呼び出し側が `ModelRetentionPolicy` で行う。
  macOS では STT Worker（要件定義 3章のプロセス隔離）に置く想定
- **ログ：** WhisperKit のログは無効にする。認識テキストを持つ型の `description` は文字数だけを出す
- メモリ・熱の目標値と、モデル・設定値の決定は #49 の実測で行う。不成立なら UtterSpeechWhisperKit と上の表の UtterSpeech の型を消す

## 命名規約

- 型は UpperCamelCase、ファイル名は主たる型名と一致させる（`SpeechRecognizer.swift`）
- protocol は役割名（`AIProvider`）、実装は `<方式><役割>`（`ClaudeProvider`, `LocalBasicRefiner`）、Stub は `Stub<役割>`
- テストファイルは `<対象型>Tests.swift`
- 機能IDに対応するテストは `@Test("REC-05: 最大録音時間で自動停止する")` のように表示名へ機能IDを含める
