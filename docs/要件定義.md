# 音声入力アプリ「utter」 要件定義書

## 1. 目的と対象
Typeless・Aqua Voice・Nani.nowを参考に、音声入力の低遅延、自然な文章整形、開発用語認識、省電力を両立するmacOSネイティブOSSを開発し、共通基盤を活用したiOS個人利用版も開発する。独自実装とし、競合製品の非公開技術を前提としない。

- macOS版はApple Silicon、macOS 26以降をMVPの暫定対象とする。macOS 15対応は将来検討（SpeechAnalyzerが使えないためWhisperKit専用構成になる）。
- Swift 6、SwiftUI/AppKit。メニューバー常駐、初期録音操作はToggle。
- ローカルSTT優先、クラウドSTTは明示的オプトイン。ローカルLLMはMVP非採用。
- Claude API、Sign in with ChatGPT、ローカル簡易整形（Local Basic）を選択可能にする。ChatGPTはOpenAI APIキー方式も別の選択肢として並べ、両者を黙って切り替えない。Sign in with ChatGPTは無料かつ利用者の端末上でのみ動く間に限って提供し、macOSから始める（iOSは当面OpenAI APIキー方式のみ。Phase 0 #50の判定）。
- 各利用者が認証情報を設定する。開発者の共通APIキーは配布しない。
- 利用状況のテレメトリ・解析送信は行わない。
- macOS版はApp Sandboxを原則採用せず、他アプリへのAccessibility操作を利用する。Mac App Store配布は対象外。iOS版はiOS Sandboxの制約に従う。
- iOS版はApp Storeに公開せず、本人所有のiPhoneへのXcode実機インストールを想定する。iOSの最低対応バージョンはPhase 0でSTT API・対象端末に応じて確定する。

### 1.1 MVPの範囲

- macOS MVP＝Phase 1〜3（初期安定版公開まで）。Edit、クラウドSTT、履歴、Realtime DirectはMVP外。
- iOS MVP＝Phase i1〜i3（個人端末での実用動作まで）。専用キーボードからの入力を主目的とし、録音はiOS本体アプリで行う。自動的な元アプリ復帰は保証せず、成立しない場合の手動復帰導線を必須とする。
- Phase 0の結果により、11章の判定基準に従ってMVP範囲を縮小できる。

## 2. 機能と操作
### 2.1 録音

- REC-01：グローバルショートカット1回目で録音開始、2回目で停止。Escでキャンセル。Escの捕捉は録音〜整形中のセッション中のみ有効とし、待機中は他アプリのEsc操作に干渉しない。
- REC-02：Push-to-talk切替を提供。ショートカット競合を検出する。修飾キー単独（Fn等）の割当はイベントタップと追加権限が必要なため、対応可否をPhase 0で判断する。
- REC-03：HUDで録音・認識・整形・挿入・エラー状態を表示。フォーカスを奪わない（非アクティブ化パネル）。
- REC-04：マイク権限拒否、切断、入力デバイス変更、スリープ、連打、セッションキャンセルを安全に処理する。
- REC-05：1セッションの最大録音時間を設ける（暫定5分、設定で変更可）。上限到達時は自動停止して通常どおり処理し、HUDで通知する。音声バッファ上限到達時も同様に扱い、無言で音声を破棄しない。
- REC-06：セッションは「待機→録音→認識→整形→挿入→待機」の状態機械で管理し、同時に1セッションのみとする。処理中の開始操作は無視またはキャンセル確認とし、挙動を固定する。

### 2.2 入力モード

- Instant（MVP標準）：録音中に可能な範囲でSTTを進め、停止後に最終認識・整形して一括挿入。
- Realtime Preview（MVP）：HUDで確定済みと暫定テキストを区別して表示。入力欄へは停止後一括挿入。
- Realtime Direct（実験機能）：確定済みチャンクを入力欄に逐次挿入。安全な範囲追跡とUndoが成立するアプリに限定。
- Edit（v1.1）：選択テキストを音声指示で変更。変更前後の差分プレビュー、明示的確定、キャンセル、復元を提供。選択テキストのクラウド送信は、音声入力の整形とは別の同意とする。

### 2.3 文章整形と文脈

- TXT-01：Raw、Natural、Structuredの3モード。
- TXT-02：フィラー、言い直し、句読点、段落を適切に処理。数字、URL、コード、固有名詞を保護し、意味を創作しない。
- TXT-03：ユーザー辞書と用語置換ルールを提供。
- TXT-04：発話内容は常に「整形対象のデータ」として扱い、指示として実行しない。発話が質問や命令文であっても回答・実行せず、その文を整形して返す（Editモードの音声指示は例外）。
- CTX-01：前面アプリのbundle IDからスタイルを自動選択。Discord/Slackは簡潔、メールは丁寧、IDEは技術語保持、Terminalはコマンド保護、文書アプリは段落整形。
- CTX-02：ユーザーによるアプリ別上書き。Webサイト単位の識別は明示的許可制。
- CTX-03：クラウドAIへ送る文脈情報はスタイル区分と辞書語に限定する。ウィンドウタイトル、入力欄の既存本文、URLは既定で送信しない。

### 2.4 テキスト挿入

- INS-01：録音開始時に入力対象を記録し、挿入直前に再検証。対象が消失または別要素に変わっていた場合は自動挿入せず、コピー可能なプレビューへ退避する。
- INS-02：Accessibility APIによる直接挿入を優先し、失敗時は許可済みPasteboard/CGEvent、最後にコピー可能なプレビューへ切替。
- INS-03：二重挿入禁止。成功不明時に無条件再試行しない。TerminalではEnterを自動送信しない。
- INS-04：クリップボード復元は他アプリによる更新と競合しない場合に限定（changeCountで判定）。
- INS-05：Accessibility挿入は成功応答だけを信用せず、可能なアプリでは挿入後の値を読み戻して確認する。確認できないアプリは「成功不明」として扱い、アプリ別の既定経路を互換性表で管理する。
- INS-06：Pasteboard経由の挿入時は、クリップボード管理アプリに履歴として残らないよう一時データの印（Transient/Concealed種別）を付与する。
- INS-07：挿入はアプリ標準のUndo 1回で取り消せることを目標とし、経路ごとのUndo挙動を互換性表に記録する。

### 2.5 権限とオンボーディング

- PERM-01：必要権限（マイク、Accessibility、必要な場合のみ音声認識・入力監視）を用途説明つきで段階的に要求する。未使用の経路の権限は要求しない。
- PERM-02：権限が後から取り消された場合を検出し、該当機能のみ無効化して再設定を案内する。
- PERM-03：初回利用前にSTTモデルの取得状態を表示する。モデル取得はユーザー操作を起点とし、取得元とサイズを明示、取得後に完全性を検証する。

## 4. アーキテクチャ

- macOS Main App：ショートカット、AVAudioEngine、HUD、設定、認証、AI連携、入力先管理。
- iOS Main App：AVAudioSession/AVAudioEngineによる録音、STT、AI連携、権限・認証・設定・共有結果の保存。
- iOS Keyboard Extension：UIInputViewController、UITextDocumentProxyによる通常入力・音声結果の挿入。マイク・大規模STTモデル・クラウド認証処理は持たない。
- Shared Packages：音声認識インターフェース、AI Provider、テキスト整形・検証、辞書、セッションモデル、エラー型を共通化。プラットフォーム固有APIはアダプターで分離。
- STT Worker：モデルのロード、音声チャンク受信、推論、部分・確定イベント、モデル解放。
- SpeechRecognizer：`partial` / `confirmed` / `completed` / `failed` の共通イベント。イベントにはセッションIDと順序番号を付与。
- Refinement Router：選択プロバイダーへの1回送信。応答を検証して挿入。
- Persistence：設定、辞書、任意の履歴、API使用量を管理。iOSはApp Groupの共有領域に挿入用の短命な結果のみ配置し、トークンや録音データは原則共有しない。
- 音声チャンクはバッチ化してWorkerへ送る。共有メモリはプロファイリングで必要な場合のみ導入。
- キャンセル済みセッションの遅延レスポンスは無視。モデルロード・推論は最大1件とし、キュー長を制限する。

### 4.1 整形応答の検証とフォールバック

- 検証項目：空応答でないこと、STT結果に対する文字数比が許容範囲内であること、保護対象（数字、URL、コード、辞書語）が保持されていること、拒否文・前置き・回答文などの整形以外の出力でないこと。閾値はPhase 2で評価セットから決める。
- 検証失敗、タイムアウト、通信エラー時は、ローカル処理（Local BasicまたはRaw）の結果を挿入し、HUDで退避したことを通知する。発話内容を失わないことを優先する。
- ローカルへの退避は追加送信を伴わないため既定で有効。別のクラウドプロバイダーへの切替は明示的許可がある場合のみ（AI-04）。
- クラウド整形の応答待ちには上限時間を設け、超過時は上記の退避を行う。

## 5. AIプロバイダーと費用制御

- AI-01：Claude API、Sign in with ChatGPT、OpenAI APIキー方式はそれぞれ独立した接続・切断・失敗処理を持つ。Sign in with ChatGPTとOpenAI APIキー方式は同じ送信先（OpenAI）として同意を取るが、選択肢は分け、一方の失敗で他方へ自動で切り替えない。Sign in with ChatGPTは当面macOSのみで提供する。
- AI-02：Sign in with ChatGPTは音声STTではなく、対応範囲の文章整形に使用する。利用条件、OAuth登録、Responses APIの制約をリリース前に再確認する。他製品のクライアントIDの流用や非公開エンドポイントの利用は行わない。
- AI-03：Local Basicはオフラインで使用可能なルールベース整形とし、クラウドAIと同等の自然さは保証しない。
- AI-04：クラウド間の自動フォールバックは初期無効。各送信先の同意とClaudeの予算上限を遵守する。
- AI-05：Claudeのトークン使用量から推定費用を記録。APIクレジット残高や実請求額と混同しない。単価表はコードに固定せず、更新日つきの設定として持ち、利用者が修正できるようにする。
- AI-06：タイムアウト、認証失効、利用枠不足、予算超過、ネットワーク切断を別々のエラーとして扱う。
- AI-07：整形用モデルは低遅延の小型モデルを既定とし、利用者が変更できる。モデル名は設定値として持ち、廃止・改名に追従できるようにする。

## 6. 速度・メモリ・電力の非機能要件

**以下は保証値ではなくストレッチ目標。** 10秒程度の発話、準備済みモデル（ロード済み）、内蔵マイク、通常ネットワークの条件で計測する。Phase 0の実測後に数値を再設定する。

| 指標 | 目標 |
|---|---|
| 録音開始遅延 | p95 ≤ 200ms |
| Realtime初回文字表示 | p95 ≤ 1.5秒 |
| ローカル高速入力：停止→挿入 | p50 ≤ 300ms、p95 ≤ 700ms |
| AI整形あり：停止→挿入 | p50 ≤ 800ms、p95 ≤ 1.5秒 |
| コールドスタート（モデル未ロード）：停止→挿入 | 計測のみ。目標はPhase 0後に設定 |
| 待機時アプリメモリ | ≤ 50MB目標 |
| 録音のみのアプリメモリ | ≤ 100MB目標 |
| Apple STT実行時 | 500MB以下を目標、OS管理領域は別計測 |
| WhisperKit実行時 | 1GB以下を目標、モデル・GPU領域を別計測 |
| 待機時CPU | 平均0.1%以下目標 |
| 8時間待機時の追加バッテリー消費（主指標） | 1%未満を目標、同条件の対照測定 |
| 待機時追加消費電力（参考値） | 主指標からの導出値。約70Wh機で平均0.09W以下に相当 |
| 処理後の負荷復帰 | 5秒以内を目標 |

- 「AI整形あり」は、STT確定・LLM初回トークン・LLM完了・挿入の区間別にSignpostで計測する。p50 800msはSTT確定とLLM往復の合計であり、達成難度が高い。未達の場合は目標の見直し、または整形結果のストリーミング表示で体感を補う。
- Bluetoothマイクは接続プロファイル切替で開始が遅れるため、録音開始遅延の目標対象外とし別計測する。発話冒頭の欠落有無も併せて確認する。
- 省電力モード：推論後に原則モデル解放。
- バランスモード（標準）：短時間保持（30〜60秒を検証候補）、メモリ圧迫・バッテリー状態で解放。解放後の初回入力は上表のコールドスタート扱いとなる。
- 高速モード：ユーザー許可とメモリ上限の範囲でモデル保持。
- 待機中はマイク停止、STT停止、不要な描画・タイマー・ポーリング・ネットワーク送信を停止。
- 高度なAI整形はネットワーク遅延があるため、Raw/Local Basicと同じ速度を保証しない。

## 7. 安定性とプライバシー

- M5 MacBook Pro（24GB）でLM Studio使用時にMac全体のフリーズ・再起動が発生したため、重いローカルLLMを常駐させない。STTのCPU/GPU/ANE負荷は段階的に検証する。
- XPC Workerの異常終了を検知し、録音を再処理できるようにする。音声は必要時のみ保護された一時領域に保存し、正常終了後に削除する。
- 異常終了で残った一時音声は、次回起動時に復旧可否を確認し、保持期限（暫定24時間）を過ぎたものは自動削除する。
- 音声は原則ローカル処理。クラウドSTTへの音声送信、AI整形への文字列送信は別々に同意を取得する。
- パスワード欄、機密アプリ、ユーザー指定除外アプリでは録音・送信・履歴を抑止する。判定はセキュア入力欄の属性とシステムのセキュア入力状態を併用し、判定不能な場合は安全側（抑止）とする。
- 入力履歴は初期無効。認証情報はKeychainに保存。診断ログへ本文・音声・秘密情報を含めない。

## 8. 受け入れ基準

- AC-01：Toggle/Push-to-talkで録音、停止、キャンセルが可能。
- AC-02：モデル取得済みの状態で、オフラインで録音→ローカルSTT→挿入が可能。
- AC-03：Realtime Previewに暫定・確定文字列が表示される。
- AC-04：日本語・日英混在・技術用語の評価セットを実行できる。
- AC-05：Claude API、Sign in with ChatGPT、OpenAI APIキー方式（11章の代替。Sign in with ChatGPTと併記）、Local Basicを個別に選択できる。iOSではSign in with ChatGPTを当面対象外とする。
- AC-06：クラウドへの無断送信、無断の有料切替がない。通信を監視した自動テストで、同意なしの状態で外部送信が0件であることを確認する。
- AC-07：辞書、Raw/Natural/Structured、アプリ別スタイルが動作する。
- AC-08：TerminalでEnterを送信せず、二重挿入がない。
- AC-09：挿入先消失時・変更時に安全にコピー可能なプレビューへ退避する。
- AC-10：STT Workerの異常終了時にメインアプリが継続し、音声復旧を試行できる。
- AC-11：メモリ圧迫時に高負荷モデルのロードを抑止する。
- AC-12：Keychain、クラウド同意、機密アプリ除外、履歴無効が動作する。
- AC-13：OSSから開発者の秘密情報なしにビルドできる。
- AC-14（v1.1）：Edit Modeで選択文章の音声編集・差分確認・確定・Undoができる。
- AC-15（実験機能）：Realtime Directは未対応アプリで自動的に無効となる。
- AC-16：クラウド整形の失敗・タイムアウト・検証失敗時に、ローカル整形結果が挿入され、発話が失われない。
- AC-17：質問文・命令文を含む発話の評価セットで、回答や実行ではなく整形結果が返る（TXT-04）。
- AC-18：最大録音時間到達時に自動停止し、それまでの音声が処理される。
- AC-19：6章・9章の計測を再現可能な手順で実行でき、リリースごとに結果を記録する。目標未達の項目は既知の制限として公開する。
- AC-20：主要対象アプリの挿入互換性表（経路、成功確認可否、Undo挙動）が整備されている。

## 9. 精度評価

- 日本語・日英混在・開発用語・数字・自己訂正・騒音の6区分で、各区分50発話以上（合計300以上、暫定）のデータセットを用意する。発話単位の成功率は件数が少ないと1件の重みが大きいため、区分ごとの件数を結果に併記する。
- 一般日本語CER ≤ 8%、フィラー除去成功率 ≥ 95%、自己訂正成功率 ≥ 90%、辞書語正答率 ≥ 90%、重大な意味改変率 ≤ 1%を初期目標とする。
- CERの正規化規則（句読点、全角半角、数字表記、英字の大文字小文字）を事前に定める。日英混在は用語単位の正答率を併用する。
- 「重大な意味改変」の判定基準（否定の反転、数値・固有名詞の変更、内容の追加・欠落など）を定義し、判定手順を固定する。
- STT単体の誤りとAI整形後の意味改変を分けて測定する。
- Typeless、Aqua Voice、Nani.nowとの速度比較は、同一発話・同一Mac・同一ネットワーク条件で行う。競合製品の測定値は未取得。

## 11. 技術検証で確定する事項と判定基準

| 検証事項 | 不成立時の方針 |
|---|---|
| Apple SpeechAnalyzerの日本語モデル・部分認識・対応デバイス・必要OS | 日本語精度または部分認識が不足する場合、WhisperKitを標準STTとする |
| WhisperKitの最適モデル、初回ロード時間、メモリピーク、熱・電力、安定性 | 安定性に問題がある場合、より小型のモデルに下げる。それでも不成立ならApple STT単独とする |
| Sign in with ChatGPTの最新OSS登録条件、対応モデル、OAuth・Responses API制約 | OSSとして正式に登録・利用できない場合、MVPから外し、OpenAI APIキー方式を代替とする |
| アプリ別Accessibility挿入の成功率、Undoとクリップボード復元の安全性 | 成功確認できないアプリはPasteboard経路またはプレビュー退避を既定とする |
| 修飾キー単独ショートカットに必要な権限 | 追加権限の負担が大きい場合、通常のキー組み合わせのみ対応とする |
| 速度ストレッチ目標と待機時50MB・バッテリー1%目標の現実性 | 実測に基づき6章の数値を再設定する |
| Apache-2.0を含むライセンス、依存関係、モデル重みの配布方法、配布署名方式 | モデルは同梱せず初回取得とする等、配布形態で調整する |

**判断原則：** 性能・省電力目標と機能の両立が難しい場合、Mac全体の安定性とデータ保護を最優先し、品質劣化やクラウド送信はユーザーが選択できるようにする。

## 12. iOS個人利用版 — 製品要件（追加）

### 12.1 スコープと操作体験

- iOS-01：iPhone向けにiOS本体アプリとCustom Keyboard Extensionを提供する。App Store公開、TestFlight配布、他者向け配布はMVP対象外。
- iOS-02：他アプリの通常の編集可能なテキスト欄でutterキーボードを選択し、音声入力結果をカーソル位置へ挿入できることを目指す。ただしiOSがサードパーティキーボードを許可する入力欄に限る。
- iOS-03：キーボード内の「音声入力」操作から本体アプリでの録音に移る導線を提供する。拡張から本体アプリへの直接起動・復帰は公開APIでの成立をPhase i0で確認し、非成立の場合はユーザー操作によるアプリ切替・ディープリンク等の許可された代替導線を用いる。非公開API・URLスキームの悪用はしない。
- iOS-04：本体アプリで録音→ローカルSTT→必要に応じたAI整形を実行。結果をApp Groupへ保存し、ユーザーが元の入力欄に戻ってutterキーボードを表示した際に挿入候補を提示する。
- iOS-05：初期仕様は**挿入前プレビュー＋明示的な挿入操作**とする。ユーザーが許可した場合のみ、後続フェーズで復帰時自動挿入を検討する。
- iOS-06：録音前の入力先アプリ・入力欄の同一性は、iOSの公開APIで完全には保証できない。誤挿入防止のため、復帰後の挿入先をユーザーが確認する。macOSのINS-01と同等の対象検証を保証しない。
- iOS-07：録音失敗・アプリ復帰失敗・キーボード非表示・結果期限切れの場合も、本体アプリで結果を確認・コピーできる救済導線を提供する。コピーは主経路ではない。
- iOS-08：通常の文字入力、削除、改行、地球儀キー（キーボード切替）を提供する。iOS標準キーボードと同等の日本語変換・予測変換はMVPでは保証しない。必要なら標準キーボードへの切替を案内する。
- iOS-09：キーボードが使用できないセキュア入力欄、電話番号入力欄、サードパーティキーボード禁止アプリではiOS標準キーボードへ切り替わる。これを回避しない。
- iOS-10：iOS版は端末内の個人利用を前提とするが、クラウドAIへの送信同意、辞書・履歴設定、セキュリティ要件はmacOS版と同水準にする。

### 12.2 キーボード拡張の制約

- Keyboard Extensionからマイク録音は実行しない。`RequestsOpenAccess`を有効にしても録音権限を得られるわけではない。
- キーボード拡張は別プロセスで、メモリ上限が厳しい。STTモデルや長時間処理を常駐させず、結果の表示と`textDocumentProxy.insertText`による挿入に集中する。
- キーボード拡張はホストアプリの入力欄全体や選択状態を自由に取得できない。Edit ModeはiOS MVPから除外し、限定的な文脈取得による編集を将来検討とする。
- App Groupへの共有書き込みとネットワークアクセスが必要な場合、キーボードに「フルアクセスを許可」が必要になる。初期設計ではキーボード自体からネットワーク送信を行わず、共有結果の読み取り要件とフルアクセスの必要性をPhase i0で検証する。フルアクセスが必要なら理由を明示し、無効時の機能制限を案内する。
- フルアクセスが有効でも、キーボードで入力された通常の文字列を開発者サーバーに送信しない。キーボードの入力イベント解析・テレメトリは行わない。
- キーボードから本体アプリを起動できること、他アプリへの自動復帰、復帰時に同じ入力欄が残ることは**未確定の技術リスク**として扱う。

### 12.3 セッション受け渡し・保存

- iOS-IPC-01：本体アプリが処理結果をApp Groupコンテナの専用ファイルまたは小規模SQLiteに保存する。保存形式は`sessionID`、`createdAt`、`expiresAt`、`status`、`text`、`consumedAt`を含む。
- iOS-IPC-02：共有結果の有効期限は初期10分（検証で調整）。期限切れ・消費済み・不正なセッションIDの結果は挿入しない。
- iOS-IPC-03：挿入ボタンの連打・キーボード再生成・他アプリへの切替で二重挿入を起こさない。挿入結果が確認不能な場合、再挿入を自動実行せず確認を求める。
- iOS-IPC-04：ファイルのアトミック書き込みまたはトランザクションを用い、共有データの破損を防ぐ。App Group内にAPIキー・OAuthトークン・生音声を保存しない。
- iOS-IPC-05：挿入後または期限切れ後に共有テキストを削除する。機密性の高い結果は端末保護・ファイル保護クラスを利用し、ロック状態でのアクセス失敗を安全に扱う。
- iOS-IPC-06：端末の再起動、キーボード拡張の強制終了、本体アプリの中断時も、結果の状態が矛盾しないよう復旧する。

| 層 | 技術 | 採用方針 |
|---|---|---|
| 言語 | Swift 6 / Swift Concurrency | macOSと共通 |
| 本体UI | SwiftUI | iPhone向けに別画面を実装 |

### 12.5 iOS非機能要件

- iOS-PERF-01：キーボード表示と通常入力は録音モデルのロードに依存させない。起動・表示遅延、ピークメモリ、プロセス強制終了率を計測する。
- iOS-PERF-02：待機時に本体アプリでSTT・マイク・GPU推論を常駐させない。iOSのバックグラウンド実行制限を迂回しない。
- iOS-PERF-03：録音中の画面ロック、電話着信、オーディオ割り込み、低電力モード、熱状態変化に対応する。必要なBackground Modesは実際のUXで必要な場合のみ検討し、常時録音のためには使わない。
- iOS-PERF-04：macOSの第6章の数値目標をiOSへ流用しない。実機・OS・STTモデル確定後にiOS専用のp50/p95、ピークメモリ、10分連続使用時の電力・熱目標を設定する。
- iOS-PERF-05：キーボード拡張のメモリ制約により強制終了されても、元アプリの入力欄や結果を破損させない。

### 12.6 iOS署名・個人端末での運用

- Apple AccountをXcodeへ登録し、iOS本体アプリとKeyboard Extensionを同じ開発チームで署名する。
- 無料Personal Teamでの実機インストールは可能だが、プロビジョニングの有効期間は通常7日間で、定期的な再ビルド・再インストールが必要。App Groupsなど必要Entitlementが無料署名で利用できるかはPhase i0で検証し、制約があればApple Developer Program加入を選択肢とする。
- 有料Developer Programでも署名・プロビジョニングの更新は必要。永続的に無更新で使えるとは扱わない。
- iOS本体アプリ、キーボード拡張、App Group IDの識別子をREADMEで設定可能にし、個人ビルドで再現できるようにする。

### 12.7 iOS受け入れ基準

- iAC-01：本人所有iPhoneへXcodeからインストールでき、キーボード一覧にutterが表示される。
- iAC-02：対応アプリの通常テキスト欄でutterキーボードを選択できる。
- iAC-03：本体アプリで録音→STT→整形を完了し、共有結果をキーボードに表示できる。
- iAC-04：明示的な挿入操作で結果が1回だけ挿入される。連打・拡張再起動時も二重挿入しない。

- iAC-07：フルアクセス無効・権限拒否・署名不備・モデル未取得・オフライン時の状態を適切に表示する。

- iAC-09：iPhone実機でキーボード表示遅延、ピークメモリ、バッテリー、発熱、録音から挿入までの遅延を計測する。

## 13. macOS / iOS共通化と差分管理（追加）

| モジュール | 共通化 | macOS固有 | iOS固有 |
|---|---|---|---|
| Domain / Session / Error | 共通 | グローバルホットキー状態 | キーボード復帰状態 |
| SpeechRecognizer protocol | 共通 | XPC Worker、macOS音声API | AVAudioSession、iOS音声API |
| AIProvider / Prompt / Validation | 共通 | macOSの認証・設定画面 | iOSの認証・設定画面 |
| Dictionary / Styles / Persistence models | 共通 | bundle IDでのアプリ判定 | アプリ識別は原則不可、手動スタイル優先 |
| Recording UI | 別実装 | メニューバーHUD | 本体アプリの録音画面 |
| Text Insertion | 共通の結果型のみ | AX / CGEvent / Pasteboard | UITextDocumentProxy |
| Worker / Extension | 非共通 | XPC STT Worker | Keyboard Extension + App Group |
| Build / Signing | 一部共通 | Developer ID、公証 | iOS Development、Extension Entitlement |

- `Packages/UtterCore`、`UtterSpeech`、`UtterAI`、`UtterText`、`UtterPersistence`をSwift Package Managerで共有する。
- `Apps/macOS`、`Apps/iOS`、`Extensions/iOSKeyboard`、`Workers/macOSSTT`を別ターゲットとする。各ターゲットのEntitlement、Info.plist、ビルド設定は分離する。
- macOSのグローバルショートカット、他アプリのbundle ID検知、AXによる選択範囲編集をiOSへ移植しない。iOSはユーザー操作によるキーボード入力を前提とする。
- 既存macOSの機能ID・受け入れ基準は維持し、iOS固有仕様を`iOS-*` / `iAC-*`で追加管理する。

## 14. iOS Phase i0 技術ゲート（追加）

| 検証事項 | 成立条件 | 不成立時 |
|---|---|---|
| キーボードから本体アプリへの導線 | 公開API・ユーザー操作で実現 | 手動アプリ切替を案内。ワンタップ起動はMVP対象外 |
| 本体アプリから元入力欄への復帰 | 対応アプリで実用的な操作手順がある | 手動復帰＋結果保持を標準とする |
| App Groupと個人署名 | 本体・拡張間で安全に結果共有 | 有料開発者署名の要否を確認。不可ならiOS MVPを保留 |
| キーボードのフルアクセス | 共有結果読取・挿入が成立 | 明示的なフルアクセス案内、権限がない場合は安全に無効化 |
| iOS STT | 日本語と日英混在で十分な精度・負荷 | モデルを小型化／対応API切替／iOS版の対象端末を限定 |
| メモリ・発熱 | キーボードと本体アプリが継続利用可能 | STT処理を縮小し、安定性を優先 |

**意思決定：** iOSは「他アプリでも使えるカスタムキーボード方式」を採用する。ただし、録音は本体アプリに限定し、他アプリへの完全なシームレス復帰を製品保証には含めない。公開APIで成立する操作だけを実装し、Phase i0の検証結果を反映してUXを確定する。
