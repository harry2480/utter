# utter ビルド・配布規約

Xcode / Swift Package Manager / GitHub Actions / GitHub Releases によるビルド・署名・配布の規約。
要件の根拠は [要件定義.md](要件定義.md) の3章・12.6節。

---

## 開発環境

| 項目 | 前提 |
|---|---|
| Mac | Apple Silicon |
| macOS | 26 以降（SpeechAnalyzer を使うため） |
| Xcode | 26 以降（Swift 6） |
| 依存管理 | Swift Package Manager のみ。CocoaPods / Carthage は使わない |
| 補助ツール | shellcheck・xcodegen（`brew install shellcheck xcodegen`）、gh |

---

## 依存関係

- 依存は各 Package の `Package.swift` に記述し、`Package.resolved` をコミットしてバージョンを固定する
- 依存を追加する前にライセンスを確認する（Apache-2.0 と両立するもの）。モデル重みのライセンスも別途確認する。確認結果は [ライセンス・依存関係.md](ライセンス・依存関係.md) に出典と確認日つきで記録する
- 依存の更新は Dependabot（`swift` エコシステム）が PR を作成する。自動マージはせず、人がレビューしてマージする

## 署名と識別子

Accessibility 等の権限はコード署名に紐づくため、署名が変わると再許可が必要になる。

- Team ID・Bundle ID・App Group ID はリポジトリに固定せず、`Config/Local.xcconfig`（gitignore 済み）で上書きする。既定値は `Config/Base.xcconfig`（署名なしビルド用のダミー）、雛形は `Config/Local.xcconfig.example`
- 自前ビルド利用者向けに、固定の開発用署名でビルドする手順を README に記載する。Ad Hoc 署名は再ビルドのたびに権限が外れるため使わない（方式案は [ライセンス・依存関係.md](ライセンス・依存関係.md) 4章）
- macOS 公式バイナリは Developer ID 署名＋公証。App Sandbox は原則使わない（他アプリへの AX 操作のため）
- iOS は iOS Development 署名で本人端末にインストールする。無料 Personal Team は約7日で失効するため再インストールが必要。App Group が無料署名で使えるかは Phase i0 で検証する
- 証明書・プロビジョニングプロファイル・API キーはコミットしない。CI で署名が必要になったら GitHub Actions secrets を使い、PR からのワークフローに渡さない

## ビルド手順

Xcode プロジェクトは xcodegen で `project.yml` から生成する。生成物（`*.xcodeproj`）はコミットしない（.gitignore。`project.yml` が正）。
コマンドはリポジトリのルートで実行する。

| ターゲット | 定義 | スキーム | 成果物 |
|---|---|---|---|
| macOS アプリ（メニューバー常駐、Dock に出さない `LSUIElement`） | `Apps/macOS/project.yml` | `UtterMac` | `utter.app`（Bundle ID は `<UTTER_BUNDLE_ID_PREFIX>.mac`） |

```sh
# 1. プロジェクトを生成（project.yml を変えたら毎回）
xcodegen generate --spec Apps/macOS/project.yml

# 2a. 署名なしでビルド（scripts/verify.sh・CI と同じ条件）
xcodebuild -project Apps/macOS/Utter.xcodeproj -scheme UtterMac -configuration Debug \
  -destination 'generic/platform=macOS' CODE_SIGN_IDENTITY=- CODE_SIGNING_ALLOWED=NO build

# 2b. 開発用署名で Xcode から実行する
cp Config/Local.xcconfig.example Config/Local.xcconfig   # DEVELOPMENT_TEAM と UTTER_BUNDLE_ID_PREFIX を自分の値にする
open Apps/macOS/Utter.xcodeproj                           # スキーム UtterMac で Run
```

- `xcode-select -p` が Command Line Tools を指していると xcodebuild を実行できない。`sudo xcode-select -s /Applications/Xcode.app` で切り替えるか、`DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` を付けて実行する
- 署名を固定するため、`Local.xcconfig` の Team ID・Bundle ID は一度決めたら変えない（変えると Accessibility 等の権限の再許可が必要になる）
- Packages はローカルパッケージとして参照する（現在は UtterCore のみ。使う Package は機能を結線する PR で追加する）
- 権限の用途説明（`NSMicrophoneUsageDescription` など）と Entitlement は、その権限を使う機能を実装する PR で追加する。未使用の権限は要求しない（PERM-01）

## CI

`.github/workflows/ci.yml`

| job | ランナー | 内容 |
|---|---|---|
| 検証（`verify`） | `macos-26` | `scripts/verify.sh`（swift format lint、Package の build/test、アプリの署名なし xcodebuild、shellcheck）。shellcheck と xcodegen は brew で導入する |
| CI ステータス確認（`ci-status`） | `ubuntu-latest` | `verify` の結果を集約。branch protection の required check にする |
| カバレッジ計測（`coverage.yml`） | `macos-26` | `scripts/coverage.sh` の lcov を Codecov にアップロード。required check にはしない |

- アプリターゲットは `scripts/verify.sh` で署名なし（`CODE_SIGN_IDENTITY=- CODE_SIGNING_ALLOWED=NO`）の `xcodebuild build` を行う。新しいターゲットを作ったら追加し、テスト・ターゲットを作ったら `xcodebuild test` も追加する
- 実機・権限ダイアログ・マイクが必要なテストは CI で実行しない。手順書と記録で担保する
- Codecov のアップロードトークンは Actions secrets の `CODECOV_TOKEN` に設定する。アップロード失敗では CI を落とさない
- ランナーの macOS / Xcode バージョンを変えたときは、ローカルとの差異を README に記録する

## 配布

| 対象 | 方法 | フェーズ |
|---|---|---|
| macOS 公式バイナリ | GitHub Releases（Developer ID 署名・公証済み） | Phase 3 |
| macOS 自前ビルド | README の手順で Xcode からビルド | Phase 3 |
| macOS 自動更新 | Sparkle 2（更新確認は低頻度・無効化可能） | 後続 |
| iOS | Xcode から本人端末へ実機インストール | Phase i3 |

- STT モデルはバイナリに同梱せず、初回にユーザー操作で取得する（取得元・サイズを明示し、取得後に完全性を検証, PERM-03）
- リリースごとに性能・精度の計測結果を記録し、目標未達の項目は既知の制限として公開する（AC-19）
