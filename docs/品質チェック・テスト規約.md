# utter 品質チェック・テスト規約

Swift Testing / XCTest / XCUITest と swift format によるコード品質チェック規約。
要件の根拠は [要件定義.md](要件定義.md) の6章・8章・9章。

## Quality Check 一覧

| チェック | ツール | 対象 | コマンド |
|---|---|---|---|
| フォーマット / lint | swift format（Swift ツールチェーン同梱） | 全 Swift ソース | `scripts/verify.sh`（整形は `scripts/format.sh`） |
| ログ出力の検査 | `scripts/check-logging.sh`（grep） | 製品コードの Swift ソース（テスト・utter-eval を除く） | `scripts/verify.sh` |
| ビルド・型チェック | `swift build`（Swift 6 strict concurrency） | `Packages/*` | `scripts/verify.sh` |
| Unit テスト | Swift Testing | `Packages/*/Tests/`、`Apps/iOS/UtteriOSKit/Tests/`（iOS アプリのうち OS の API を使わない部分。macOS で実行する） | `scripts/verify.sh` |
| シェルスクリプト lint | shellcheck | `scripts/*.sh`、`Verification/*/scripts/*.sh` | `scripts/verify.sh` |
| カバレッジ | `swift test --enable-code-coverage` + llvm-cov → Codecov | `Packages/*/Sources/` | `scripts/coverage.sh` |
| アプリのビルド | xcodegen + xcodebuild（署名なし） | `Apps/macOS`、`Apps/iOS`（iOS Simulator 向け） | `scripts/verify.sh` |
| iOS 向けビルド | xcodebuild（署名なし、`generic/platform=iOS Simulator`） | iOS を宣言する `Packages/*` | `scripts/verify.sh` |
| 配布用の署名設定 | `scripts/check-release-config.sh`（`xcodebuild -showBuildSettings`） | `Apps/macOS` の Release 構成 | `scripts/verify.sh` |
| ワークフロー lint | actionlint | `.github/workflows/*.yml` | `scripts/verify.sh` |
| アプリの UI テスト | XCUITest | Apps / Extensions / Workers | テスト・ターゲット作成時に `scripts/verify.sh` へ追加 |

### verify の実行フロー

`scripts/verify.sh` は以下の順で実行する。CI（`.github/workflows/ci.yml`）も同じスクリプトを macOS ランナーで実行する。

1. `swift format lint --strict`
2. `scripts/check-logging.sh`: 製品コードで `print` / `debugPrint` / `dump` / `NSLog` / `fputs` などや `FileHandle.standardOutput` / `standardError` を使っていないこと、`fatalError` / `precondition` / `assert` のメッセージで補間していないこと（ログの秘匿、iAC-10）。これらは OSLog と違い補間を非公開にしないため、本文やトークンがそのまま残る。意図して出力する行は `check-logging: allow` と理由を書いて除外する。ログは OSLog の `Logger` を使い、`privacy: .public` を付ける値に本文・秘密情報が入らないことはレビューで確認する
3. `Packages/` 配下の各パッケージと `Apps/*/*/Package.swift`（`Apps/iOS/UtteriOSKit`）で `swift build` → `swift test`
4. アプリの署名なしビルド: `xcodegen generate` → `xcodebuild build`（Debug、`CODE_SIGN_IDENTITY=- CODE_SIGNING_ALLOWED=NO`）。macOS アプリはビルド後に Info.plist の `LSUIElement` を確かめる（起動はしない）。xcodegen（`brew install xcodegen`）と Xcode が必要で、見つからなければ失敗する
5. iOS の最低バージョンの一致: iOS を宣言する各 `Package.swift`（`Apps/iOS/UtteriOSKit` を含む）の `.iOS(.vNN)` と `Apps/iOS/project.yml` の `deploymentTarget` が同じであること
6. iOS Simulator 向けの署名なしビルド: iOS を宣言する各 Package（`xcodebuild -scheme <Package>`）と `Apps/iOS`（xcodegen → xcodebuild）。シミュレータは起動しない。iOS Simulator SDK が無ければローカルではスキップ、CI では失敗
7. `scripts/check-release-config.sh`: Release 構成で Hardened Runtime が有効、Entitlement のファイルがあり plist として正しい、App Sandbox が無効、マイクの用途説明があるなら `com.apple.security.device.audio-input` もある、を確かめる（署名はしない）
8. `shellcheck scripts/*.sh Verification/*/scripts/*.sh`
9. `actionlint`（見つからなければスキップ。CI は brew で導入する）

コード変更後は必ず実行し、全パスすることを確認する。

### カバレッジ

`scripts/coverage.sh` は各パッケージのテストをカバレッジ付きで実行し、`coverage/<Package>.lcov` を出力する。CI（`.github/workflows/coverage.yml`）がこれを Codecov にアップロードする。

- 計測対象は `Packages/*/Sources/`。テストコード・依存パッケージ・アプリターゲット（実機検証が中心）は除外する（`codecov.yml`）
- 当面はカバレッジ率で CI を落とさない（`informational: true`）。Phase 1 でパッケージが揃ったら閾値を決める
- 必須テスト観点（下記）はカバレッジ率とは別に、テストの有無で確認する

## テストの層

| 層 | 対象 | 方針 |
|---|---|---|
| Unit | Packages | 外部依存なし。外部 API・STT は Stub、時刻・UUID は注入する |
| 統合 | Apps のアダプター（AX 挿入、Pasteboard、Keychain、XPC） | 実機の macOS で実行。CI で動かせないものは手順書と結果記録で代替 |
| UI | HUD、オンボーディング、iOS キーボード | XCUITest。権限ダイアログが絡む部分は手動手順で補う |
| 性能・電力 | 6章・iOS-PERF-* の指標 | Instruments / Signpost で計測し、結果を `docs/計測/` に記録（AC-19） |
| 精度 | 9章の評価セット | 評価用音声はリポジトリに含めず（gitignore 済み）、正解テキストと正規化規則のみ管理する。規則と手順は [精度評価.md](精度評価.md)、計算は `utter-eval` |

## 必須テスト観点

以下は要件上の事故に直結するため、該当コードを変更したら必ずテストを追加・更新する。

- **状態機械**（REC-06）: 処理中の開始操作、連打、キャンセル、最大録音時間（REC-05）
- **送信の同意**（AC-06）: 同意なしの状態で `URLSession` が呼ばれないこと（Stub の呼び出し回数で検証）
- **応答検証とローカル退避**（4.1節, AC-16）: 空応答、文字数比の逸脱、保護対象の欠落、回答文の混入、タイムアウト
- **TXT-04**: 質問文・命令文の発話が回答されず整形結果として返ること
- **二重挿入防止**（INS-03, iOS-IPC-03）: 成功不明時に再試行しないこと、共有結果の消費済み・期限切れを挿入しないこと
- **ログの秘匿**: エラー型・ログ文字列に本文・トークンが含まれないこと。本文・秘密情報を持つ型は `CustomStringConvertible` と `CustomReflectable` の両方で文字数などだけを出し、`String(describing:)`・`String(reflecting:)`・`Mirror`・`dump` で本文が出ないことをテストする

## テストの書き方

- Swift Testing（`import Testing`、`@Test`、`#expect`）を標準とする。XCTest は UI テストと既存資産のみ
- 表示名に機能IDを含める: `@Test("INS-03: 成功不明時に再試行しない")`
- 1テスト1振る舞い。パラメータ化（`arguments:`）で入力パターンを網羅する
- 実ネットワーク・実マイク・実モデルに依存するテストを Unit に入れない
- テストデータに実在の個人情報や実際の発話録音を使わない
